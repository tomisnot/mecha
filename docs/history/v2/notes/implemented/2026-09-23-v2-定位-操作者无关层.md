# v2 定位 = 这台软件的操作者无关层

> **状态**：implemented
> **作者**：mecha v2（委托方定调 · 新对话落笔）
> **日期**：2026-09-23

## Problem

v1 把自己定位成"一台自给自足的 AI 框架"（自带 journal/jobs/spill/gate/archive），以 dsh 为主语。可观察后果：在 dsh 部署里长出**两套写权门**和**第二份真值**（总纲 §9 的两条洞）。审计（总纲 §2.1）进一步量化：v1 全部 4497 行里 708 行（15.7%）是在 dsh 已有成熟件处重复造轮子。

委托方的最终愿景（总纲 §1.2，不可删改）定死了三件架构事实：dsh 与 AI **不是这套系统的架构，而是这台软件的一个新操作者**；软件有自己的门、状态、历史，人类从 GUI 进、硅基生命从工具进，**过同一道门**；**软件不依附 dsh**——dsh 消失时软件、数据、域状态史、侧边栏全部照常，只少一个操作者。

如果不把"v2 到底是什么"写成一篇可判定的决策，新对话会重新锚定 v1 的旧形状，同一批洞会复发。

## Decision

**mecha v2 是「这台软件的操作者无关层」，只有四件正职：写入门（Gate）、域状态史（History）、能力面（Surface）、人类监控面（Monitor）。**

- AI 适配器**必须**被建模成"操作者适配器之一"，与 GUI 适配器**平级**，不是主子关系。dsh 是这台软件的一个新操作者，不是它的宿主架构。
- **History 必须能在 dsh 消失后独立工作**，它是软件自己的资产（人操作时也写），**禁止**把它降级成 dsh session log 的投影或副本。它与 dsh 的操作者行为史是两份资产，关系只能是**互引**（每次 `set` 带当次 call-id/seq）。
- `actor` **必须**由通道决定，**禁止**由请求内容决定——AI 无法传 `actor='human'` 伪造人类归因或借此拿到写权。
- 写权门**只能有一道**，且**只能落在执行器上**（不在包装层）。dsh 的 sandbox/approval 管 OS 资源，我们的 Gate 管域状态——是两层，不是两道竞争的门。

## Consequences

**换来**：单一写权门、软件独立于 dsh、域状态史是唯一真值、不再有第二份真值。

**付出**：四件正职必须我们自己拥有，不能整层委托给 dsh；不能复用 dsh session log 当我们的历史；稳定脊椎的代码量比"薄薄一层 dsh bundle"要多。

**放弃**：把 mecha 做成 dsh 能力族/组合包的选项（见下）；把 mecha 做成自给自足 AI 框架的 v1 路线。

## Alternatives considered

**否决：mecha 作为 dsh 能力族（capability seam / bundle 挂进 dsh）。** 这会让 dsh 重新变回主语，正是 v1 的根本错误：History 沦为 dsh session log 的投影，随 dsh 生死（违反 §1.2 事实三"软件不依附 dsh"）；Gate 沦为 dsh `ctx.tools` 的一个 guard，两套写权门复发；`actor` 归因被 dsh 持有而非由我们的通道决定。能力族形态与"操作者无关"在定义上冲突——一旦挂进 dsh 的 ctx，操作者就成了架构。

**否决：mecha 作为自给自足的 AI 框架（v1 原样）。** 审计已量化其代价：708 行纯重复 dsh 已有件，且以 dsh 为主语的部署必然产生第二份真值。

**否决：mecha 作为纯 MCP server。** 多一层进程边界，Resources/Prompts 不桥接；更关键的是 MCP server 形态只覆盖"AI 怎么进来"，承载不了 Gate/History/Monitor 这条操作者无关的脊椎——它会把 v2 重新压扁成"一个适配器"。
