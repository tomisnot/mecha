# 装配统一：真实部署路径改经 assemble() 单点（D-33）

> **状态**：implemented
> **作者**：mecha v2（回应委托方补充 D-33）
> **日期**：2026-09-23

## Problem

`mecha/assembly.py` 是具名装配点（L6 的取数处），但真实部署路径**绕开它手搭**：
`V2Bridge.for_gui/for_shared` 与 `hub.build_stack` 各自 `resolve_data_dir +
JsonlLogSink + History + Authority + Gate + Surface` 逐件拼装。后果实测可见：
端到端判据用 ToyEngine 走 assemble、真路径走手搭——**两份装配代码**，assemble
改了真路径不会红（装配漂移判据失明），这正是 L6 要防的"机制建好但装配没接"的
装配版。委托方判据：让真实路径经 assemble()（或让 assemble 能表达真实路径的
需求），并让判据在真引擎上跑装配。

## Decision

**assemble() 补齐真实路径需要的两点表达力，三条装配路径（GUI/共享/Hub）全部
改经它：**

1. `mode` 参数（默认 `DEFAULT_MODE`=LOCKED 不变；GUI 类宿主显式传 HUMAN）——
   真实路径此前手搭 `Authority(mode)`，assemble 只会造 LOCKED。
2. `Software.layout` 字段——真实路径要 `data_dir/artifacts` 子路径，此前靠
   自己 `resolve_data_dir` 拿 layout；现在从装配结果取，宿主不再自己解析。
3. `own_thread` **不进 assemble**：引擎构造（ElEngine(own_thread=…)）是宿主
   在 assemble **之前**做的事，assemble 收现成 engine 实例——线程模型是
   Provider 的事（churn 不越 Provider 层），装配点不表达。

V2Bridge 新增 `_assembled()` 类方法承接公共段，`for_gui/for_shared` 只保留
引擎构造与 cache 形态差异；`hub.build_stack` 同改。`make_jsonl_history` 随之
删除（零调用方，不留死契约）。

**判据侧（"在真引擎上跑装配"）**：`phase5_bridge_selfcheck`（for_gui/for_shared
= ElEngine 真引擎）与 `phase5_hub_selfcheck`（build_stack 起真 Hub 子进程）本来
就在真引擎上跑，现在它们验的就是 assemble 单点路径。另把
`capability_map_selfcheck` 的 `provider.log.local` 消费证据符号改为 `assemble`
——若谁退回手搭（import 消失），守卫当场红（D-33 的机械防回归）。

## Consequences

换来：一份装配代码，ToyEngine 判据与真引擎判据验同一条路径；assemble 漂移会
在 phase5 两套判据上红；"退回手搭"被消费守卫盯着。付出：assemble 签名长了一个
`mode` 参数（默认值保持出厂收紧语义不变）；`Software` 多一个 `layout` 字段。

## Alternatives considered

**否决：assemble 加 own_thread 参数。** 线程模型是引擎 Provider 的构造细节
（ElEngine 自己的旋钮），塞进装配点 = 把 EL 的 SQLite 认线程约束焊进库（v1 的
"实现混领域"反模式，总纲 §2.1）。
**否决：只让 hub 走 assemble、bridge 保留手搭。** 留一份手搭就留一份漂移面，
D-33 的病根没除。
**否决：不加判据、只改代码。** 委托方验收明说"判据在真引擎上跑装配"；且没有
机械防回归的话，下一次"顺手手搭"只能靠人审——正是本仓反复付过账的假绿变体。
