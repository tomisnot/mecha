# 验收整改：契约收紧 + 消费面接线（响应第二/三轮审查与撤回）

> **状态**：implemented
> **作者**：mecha v2
> **日期**：2026-09-23
> **补记说明**：本 note 是**被审查第三轮撤回 §6 抓到才补的**——整改代码已在
> `a8763af` 落地，但"改 History 单写者不变量、改 Authority 公开签名"这类非平凡
> 改动当时只写进了 commit message，没写 note，违反硬纪律 9（没写的决策不许静默
> 拍定）。撤回 §6 的批评成立，本篇兑现它。

## Problem

外部验收（第二轮 + 第三轮 + 勘误 + 撤回）实测出一批**已声明契约与实现不符**
的缺陷，和一批**机制已建、消费方未接**的真空。逐条经本仓独立复现确认属实后
修复。其中两项改变了框架不变量/公开签名，属 ADR 制度 §3.1 的"非平凡"：

- **History 的单写者**：此前只是 `history.py` Limitations 里的一句"进程内假定
  单写者"（约定），审查 2.2 实测两宿主共用目录会产出重复 seq `[1,1,2,2]`，
  直接破坏"seq 单调"这条核心不变量。
- **Authority 的公开签名**：`gate()`/`switch_mode()` 形参都叫 `actor`，实际都收
  `side`（审查 2.4 的"同名不同义"）；改签名是破坏性变更。

## Decision

**逐项决策理由（复述代码看 `a8763af`，这里只记"为什么这么定"）：**

1. **单写者从"约定"升为"OS 文件锁强制"**（新增 `mecha/write_lease.py`，
   `JsonlLogSink` 构造即抢锁）：同一数据目录第二个写宿主 **fail-closed 拒绝**，
   而非"降级为只读客户"。理由：只读客户要处理"读时对方正在追加"的可见性竞态，
   且当前无此真实需求（并存部署各用各目录即可）——降级是 n=1 不建的机制。
   配套 `Software/History/sink.close()` 链（宿主关停/租约交接）。
2. **Authority 形参 `actor`→`side` 改名，而非改行为**：`gate`/`switch_mode` 本就
   都收 side（写权看 side 是硬纪律 4 的既有语义），只是形参名误导。改名从命名上
   根除陷阱、**不改变任何运行时行为**（位置参数调用兼容）。细标签→side 的映射放
   适配器层（`bridge.switch_mode`），库不认宿主词。
3. **disposer 对称 / did_you_mean / call_id 透传**：都是"已声明契约的实现补全"，
   无独立取舍——`register` 的 disposer 一并撤销角色登记（消幽灵条目）；
   `UnknownKey.typo` 用 difflib 自动猜（候选集由调用方给，库不持领域键表）；
   `CURRENT_CALL_ID` contextvar 让 hub 经 mcp `Context.request_id` 注入、
   `gate.set` 读取（AI 侧互引，总纲 §5.2②）。
4. **异步作业 + CodeAct 接进消费面**：`submit_job`/`read_job`/`cancel_job` 三工具
   （单一 `JobRegistry` 由宿主注入，消 D-21）；`read_job` **有意折叠** v1 的
   `job_status`+`list_jobs`——命名律禁 `list_`/`get_` 前缀（枚举是投影不是工具），
   用约束反推更少的工具面。`run_actions`（CodeAct 编排）的审计**落临时 History、
   不污染账**（§5.2② 两份资产：`codeact.N` 进域史会让重启折叠快照吃进
   审计噪声、存档 load 被 validate 拒）。
5. **消费方守卫 + 制度第 6 条**：`capability_map_selfcheck` 加"每条 PROVIDER 的
   consumer 必为表内真实能力名 + 无 consumer 必进 DEFERRED_PROVIDERS 显式登记"
   （撤回 §6/勘误 §3 的 3 条假声明据此转真）；`ADR制度` 加第 6 条"推迟必须绑可
   判定触发事件 + 触发/关门必须回登"（审查 §3 的沉默推迟制度化）。

**破坏性变更清单**（下游须知）：`Authority.switch_mode/gate` 形参名 `actor`→`side`
（位置参数兼容，keyword 调用需改）；`JsonlLogSink` 默认 `exclusive=True`，同目录
第二宿主会抛 `writer_lease_held`（这是**刻意的**，误伤只读投影时传 `exclusive=False`）。

## Consequences

换来：三条核心不变量（单写者、side 定写权、史两份资产）从"文档约定"变"代码强制
+ 判据盯"；对外能力面补齐异步长任务与编排（对等性从 7 工具升到 11）；map 的消费方
列不再说谎。付出：多一个 OS 锁的平台适配面（msvcrt/fcntl 两路）；`__del__` 在解释器
关闭期的坑（撤回 §6 实测：惰性 import 抛 `ImportError` 污染 stderr）——已改模块级
导入 + `__del__` 吞关闭期异常。

## Alternatives considered

**否决：每项修复各写一篇 ADR。** 它们是同一轮验收驱动、同因（"契约说一套实现做
一套"）的一批，逐项拆会让每篇的 `Alternatives` 高度重复（都是"否决：不修/推迟"）；
合并一篇、Decision 分点，既满足硬纪律 9 又不制造 note 噪声。
**否决：只改代码、靠 commit message 交代。** 正是撤回 §6 抓到的违反——commit
message 不进 note 树、后人查不到，非平凡改动必须有 note。
**否决：租约做成"第二个宿主自动降级只读"。** 审查提过这个选项，但只读客户要处理
读时可见性竞态、当前无真实只读消费者（§5.4 Require evidence）；拒绝 + 显式
`exclusive=False` 逃生口更简单。
