# 驾驶舱呈现回归：v1 两页形状原样整回，数据源换活桥投影

> **状态**：implemented
> **作者**：mecha v2（用户裁决 2026-09-24："旧版驾驶舱效果我特别满意……飞行记录仪
> 和配置两页，怎么折叠，怎么分层，把什么放上面，全给我整回来"）
> **日期**：2026-09-24

## Problem

两模式收拢时新建的 dsh 监控面板（MonitorTabBody）是简化版：单列表 + mode 徽标。
用户对比 v1 驾驶舱（EL 仓 git `e366de8~1:dsh/src/client/CockpitTabBody.tsx`）后
明确要旧呈现：**两页签（飞行记录仪 | 配置态）+ 逐行折叠（概括=seq/actor/kind/reason，
展开=before→after 全量）+ 配置态族→前缀二级分层树 + 原 CSS**。v1 数据源
（:8766 cockpit-server 读磁盘 journal）已随 v1 退役，但呈现规范应保留——
"黑匣子投影"的形状与"读磁盘还是读活桥"是两回事。

## Decision

1. **呈现逐字照搬 v1**：前端组件保留 v1 的 `.re0-tab-native` 全套 CSS、两页签、
   `openSet` 展开态记忆、`fmtVal`（$pointer/$truncated 指针友好显示）、折叠行 DOM
   结构；只换数据获取（fetch v2 端点）。
2. **监控端点加两个只读投影路由**（EL `src/v2_bind.py`，v1 `src/cockpit/backend.py`
   的输出形状逐字段对齐）：
   - `GET /history?since_seq=N` → `{events:[{seq,kind,actor,target,before,after,
     reason,call_id}], mode}`——**before 由全史 fold 重建**（v2 Event 只记 after；
     同键上一条的值=before，首写=None）。
   - `GET /config` → `{has_schema, groups:{族:[{prefix,rows:[{name,short,value,
     unit,set}]}]}, orphans, n_keys}`——schema 行（`bridge.params(include_internal)`）
     join 现值（`effective()`）+ 每键最后写入归因（史重建）；无引擎的纯内存桥如实
     `has_schema=False`、快照键全归 orphans（不凭空造树）。
3. **徽标位换语义**：v1 是 alerts 级别（run 降级/失败/空演化规则依赖 v1 的 run
   事件流与 provenance 字段，v2 History 只记 set 事件）；同位置同 CSS 类改显
   **写权模式**（human 绿 / ai 紫 / locked 黄）。alerts 规则不硬凑——等 v2 有
   run 事件面（真实调用方）再评估（n=0 不建）。
4. **端点纪律不变**：只读、loopback、无鉴权、POST 一律 404（控制权归看门人）。

## Consequences

换来：用户满意的驾驶舱 UX 在 v2 复活，且数据是**活桥真值**（v1 读磁盘 journal 有
轮询延迟与崩溃尾行问题，v2 读进程内 History 即时一致）。
付出：监控端点面从 2 路由扩到 4（/history 与 /activity 有意重叠——/activity 是
v1 兼容口形状、/history 是驾驶舱形状带 before；判据分别守）；before 重建是 O(全史)
fold，史大时每次轮询重算（当前史规模 <10³，秒级内，不预建缓存——漂了再说）。
放弃：v1 的 alerts 徽标语义（规则依赖已退役的 run 事件 provenance；硬凑=假告警，
比没有更糟）。

## Alternatives considered

**否决：只换皮不换数据形状（前端自己算 before）。** 前端拿不到全史增量
（/activity 只回增量），before 链必须在服务端从史重建——数据形状的责任在投影层，
塞给 UI 会造成每个消费方各算各的（两套账）。
**否决：恢复独立 cockpit-server 进程读磁盘 journal（v1 原架构）。** 黑匣子
"项目死后仍可读"的独立性在 v1 语境成立（驾驶舱是独立 Web）；v2 的监控面板寄生
dsh 会话，dsh 活着权威才有人看——为已消失的需求多养一个进程与端口，不值。
**否决：alerts 照搬 v1 规则。** v2 History 没有 run 事件（run 走 Surface 不落
域史），degradation/empty_run 规则无数据可评；返回恒空 alerts 是假绿装饰。
