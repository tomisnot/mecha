# 失败留痕的判据：**副作用有没有可能已经发生**

> **状态**：implemented
> **作者**：mecha v2（⑥ 甲类 A1；维护者批准整批改进后先做）
> **日期**：2026-09-26

## Problem

命令面此前**只给"handler 正常返回"留痕**（`_audit` 只在拿到 `CommandResult` 之后被调用）：
`_check_args` 与 `_call_handler` 合在同一个 `try` 里，任何 `MechaError` 都直接
`return _failure(e)` ⇒ **拒绝与 handler 抛错一律无痕**。

⚠ 两个后果：

1. **不对称**：`return {"ok": False}` ⇒ **有审计**；`raise MechaError` ⇒ **无审计**。
   **"抛"比"返回失败"更响，留的痕却更少。**
2. ⚠ **最该留痕的失败反而无痕**：handler **已经跑过** ⇒ 它**可能已经动过宿主状态**
   （域状态外置的项目尤其如此：改的是外置库/外部 API）⇒ 事后**查不到这次失败发生过**。
   这与"有副作用的命令哪怕回执不合契约也必须留痕"的既有理由**同源**，只是当时
   只覆盖了"返回失败"那一半。

## Decision

**判据改成【副作用有没有可能已经发生】，而不是【这次失败没失败】**：

1. **拒绝点不留痕**：scope / authority / 审批 / **参数**都在 handler **之前**
   ⇒ 副作用**不可能发生** ⇒ 不留痕（且每次参数手滑都记一条会把真痕迹淹掉）。
   ⇒ 实现上把 `_check_args` 与 `_call_handler` **拆成两个 try**。
2. **handler 已进入的失败必须留痕**：抛 `MechaError` **或任何异常**，都**先**写一条
   `ok=False` 的 `command.<name>` 审计，**然后按原样处理失败**：
   * `MechaError` ⇒ 照旧 `return _failure(e)`（回执不变）；
   * **其它异常 ⇒ 原样抛出**（**不把 bug 伪装成域失败**）。
3. `error_kind` ＝ `MechaError.kind`（域失败）或 `type(exc).__name__`（编程错误）。
4. `gate` 没注入 ⇒ **写不了 ⇒ 如实无痕**（既有的 `missing_gate` 语义不变）。
5. 审计本身写不进去时**不掩盖原失败**（原失败更响亮）。

## Consequences

**换来**：跑过的 handler 一定有痕——包括"抛异常"这条此前最黑的路径；失败与成功都能在
`/history` 里看到（带 `actor` / `call_id` / `error_kind`）。

**付出 / 放弃**：

- ⚠ **放弃"`command.*` 是成功路径的账"这个直觉**：审计事件现在**既有成功也有失败**
  ⇒ 读的人要**按 `ok` 字段区分**（形状没变，语义变宽了）。**这是行为变更。**
- ⚠ **放弃"审计事件数 == 命令调用数"这类推断**：失败的 handler 调用也会各多一条。
- **放弃给拒绝点留痕**（有意）：拒绝时代价为零、价值为负（淹没真痕迹）。
- **放弃把普通异常归一化**：留痕 ≠ 归一化；bug 仍穿透，由传输边界兜。
- **放弃"审计里带异常栈"**：只记 `error_kind` + `error_message`（审计值不许塞大对象，
  这是既有纪律）；栈仍在宿主日志里。

### 迁移须知

- **审计事件会变多**：每个"handler 已进入但失败"的调用 **+1 条**（成功路径不变）。
- 消费者若按 `command.*` 事件计数/对账，请改成**按 `ok` 分**。
- 三个项目的影响面：EL（**命令面 0 处**）不受影响；ML / GP 的命令面会看到更多
  `command.*` 事件（都是失败的那部分）。

## Alternatives considered

**否决：不拆 try，一律留痕（参数错也记）。**
参数错是**手滑**，频率高、信息少；每次都记会把真痕迹淹掉。而且参数错时 handler
**根本没跑** ⇒ 判据（副作用有没有可能发生）明确说"不记"。

**否决：把普通异常也归一化成域失败后返回。**
那会**把 bug 伪装成领域失败**，让人去查领域逻辑而不是代码坏了；也与既有的
**分层归一化**（域失败就地归一、编程错误由传输边界 `LocalToolHost.call` / MCP 投影兜）
冲突。⇒ 只加痕，不改路径。

**否决：给失败审计另起一个键前缀（如 `command_fail.<name>`）。**
无必要：形状里已有 `ok`，且**同一个键前缀才能让"这条命令的历史"一次读全**。

## Required verification

- `python checks/run_all.py` **全绿**（22 项）。
- `checks/phase6_command_surface_selfcheck.py` 的 `check_failure_leaves_trace`（四条）：
  ① handler 抛 `MechaError` ⇒ **有痕**（`command.*` / `ok=False` / `error_kind=kind`）
  且回执照旧；② handler 抛**普通异常** ⇒ **也有痕**（`error_kind=异常类型名`）**且异常原样抛出**；
  ③ **对偶**：参数错 ⇒ **不留痕**；④ **对偶**：正常成功 ⇒ 审计现状不变（1 条 `ok=True`）。
- 既有那批复审仍在（不许回归）：scope / authority / 审批被拒 ⇒ **无痕**（它们都在
  handler 之前）；宿主 validator 拒审计键那条已按"只记史"改写但仍 fail loud。
- 红证（隔离调用，**自证扰动落上**）：把两处 `_audit_entered_failure(...)` 删掉 ⇒
  **两条"有痕"断言都红**（`抛 MechaError 无痕…` / `普通异常无痕…`），而**两条对偶仍绿**
  ⇒ 新语义与"拒绝不留痕"是**分开验证**的。
