# 工具命名放宽（允许单段）与三条接入口径

> **状态**：implemented
> **作者**：mecha v2（第三个项目 n=3 报告的发现 2 / 发现 4 与 §9-2 / §9-3 的落地）
> **日期**：2026-09-26

## Problem

1. **工具命名律过死，且与命令面自相矛盾**：`tools._NAME_RE` 要求**至少两段**
   ⇒ `undo` / `reset` / `sync` 这类**天然单词动词结构上不可能合规**，只能造词
   （`undo_change`）。而**命令面早就允许单段**（`commands._NAME_RE` 本该是同一个正则，
   其 ADR 明写"单段名 `reset` 合法"）⇒ **同一条律在两个面上互相打架**。
   ⚠ **已被撞两次**：某项目被迫改 7 个名（`get_paper→read_paper` … `undo→undo_change`），
   后来又撞一次（`list_briefings→query_briefings`）。
2. **`adapter.gui` 被读成"必须是一个独立 GUI"**：人类面是**本地网页**的项目里，
   这个角色被当成空角色（或误以为必须再做一个 GUI 才"合规"）。
3. **两条接入须知藏得太深**：`providers.jobs` 的 local 实现**每次 `submit` 新起一个
   daemon 线程、不排队、不设并发上限**——这条只写在实现注释里，接入方容易以为框架
   给了队列；`estimate_sec=0` 又让 AI 没法判断"要不要挂后台"。

## Decision

1. **工具名允许单段**：`(_[a-z0-9]+)+` → `(_[a-z0-9]+)*`（**与命令面逐字相同**）。
   ⚠ **只有段数放宽**：`get_` / `list_` 禁用与项目前缀禁用**一字未动**。
2. **官方改名惯例进错误信息**（L4：那条消息就是宿主/模型看到的教学面）：
   `get_*` ⇒ `read_*`、`list_*` ⇒ `query_*`。⇒ 新项目不必再自己论证一遍。
3. **`adapter.gui` = 面向人的适配面**，**不要求独立 GUI**（人面是本地网页的项目，
   那个网页**就是**这个角色）；**没有面向人的适配面时，不要声明空角色**。
4. **并发度归项目**（写进《接入指南》的接入须知）；**`estimate_sec` 建议非零**
   （尤其 `side_effect=True`），**不强制、不校验**。

## Consequences

**换来**：不再为凑段数造词（`undo` 直接合法）；两个面的命名律一致；接入口径
（并发、估算、人面角色）写在接入方真正会读的地方。

**付出 / 放弃**：

- **放弃了"用段数逼出动词_宾语"这条约束**（在**单段**这一格上）。任务导向命名的
  把关现在**完全落在"不许 `get_`/`list_` 开头"**这一条上——它是有效的那条，但它
  只拦两类前缀（不拦别的"名词式"命名）。
- **放弃了给 `adapter.gui` 改名**（`adapter.human` 更名副其实）：改名会动能力图与
  既有消费者，**换不来对齐**⇒ 保留这个历史名字，用文档写清它的所指。
- **放弃"框架兜并发"这个错觉**：不加队列、不加并发上限（并发度是你引擎的约束，
  不该焊进库）。⇒ 接入方要排队/限流，自己加。
- **放弃对 `estimate_sec` 的强制**：不加校验（本地的快命令会被误伤）。

### 迁移须知

1. **工具命名**：以前被拒的**单段名现在合法**（放宽，**非破坏性**——既有名字全部仍合法）；
   `get_*` / `list_*` / 项目前缀**照旧拒**（按上面的官方惯例改名）。
2. **`adapter.gui`**：如果你把它当"必须独立 GUI"而声明了一个**空角色**，请**撤掉那个空角色**；
   如果你有人类面（本地网页/面板），**它就是 `adapter.gui`**。
3. **并发与估算**：框架**不排队、不限并发**；`estimate_sec=0` 等于没告诉 AI 任何事。

## Alternatives considered

**否决：继续要求"至少两段"。** 它把 `undo` 这类天然动词判成违规、逼出 `undo_change`
这种造词；而且与命令面矛盾——**修一个面比改口径更贵**。（"摩擦持续复现本身就是
'这条律是否过严'的最强论据"。）

**否决：把 `adapter.gui` 改名 `adapter.human`。** 名字更准，但**会动能力图与既有
消费者**；而"面向人的适配面"这层意思**用文档就能说清**，不必付改名的代价。

**否决：给 `providers.jobs` 加队列 / 并发上限。** 并发度是**引擎自己的线程模型**
（某项目的 SQLite 认线程就是它的约束）；框架替它定并发＝把宿主约束焊进库，
而且今天**没有**一个项目要框架的队列 ⇒ 为不存在的需求建机制（R1）。

**否决：强制或校验 `estimate_sec` 非零。** 本地的快命令（毫秒级）填 0 是**诚实的**；
强制会让它们被迫编一个数——那是把"建议"变成"形式主义"。

## Required verification

- `python checks/run_all.py` **全绿**（22 项）。
- `checks/phase4_adapter_selfcheck.py` 的 `check_naming` 三条新断言：
  ① **单段天然动词合法**（`undo` / `reset` / `sync`，与命令面同一口径）；
  ② 放宽段数**没有放宽别的**（`do__thing` / `_undo` / `undo_` / `Do_thing` / 含空格仍拒）；
  ③ 既有的 `get_` / `list_` / 项目前缀拒注册**不回归**。
- 红证（隔离调用，**自证扰动落上**）：把正则改回 `(_[a-z0-9]+)+` ⇒ **只有**"单段合法"
  那条红（红出 `undo` / `reset` / `sync` 仍被拒），**其余条全绿** ⇒ 证明放宽是**窄的**
  （只动了段数，没有顺带放松别的）。
