# 降级读数 · 三态槽位 · 时间戳（零迁移）

> **状态**：implemented
> **作者**：mecha v2
> **日期**：2026-09-26

## Problem

1. **原始层没到端点**：硬纪律是"**两层信任、原始赢**"，而 `monitor_summary_payload`
   只投影概括层 ⇒ 端点上看不见原始层。
2. **概括层故障把整个读面带走**：`summarizer` 抛错 ⇒ `Monitor.read()` 整体抛
   （`phase10` 当年诚实登记为"未支持降级读数"）。
3. **账本缺三样**（框架自己的 L2："可追溯、可撤销、可回放"）：无 `之前是什么`（读侧有、事件无）、
   无 `时间`、无 `能不能撤`。

## Decision

1. **降级读数**：`Monitor.read()` **不再抛** ⇒ 概括层故障时返回
   `summary={}` + **`disputed=True`** + `summary_error`（带类型名）+ **`raw_snapshot` 照给**；
   `MonitorView` 加 `summary_error`；`monitor_summary_payload` 加 **`raw`** 与 `summary_error`。
2. **语义裁决①：「概括层故障」算存疑**（`disputed=True`）—— 硬纪律说"概括与原始不可调和
   ⇒ 原始赢、概括标存疑"，而"**概括根本没出来**"是它的**极端情形**。
3. **`ts` 可选**：`Event.ts`（ISO 8601 UTC，`History.append` 现取墙钟）；**不 bump 版本、零迁移**
   （`from_record` 用 `.get`；`format_version.py:5`"只有结构性变化才 bump"）。
4. **`undoable` 三态槽位**：`Event.undoable: bool | None = None`（**`None`＝未声明**），
   经 `Gate.set/set_batch/seed/record` 透传（全可选 ⇒ 非破坏）。
5. **`之前是什么` 不落事件**：`cockpit.history_records` 已由**全史 fold** 重建
   （`since_seq` **只过滤 emit**）⇒ 只加判据钉住，不改实现。

## Consequences

**换来**：端点上两层并列（概括缺席时原始层照读）；账本有了时间与"能不能撤"的槽位；
`/history` 的 `before` 被判据钉住（含它那条"顺序不可换"的静默错）。

**付出 / 放弃**：

- ⚠ **放弃"用异常表达概括层故障"**：少了一种响亮失败 ⇒ 补偿是 `summary_error` 明文 + `disputed`。
- ⚠ **放弃"端点只服务概括层"**：消费方要自己选层（`raw` 与 `summary` 并列）。
- ⚠ **放弃"事件自带 `before`"**：信息冗余（可由史推出）+ 每条体积翻倍；而"截断的史读不出
  before"这一顾虑**实测不成立**（fold 走全史、过滤只作用于 emit）。
- ⚠ **放弃"`undoable` 用布尔"**：那会把"**没声明**"冒充成"**不可撤**"。
- ⚠ **放弃"`ts` 参与排序/寻址"**：`seq` 仍是唯一顺序（同秒多条、时钟回拨）——
  明文写进 `Event.ts` 的注释，并用判据钉。
- ⚠ **放弃给 `raw` 做分页/裁剪**：`/history` 早已把**全史（含 value）**放上 wire，
  而 `raw` 是它的 **fold** ⇒ **不是新的披露面、体积更小**。

### 迁移须知

- **`Monitor.read()` 不再抛**：原先靠"捕异常"判故障的调用方要改读 `summary_error`/`disputed`。
- wire **加两键**（`raw`/`summary_error`）：加法，老消费方按需忽略。
- `Event` **加两个带默认值的字段**：老 journal 照读（`ts=""`/`undoable=None`）；**无需迁移**。
- ⚠ **`MonitorView.summary_error` 今天没有"显示它的人"** ⇒ 守卫表里如实标 `deferred`
  （投影会透出、但**面板资产不消费**、GP 端点只是带出）——**不许出现"框架开始标存疑了、
  但没人看得见"**；等一个真会显示"概括层故障"的界面出现 ⇒ 转 `consumed` 并点名判据。

## Alternatives considered

**否决：暴露原始层要用新的只读路由 / 加鉴权 / 分页。** `/history` 已把全史放上 wire
⇒ `raw` 不增加披露面，新机制是多余的。

**否决：`read()` 继续抛，只把 `raw_snapshot` 塞进异常对象。** 那仍然"一次概括失败
⇒ 读面整体不可用"，与"两层信任、原始赢"直接冲突。

**否决：`before` 落进事件体。** 见上（冗余 + 体积；且真需求不存在）。

**否决：`ts` 升 `FORMAT_VERSION` 走迁移链。** 加**可选**字段不是结构性变化；升版本会让
存量 journal 多一次迁移成本，换不来任何东西。

**否决：`undoable` 放 `CommandSpec`。** 写入的**唯一收口是 `History.append`**，
而 `CommandSpec` **只覆盖命令面** ⇒ 会漏掉直写路径（三家都有）。

## Required verification

  wire 上可读"；**旧断言（原样抛出）与那条"未支持"登记一起退役**（登记兑现了就撤，
  否则它会变成假话）。
