# 否决：保留 result_meta 这类"无消费方的死契约"

> **状态**：rejected — 全库零调用的契约是负债，不是保险
> **作者**：mecha v2
> **日期**：2026-09-23

## Problem

v1 `spec §0.3` 的 `result_meta` 实测在 `mecha/` + `cockpit/` **零提及**，只有主仓 adapter 实现了它、**无任何消费方**，spec 却称它"消费者必须知道的语义标记"（D-19）。同类：`registry._slim` 透传 `'home'` 字段无人消费（D-20）。

## Decision

**不许留死契约**。每条隐式契约必须二选一：**接线**（有真实消费方 + 判据）或**删除**，并写 ADR 说明（§7 Phase 2 第 5 条）。签名上看不出的隐式键（`ok`/`est_sec`/`method`/`body`）**必须**在 `output.schema` 里显式声明，缺键即校验失败（消 D-15）。

## Consequences

换来：spec 里每条契约都可追溯到消费者；隐式键变显式。付出：删契约要确认无外部私有 fork 依赖（v2 阶段无此顾虑）。

**重新考虑条件**：若某字段有**外部消费者**（项目自有 fork）但库内不调，可保留——但**必须**在 spec 声明该消费者并给出接线判据，不许以"以后会有人用"为由留空。

## Alternatives considered

**否决：留着以防将来用。** 违反 dsh `packages/AGENTS.md:11`"Require a current owner and need"，且正是 D-19 的成因。
