# 否决：库内保留任何固定端口 / 目录名 / 协议版本字面量

> **状态**：rejected — v1 的 8767/.mecha/2025-03-26 教错所有后来者（D-6/D-7/D-8/D-12）
> **作者**：mecha v2
> **日期**：2026-09-23

## Problem

v1 把 `.mecha` 焊死在 `resolve_root`、人工端点写死 `:8767`、`--port` 默认 `8766`、MCP `protocolVersion` 钉死字面量。库与 v1 自己"抢 8765 事故后删端口默认值"的教训直接矛盾。

## Decision

**库内零固定端口默认值；端口由宿主/启动器定。数据目录名必须可由项目注入，不给则明确报错（不猜路径）。协议版本字面量只存在于 Provider 内。** 格式类字面量（pickle protocol、格式串、文件名、环境变量名）全部进 `HISTORY_FORMAT_VERSION` 制度管辖（总纲 §6.4）。

## Consequences

换来：新项目改名自己的数据布局有通道；版本协商腐烂被隔离在 Provider。付出：出厂没有"开箱即用的默认端口"，启动器必须显式配置。

**重新考虑条件**：无一般性重开。仅当某字面量被证明是**协议常量**（外部规范钉死，如线格式魔数）而非部署选择时，允许留在库内并注明出处。

## Alternatives considered

**否决：保留"合理默认值"。** "合理"是 EL 的历史偶然；默认值即契约，接入方照抄就中毒。
