# 否决：文档 / 守卫里手写计数（"N 个必实现"这类）

> **状态**：rejected — v1 为计数漂移付过两次账（18→16、16→17），每次五处手抄全红
> **作者**：mecha v2
> **日期**：2026-09-23

## Problem

README、spec、守卫里到处写着"13 个必实现""16 个工具"。数字随代码变，手抄必然漂移。D-25 甚至出现"守卫断言 README 含字面量 '13 个必实现' 且不读 `__abstractmethods__`"——把计数改成引用反而让守卫当场红。

## Decision

**文档不写计数，只写名字或指向单一来源**（L8）。守卫**必须读实际注册表 / `__abstractmethods__`，不许读手抄数字**（消 D-25）。dsh 全部目录是**生成**的，禁止手写清单（§3 L8 dsh 印证）。

## Consequences

换来：数字永不漂。付出：需要"从代码生成/读取"的工具链，文档不能直接写死数字。

**重新考虑条件**：无。唯一例外是被引用的数字本身是**外部协议钉死的常量**（非我方计数）。

## Alternatives considered

**否决：加"改一处同步五处"的清单纪律。** 治标，漂移是结构问题不是自觉问题。
