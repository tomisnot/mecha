# AI 调用体验：给新项目的指导意见

> ## 这份文档是给谁的
>
> **给正在设计或已经接入了 mecha 的项目。** 它回答一个问题：
>
> > **框架已经把机制给全了，为什么 AI 用起来还是别扭？**
>
> **它是什么**：一份**从实测里长出来的坑清单 + 判断依据**。
> **它不是**：机制说明。机制各有其家，本文**只链接不重复**（D1）：
> - **框架有什么机制** → [`capabilities.md`](../capabilities.md)（生成物）
> - **怎么接入** → [`接入指南.md`](../接入指南.md)
> - **每一条的完整推演** → [`v2/notes/implemented/`](notes/implemented/) 的对应 ADR
>
> ⚠ **本文的依据不是设计者的想象，是使用者 AI 的实测报告。**
> EL 项目的两轮实测由**使用者 AI 自己写 MCP 客户端跑完全工作流**，逐条带证据。
> 那两批问题**全部已修**，修法见 ADR；**本文只把"会疼在哪"抽出来**，供新项目事前避坑。

---

## 0. 一句话

> **机制正确 ≠ 调用顺手。**
> `Gate`/`History`/`Surface`/`Monitor` 对了，AI 仍然可能：**照说明书省参数而崩**、
> **把失败当成功读成物理结论**、**每写一次多一次往返**、**扫 50 个点撑爆上下文**。
>
> ⇒ **调用体验是独立于架构的一层工程量，必须单独做，而且必须由"使用者"实测来驱动。**

## 1. 七条已验证的坑（按"AI 会在哪里卡住"排）

> 每条给：**症状 → 为什么是设计问题（不是 AI 笨）→ 落点 → 出处**。

### P0-1 ⭐ **"可选参数有默认值"很容易是假的**

- **症状**：描述里写"默认 π"，execute 签名写 `pol="π"`，**AI 照说明书省掉这个参数 ⇒ 崩**。
- **根因**：适配层给合成签名里所有非必填参数填 `default=None`，宿主对省略的参数
  **传显式 `null`** ⇒ 盖掉闭包真默认。
- **落点**：注册期从 execute 签名派生 `defaulted` 集合；收到 `null` 且键在其中 ⇒ **丢弃该键**，
  让真默认生效。⚠ 语义边界：`null` 有两种含义（"没给" vs "要清空"）⇒ **按闭包签名区分，不猜**。
- **判据**：真 MCP 往返里，**省略可选参数**的调用必须成功且值等于真默认。
- **出处**：[ADR](notes/implemented/2026-09-24-调用体验对齐v1-默认值生效与回读与结构化错误.md) §Decision 1

### P0-3 ⭐⭐ **失败必须机器可判别，否则 AI 会读成"物理结论"**

- **症状**：工具失败时 `isError=False`、错误当**成功正文**返回（纯文本 `"Error executing tool ..."`）。
  使用者 AI **差点把"参数崩了"当成"π 脉冲无效"的实验结论** —— **静默错答案**，最贵的一类。
- **落点**：失败**不要抛异常**（宿主会给它加前缀、把结构化信息搅进散文），
  而是直接返回"带 `is_error=True` 的结构化结果"；正文统一
  `{ok:false, error:{message, info:{kind, hint, suggest}}}` ⇒ **AI 读 `info.kind` 决定怎么改**。
- **判据**：失败回执 `isError=True` 且正文可 JSON 解析出 `info.kind`。
- **出处**：同上 ADR §Decision 2

### P1-4 ⭐ **写操作要"写一次就自证"**

- **症状**：写回执只有 `{ok, key, applied}` ⇒ **每写一次多一次 `read_*` 往返**才能确认。
- **落点**：回执带三口 —— **`before`（写前值）/ `resolved`（落地事件的值）/ `readback`（写后从快照读回）**。
  ⇒ AI 不必二次查询即可核对"**我声称写的**"与"**域里真存的**"是否一致。
- **出处**：同上 ADR §Decision 3

### P1-5 **要有"清零"入口，否则 AI 在别人没收拾的台面上干活**

- **症状**：状态跨会话残留，**没有任何入口清零**。
- **落点**：一个 `reset_config` 类工具 —— 对当前快照每个键写回 `None`（validate 放行 `None`=回默认
  是**既有语义**，GUI"留空=默认"同源）⇒ **不另造第二条落地路径**；逐键留痕，回执列清单。
- ⚠ **不许走"删 History / 重置快照"旁路**（append-only 是硬纪律）。**台面干净与史实完整不冲突。**
- **出处**：同上 ADR §Decision 4 + Alternatives

### P1-6 / 4-4 ⭐⭐ **编排省下的回合，很容易花回"对齐结果"上**

- **症状 a**：编排回执的 `outputs` 是**位置数组**，`steps[].detail` 成功步为空 ⇒ **省了往返，花回对齐**。
- **症状 b**：要自己从 N 个完整 output 里抠关注量 ⇒ **扫 50 个点就撑爆上下文**。
- **落点**：
  - `steps` 每步 `{index, op, ok, detail, output}` —— **output 直接挂进步里**，顶层位置数组退役；
    成功步 `detail` 给短摘要，失败步 `detail` 是**教学原因**。
  - **`pick` 投影**：给键路径列表，**只回关注量**，投影每步 output。
    ⚠ **整键优先**（JSON 键本身可含点）；缺失键**如实列 `_missing`，绝不静默 null**。
- **出处**：[扫描顺手感 ADR](notes/implemented/2026-09-24-扫描顺手感-spec_patch与op别名与pick投影与t_max对账.md) §Decision 1/3

### 4-1 ⭐⭐ **扫描必须"只写变化量"**

- **症状**：配置参数是**整表替换**语义 ⇒ 扫 9 个点要手写 **9 份完整 config**，
  **单次调用一大坨 JSON 且极易漏键**（实测作者"差点漏 `decay_index`"）。
  原话：*"这轮唯一还让我累的地方。"*
- **落点**：**`spec_patch`** —— 在**当前配置**上只覆写列出的键；步不给则用顶层 patch。
  ⚠ **patch 只进本次 run 的 spec，不写快照**（扫描不改域状态）。
- **出处**：同上 ADR §Decision 1

### 4-2 **工具名与 op 名别搞成两套账**

- **症状**：顶层工具叫 `estimate_run`/`run_sim`，编排里的 op 叫 `estimate`/`run` ⇒
  AI *"每次都得试一次"*（报错列合法值只是**止损，不是免错**）。
- **落点**：编排入口做**别名映射** ⇒ 一套名字两种写法都收。
  ⚠ **不改内核的 op 名**（那是内核既有事实），别名是**入口便利**。
- **出处**：同上 ADR §Decision 2 + Alternatives

## 2. 三条从 dsh（成熟 harness）看来的做法

> ⚠ 这三条**我们没有实现**，是**观察到的、可借的机制思路**——不是我们的现状。
> 依据：dsh（DeepSeek Harness）源码仓的 `docs/` 与 `packages/` 自述（**本机检出路径不入库**）。

### ① **"先读后改"可以是机制，不是纪律**

它的 `fs-observation-policy` 独立成包：**要求先读取，文件系统工具才可覆盖或编辑**；
**文件自读取后变了就拒绝**，并提示"重新读取后重试"；**读取缺失路径 = 授权带防护的创建**
（仍防覆盖并发创建的文件）。
⇒ 对领域的类比：**凡"改前需要知道当前状态"的写操作，都可以把这条做成机制**
（我们只有 `set_config` 的回读自证，那是**事后**；这是**事前**）。

### ② **大结果"存起来 + 给定位符"，不要倒进上下文**

它的 `spill`：存下文本，返回**不透明定位符 + 检索指引 + 精确字节数**；
⚠ `suggestedName` **只是命名提示，绝不是路径**（后端会消毒成单个安全路径段）。
⇒ 我们有 `artifacts`（落盘 + 不透明定位符）**但没接到工具结果这条路上**。

### ③ **长活要能被"统一控制"**

它用 **3 个工具管所有种类的后台活**（后台命令、PTY、subagent 都走同三个）⇒ AI 学一次就够。
⚠ 它的 `JobRegistry` 是**机制**；而"上限、队列"**它也没给** ⇒ 那是**项目要自己想到的**（见 §3）。

## 3. ⚠ 三条"框架给了机制、但**项目必须自己想到**"（最容易漏）

> 这一节的依据是实测：**同一个机制，一家想到并兜住了，另一家没想到。**

| # | 机制 | 项目必须自己补什么 | 证据 |
|---|---|---|---|
| **1** | `jobs.submit` | ⚠ **并发上限**。框架 local 实现是"**每次 submit 新起一个 daemon 线程、不排队、无上限**" | GP 用 `BoundedSemaphore` 兜住，**超额响亮拒绝**；EL 未做 |
| **2** | `jobs.submit` | ⭐ **提交前的写权预检** ⇒ 让 AI **同步**拿到拒绝，而不是**提交一个注定被拒的 job、再去轮询失败** | GP 有（`authority.gate()` 前置，且**在 `sem.acquire` 之前** ⇒ 无副作用）；EL 未做 |
| **3** | `Surface` 的 QUERY 注册 | ⭐ **只读能力要注册进去**，否则编排（见 §4）**够不到它们** | EL 注册 5 条；ML 注册 4 条；**GP 有 25 条 `kind="read"` 声明、注册 0 条** |

⚠ **这三条的共同形状**：框架提供**动作**（submit / register），
但"**这个动作在什么条件下该被允许**"是**项目的判断** —— 框架**没有默认**，也**不该猜**。
⇒ **接入时请逐条问：这个机制有没有"上限 / 前置条件 / 解除条件"是我该补的？**

## 4. ⭐ 编排面（CodeAct）：框架有能力，但不是每家都接

**框架提供** `CodeAct`：**受限动作解释器**，动作是**结构化 dict**（不是 eval 任意代码），
**逐子调用一条记录落 History**，一段共用一个 `call_id` ⇒ 中途崩了已跑的步仍在史里。

**接上它需要两步**（缺一步就等于没有）：

1. **模型入口**：一个 `run_actions` 类工具，参数是动作序列；
2. ⭐ **把只读能力注册进 `Surface` 的 QUERY** —— 否则编排**只够到内核四个内置动作**（`run`/`summary`/`estimate`/`schema`），
   **够不到项目的领域查询**。

EL 的做法（**一份实现两处用，不造第二真值**）：
```python
for _qn in DOMAIN_QUERY_OPS:
    _tool = reg.get(_qn)
    surface.register(EntryKind.QUERY, _qn, _tool.execute,
                     called_by="framework:CodeAct.run_actions")
```
⇒ ⭐ **`called_by` 是那个"具名消费者"**：注册时**必须说清谁调它**。
⇒ **判据**：`Surface.entries('query')` **不为空**（ML 的注释原话：*"第二条标准路径也被真实消费"*）。

**什么时候值得接**（EL 的判断依据）：
> 高频常见查询**藏进编排的回合成本 > 占一个工具位**
> ⇒ 原则不变（读仍不建第二条实现），**权衡随证据更新**。
> （该判断**部分取代**了此前"读操作不升顶层工具"的否决 —— 见 ADR 的 Alternatives。）

⚠ **反面**：GP 有 **25 条只读能力**，只能**一个一个调**；它的 `GAPS.md` 自己登记了这个缺口
（*"编排面（CodeAct）未做：当前'流水线即编排'"*）。**那是当时的取舍，不是疏漏** ——
但**接入新项目时请重新评估**，尤其是**只读能力超过 10 条**、或**扫描/多步组合是常见用法**时。

## 5. 一条贯穿全部的原则（EL 做得最成功的地方）

> **把"AI 容易搞错的地方"写进工具描述里，而不是指望它读文档。**

实例（EL `query_levels` 的描述原文）：

> *"设初态 `dynamic.psi_single` 用的**身份键就从这里取，别猜索引**。"*

这一句**就是在防一个具体的 AI 行为**（猜索引）。同类机制还有：

- **`banned_words`**：工具描述里**禁止出现实现词**（`gate` / `registry` / `轮询` / `线程` / `engine_kwargs`）
  ⇒ 与成熟 harness 的 *leak-free descriptions* 是同一条纪律。
  逐工具声明，**注册时校验**。
- **`t_max_note`**：`set_drive` 回执里，若 `t_max` 与脉冲时长不等，
  给一句**方向性提示**（晚于→"终态含脉冲后自由演化"；早于→"脉冲被截断"）。
  ⭐ **提示不拦止** —— *"自由演化/截断都可能是故意设计，接口只保证'看得见'，物理判断归实验者。"*
- **物理正确的默认值**：`pol="π"`、`offset=0` 这类**真默认**要让它**真的生效**（见 P0-1）。

⇒ ⭐ **这是"内容活"，不是"架构活"，而且没有任何 harness 能替项目做** ——
因为只有项目同时懂**自己的领域**和**AI 的行为**。

## 6. 接入时的自检清单

**调用面**
- [ ] 每个可选参数的"默认值"**实测过**吗（省略它，真默认生效了吗）？
- [ ] 失败回执是**机器可判别**的吗（`is_error` + 结构化 `kind`），还是**一段散文**？
- [ ] 写操作有**回读自证**吗（`before` / `resolved` / `readback`）？
- [ ] 有**清零/复位**入口吗？（且**不走**删账旁路）
- [ ] 工具描述里**有没有实现词**（`gate`/`registry`/`线程`/`轮询`）？

**编排与扫描**
- [ ] 只读能力**注册进 `Surface` 的 QUERY** 了吗（`called_by` 说清了吗）？
- [ ] 有 **`run_actions` 类入口**吗？（没有 ⇒ AI 每步一次往返）
- [ ] 配置是**只写变化量**（patch）还是**整表替换**？
- [ ] 结果能 **`pick` 投影**吗？（不能 ⇒ 扫 50 点撑爆上下文）
- [ ] 编排回执的每步**带名字**吗，还是**位置数组**？

**机制的自兜（§3）**
- [ ] 长活有**并发上限**吗？
- [ ] 长活提交前有**写权/前置条件预检**吗（同步拒绝 > 提交后轮询失败）？
- [ ] 大结果有**落盘 + 定位符**吗，还是直接倒进上下文？

**验收方式**
- [ ] ⭐ **这些坑是"使用者"发现的，不是设计者** ——
      请让一个**真的用它干活的 AI**跑一遍全工作流，**逐条带证据**写报告。
      EL 的两轮报告就是这么来的，而且**第一轮修完后第二轮又找出了新的一批**（§1 的 4-x）。
