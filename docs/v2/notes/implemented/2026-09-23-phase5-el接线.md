> **作者**：mecha v2
> **日期**：2026-09-23

> 下线、GUI 写路径迁到 v2 Gate）。本 note 交付 ② 的接线实现；①（并存部署）
> 已由 hub.py 独立进程形态覆盖。②（同日，通读总纲后补）：§1.2 事实 2

## Problem

参考 Provider 判据（phase5-el-provider）证明架构能被 EL 接住，但"人机同一道门"
还没在真项目里成立：EL 的 GUI 写路径仍走 v1 `AppBridge`，AI 写路径走 v1
`serve.py`——两扇门、两份史。用户已显式授权跨仓接线（"大胆去改，不绕弯子"）。

接线要同时守住三条既有纪律：
- **不被 v1 旧代码锚定**：新代码只 import v2 库与 EL `src.core`，不读不抄
  `src/adapter/`、`mecha.app_bridge` 的形状（人工端点镜像的是 v1 的**决策**
  ——actor 服务端固定 human、AI 不能自授权——不是它的代码）。
- **actor 由通道钉死**（L4）：人工端点的 actor 在服务端写死 `human`，请求体
  伪造不了；MCP 面改不了 mode（`switch_mode` 拒非 human 通道）。
- **v1 默认不变**：GUI 直启仍是 v1，v2 是显式开关——并存部署，不搞大爆炸切换。

## Decision

**EL 仓新增 `src/v2_bind.py` 接线层 + `app_entry.py` 的 `RE0_V2=1` 分支**，
mecha 仓不改一行（bridge/hub 的接口已够用）。落地形态：

1. **单进程共享 Gate**：`make_v2_bridge` = `V2Bridge.for_shared`（引擎
   own_thread=True，cache 经 CacheProxy 汇流到池线程守 ARC SQLite 亲和）
   + `serve_mcp`（后台线程 MCP 服务器，AI 连它，写经**同一个** Gate）
   + `start_human_control`（人工控制端点，镜像 v1 形状：`/switch_mode`
   `/write` `/write_many`，token 文件 `.human-token`，端口 8767）。
   GUI 主线程直接读写与 MCP 线程写 → 同一快照、同一份 journal。

2. **v1/v2 同名 mecha 的冲突处理**：`v2_bind` 把 v2 仓根插到 `sys.path[0]`
   （`MECHA_V2_ROOT` env 优先），假设 v2 已生效；GUI 消费点（`ui_dynamic` /
   `ui_manybody` 的 `load_artifact`、`solver_inspector` 的 gc）用
   try/except ImportError 双路——v1 在位走 v1，v2 在位走 `v2_bind` 垫片。
   同进程只允许一个 mecha，这是刻意的（混装=两份真值）。

3. **gc 如实报告不静默**：v2 未实现数据回收（D-9），垫片返回
   `{ok: false, note: …}`，GUI 回收按钮显示"未接线"而非假装成功。

4. **GUI 模式门控现状**：`_mecha_bind.Binder` 已按 `can_write('gui')` 物理
   只读门控（AI 模式下 GUI 控件不可写），这条在 v2 下自动生效。GUI 内**没有**
   夺权/交权按钮（v1 也没有），模式切换走人工端点——不为此新造
   `authority_switch` 事件类型，等真接 GUI 按钮时再写 ADR（Definition 只放
   框架真会调的，L2）。

5. **undo/redo 未接**：v2 History 是 append-only，撤销语义要按"反向 set 记
   新事件"重新定义，与 v1 `session.undo` 不同——**决策已定**（见 ADR
   `EL能力面取舍` 第 3 条），实现挂起至 GUI 撤销按钮接线（真实调用方出现）。

6. **Monitor 接进消费配置**（通读总纲后补，§1.2 事实 2 第一交付物）：
   `V2Bridge` 构造时建 `Monitor(history.events, el_summarizer)`——`el_summarizer`
   住 mecha 仓 examples（领域概括是消费配置，不是库件），人话键一律
   `Claim(value, target=原始键)` 显式指向（审查 P3-b 机制的第一次真消费）；
   bridge 开 `history` 只读口给原始层。EL 侧 `src/ui/monitor_panel.py`
   （QDockWidget 右侧停靠）两层并列 + disputed 红条（原始赢）+ AI 归因高亮，
   写事件经 pyqtSignal 编组回主线程（MCP 线程写也刷得动）。

## Consequences

换来：**"人机同一道门"在真实项目里成立**——EL GUI（RE0_V2=1）与 dsh AI 共一
Gate、一份 History、一份真值；写权互斥、归因（gui/human/ai 进史）、原子批量
（write_many/load 走 set_batch）全部在真引擎上可验。headless 冒烟全绿：bridge
装配 ~7s、人工端点夺权/交权/写、MCP 真协议往返、journal 同史含 gui+human。

付出：EL 仓多一个接线层文件要维护对齐 v2 接口；v1/v2 并存期两套判据
（EL `checks/` 的 v1 判据在 RE0_V2 下会红——v1 判据测 v1，不迁就）。

活体验收（交用户）：`RE0_V2=1 python 能级.py` 起 GUI；dsh `web --patch` 连
`.mcp-port` 验"仿佛手脚"；`curl` 人工端点夺权。

## Alternatives considered

**否决：把 v2 直接替换 v1（不留 RE0_V2 开关）。** 大爆炸切换——v1 判据 ~20 个
全红、无回退路径，违背并存部署的渐进纪律。
**否决：GUI 与 AI 各起一个进程、靠共享 journal 文件同步。** 两份快照内存投影
要处理竞态与重放时序，等于重造 v1 Hub 的客户端同步问题；单进程共享 Gate 一把
锁串行写，简单且是真值。
**否决：在 mecha 库里加 v1 兼容垫片（mecha.ops 等）。** 库不认宿主词（L4）；
兼容是消费配置（EL 侧）的事，垫片住 `src/v2_bind.py` 正是这个边界。
