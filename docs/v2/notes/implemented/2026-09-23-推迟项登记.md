# 推迟项登记：本轮明确不建的四件（各带重新考虑条件）

> **状态**：implemented
> **作者**：mecha v2
> **日期**：2026-09-23

## Problem

Phase 1-4 实现中遇到若干"总纲没细写、但 dsh 有对应件"的能力。按硬纪律
9/10（没写的决策写 ADR、边界写机制不写分类、推迟不许沉默），逐件登记：
现在不建什么、为什么、什么条件重新考虑。

## Decision

本轮**不建**以下四件（代码里各模块 docstring 的 Limitations 段已就近标注，
本 note 是集中登记）：

1. **Log.subscribe（心跳推送原语）**：当前无订阅消费者，Monitor 按需读。
   v1 的心跳 15s vs 轮询 10s 双值漂移（D-11）教训是"同一概念单一来源"——
   没有消费者就不预建第二个来源。
2. **Tool.present_call / present_result（UI 展示投影）**：Monitor 读面够用；
   宿主卡片需求等真实 UI 出现再加。
3. **dsh 侧 Provider 接线（ctx.jobs / spillStore / approval 的注入实现）**：
   无真 dsh 宿主进程可测，现在接是假接线（违反 L6"机制建好必须装配接上"）。
   接线与其实测判据归 Phase 5（EL 消费配置）。
4. **Jobs 跨进程重启找回**：local 注册表在存活期内可查即可；把 job 元数据
   落 History 等第二个项目有需求再做。

## Consequences

换来：不预建 n=0 的机制，代码面小、无哑扩展点。付出：真实订阅者/UI/宿主
接入时要补一轮实现 + 判据。

## Alternatives considered

**否决：照 dsh 全量能力清单补齐对应件。** dsh 是 266 包 monorepo、有真实多
操作者负载；我们是单仓 n=1，照抄 = 把它的形状焊进我们（总纲 §4.3 实现细节
不当契约）。**重新考虑的统一条件**：出现第一个真实消费者调用该能力，或第二
个有据项目（n=2）。
