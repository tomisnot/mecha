# 推迟项登记：本轮明确不建的四件（各带重新考虑条件）

> **状态**：implemented
> **作者**：mecha v2
> **日期**：2026-09-23

## Problem

Phase 1-4 实现中遇到若干"总纲没细写、但 dsh 有对应件"的能力。按硬纪律
9/10（没写的决策写 ADR、边界写机制不写分类、推迟不许沉默），逐件登记：
现在不建什么、为什么、什么条件重新考虑。

## Decision

本轮**不建**以下四件（代码里各模块 docstring 的 Limitations 段已就近标注，
本 note 是集中登记）。**每条绑定一个具体触发事件**（审查 §3：推迟不许指向
"某个 Phase"这种会关门却没人回来复核的模糊锚点——触发必须是可判定的"某消费者
出现 / 某能力被真用"，且触发发生时必须回本 note 复核）：

1. **Log.subscribe（心跳推送原语）**：当前无订阅消费者，Monitor 按需读。
   v1 的心跳 15s vs 轮询 10s 双值漂移（D-11）教训是"同一概念单一来源"——
   没有消费者就不预建第二个来源。
   **触发**：出现第一个需要"事件到达即推"的真实消费者（如 dsh 侧行为史订阅）。
2. **Tool.present_call / present_result（UI 展示投影）**：Monitor 读面够用；
   宿主卡片需求等真实 UI 出现再加。
   **触发**：宿主（dsh 侧边栏 / GUI 卡片）要求把工具入参/回执投影成 UI 片段。
3. **dsh 侧 Provider 接线（ctx.jobs / spillStore / approval 的注入实现）**：
   无真 dsh 宿主进程可测，现在接是假接线（违反 L6"机制建好必须装配接上"）。
   **触发**：有真 dsh 宿主进程可注入 ctx 句柄（即"dsh 侧 Provider 实测"任务）。
   **Phase 5 关门复核（2026-09-23，回应审查 §3）**：Phase 5 落地的是 **local
   Provider 的消费面**（jobs→submit_job/read_job/cancel_job、codeact→run_actions
   已接进 EL 工具面并有真协议往返判据）——**不是 dsh 侧 Provider**。本条触发
   未发生（仍无真 dsh 宿主），**保持推迟，但已回登**：local 半边消费已坐实，
   dsh 半边待"ctx 注入可测"。
4. **Jobs 跨进程重启找回**：local 注册表在存活期内可查即可；把 job 元数据
   落 History 等第二个项目有需求再做。
   **触发**：出现"进程重启后需找回在飞 job"的真实调用方（注意：写租约（审查
   2.2）已保证单目录单宿主，跨进程找回的前提"两宿主共享 job 态"当前不存在）。

**回登（2026-09-25，产物契约落地）**：产物契约
（`2026-09-25-产物契约-Artifact与不透明定位符.md`）同样带三条推迟项，各绑
可判定触发，正文不在此重复：Artifact 的**跨重启 locator 找回**（触发：出现
"进程重启后仍需用旧 locator 取回产物"的真实调用方）、**dsh 侧产物句柄接线**
（触发：有真 dsh 宿主可注入句柄、且宿主产物确实需要跨进程回程）、
**GC/保留策略**（触发：出现因产物堆积真实耗尽磁盘的部署）。三条**触发均
未发生**，保持推迟。

## Consequences

换来：不预建 n=0 的机制，代码面小、无哑扩展点。付出：真实订阅者/UI/宿主
接入时要补一轮实现 + 判据。

## Alternatives considered

**否决：照 dsh 全量能力清单补齐对应件。** dsh 是 266 包 monorepo、有真实多
操作者负载；我们是单仓 n=1，照抄 = 把它的形状焊进我们（总纲 §4.3 实现细节
不当契约）。**重新考虑的统一条件**：出现第一个真实消费者调用该能力，或第二
个有据项目（n=2）。
