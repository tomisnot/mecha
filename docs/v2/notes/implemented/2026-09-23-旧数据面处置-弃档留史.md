# 旧数据面处置：弃 v1 存档、v1 史留只读归档（⑤ 拍板）

> **状态**：implemented
> **作者**：mecha v2（回应《待办-代替v1六件事》§2⑤）
> **日期**：2026-09-23

## Problem

v1→v2 切换时 EL 盘上有两份 v1 遗留数据（实测复验，非抄文档）：

```
.mecha/journal.jsonl   1553 行   ← v1 域状态史
save_state/            35 个文件  ← v1 存档（autosnap + 手动）
```

v2 的 `bridge.py` docstring 已明写"不兼容读 v1 旧存档（`'mecha-session-v1'`
格式）"，`MigrationChain` 的迁移边为空（D-12："v1 是唯一版本"时不需要边）。
弃掉一份 1553 行的域状态史 + 35 个存档算非平凡改动（ADR 制度第 1 条），
**必须有一句写下来的决定**，否则后人反复考古"要不要迁移"。

**一手证据（本轮探针，真 core + 真盘）**：
- 存档：`save_state/` 里出现过的带点配置键共 60 个，其中 **34 个 v2 已不认**
  （含整个 `engine.*` 只读族——v2 `settable_keys()` 不含，`make_validator` 会
  以 `readonly_key` 当场拒）。v2 的写是 `set_many` 全或无 ⇒ 这些存档**本来就一个
  都 load 不了**。弃档成本 ≈ 0（不是"我们决定不兼容"，是"它们已经读不进来"）。
- v1 史 1553 行：格式是 v1 的事件形状，与 v2 journal 的 append-only 事件不同构。

## Decision

1. **v1 存档（`save_state/` 35 文件）：明确弃，不写迁移边。** 有证据（34/60 死键、
   全或无必炸）、成本 0。不删盘上文件（那是用户数据，弃 ≠ 删），只是 v2 **不提供
   读它们的代码路径**——`load` 只认 v2 自己的快照格式。

2. **v1 史（`.mecha/journal.jsonl` 1553 行）：留只读归档，不迁移进 v2 史。**
   理由：域状态史是 v2 定位的核心资产（总纲 §5.2②），删它 = 销毁历史；但把它
   折进 v2 journal = 造第二真值 + 触发 validate 拒（事件形状不同构）。处置：
   v2 全新起 `.mecha-v2/journal.jsonl`，v1 史原地留盘、只读、人可读（JSONL 文本）。
   **不建"读 v1 史"的 API**——真要考古直接开文件。

3. **不实现 v1→v2 迁移边（D-12 维持空）。** 存档读不进、史不折入 ⇒ 没有需要
   迁移的数据流。迁移边为空是**决策**，不是待补的洞。

## Consequences

换来：切换时没有"数据迁移"这个隐藏工程项；后人读到本篇即知"弃档留史"是定案。
付出：v1 那 1553 行史在 v2 的工具面里**查不到**（要回看 v1 历史只能开文件）——
这是刻意的，v2 的 History 只装 v2 起的事件，边界干净。存档彻底失联（本就 load 不了）。

## Alternatives considered

- **否决：写 v1→v2 存档迁移边。** 34/60 键已死 + `engine.*` 必被 validate 拒 ⇒
  迁移边要么丢键（静默改数据，违背 L3"不静默"）、要么整档拒（那迁移就没意义）。
  为一个"读不进来"的格式建迁移器是纯负债。
- **否决：把 v1 史折进 v2 journal 续写。** 事件形状不同构，折叠要写翻译器；
  翻译后的史既不是 v1 原样也不是 v2 原生——两份都不像，是第三真值。留只读原档
  比造翻译保真度高。
- **否决：删掉 v1 史和存档"保持整洁"。** 那是用户盘上的历史数据，软件无权替用户
  销毁；"弃用"（不读）与"删除"（销毁）是两件事，本篇只决定前者。
