# 代替 v1：判据迁移与退役清单

> **状态**：implemented
> **作者**：mecha v2（执行委托方《待办-代替v1六件事》①④）
> **日期**：2026-09-24

## Problem

EL 仓的判据树（`checks/`）长在 v1 门面（`mecha.session/bus/ops/registry/server`、
`src.adapter`、`cockpit`）上。库替换（卸 mecha-sdk、editable 装 mecha v2）+
app_entry 翻默认后，这些判据大面积红——其中一部分守的东西 v2 已有等价机制
（该迁移），一部分守的东西 v1 特有、v2 设计上不存在（该退役），一部分纯领域
（该原样保留）。不留清单地删会犯 L8/D4 的账：**退役必须可追溯**。

## Decision

三类处置，逐文件点名（判据名即唯一标识，不写总数）：

**迁移（重写为 v2 真面，EL 仓）**：
`authority`（纯内存 Authority+Gate+Channel）、`human_control`（V2Bridge +
v2_bind 端点）、`ops_threadsplit`（ElOps；spy==0 断言诚实弱化为"工作线程不炸
SQLite 亲和"）、`gui_bind` / `gui_run_worker` / `gui_run_flow`（V2Bridge.for_gui）、
`docs_consistency`（build_tool_registry 的 schemas() ⇄ SKILL 工具表互钉）、
`solve_max_step_hard`（D 组改经 protocol.solve_schema() 派生面）、
`manybody_integration`（make_validator 真门 + Surface.run + ElOps）、
`gui_app_entry`（C 组改 v2 启动器形状：spawn GUI、无 cockpit/serve 回流）。
新建 `drive_wave`：接替 `fields` 的换算物理守卫（freq/Rabi 往返/π 时长/
非法波当场拒/append-replace/摘要不内联），经真门（set_drive 工具 + Gate）。

**退役（git rm，理由各一句）**：
- `mecha_backend` / `mecha_kernel` / `mecha_codeact` / `mecha_mcp` /
  `mecha_domain_words` / `mecha_purity` / `mecha_gc` / `mecha_toyengine` /
  `mecha_readme_consistency`——测 v1 库内核（Session/Bus/Ops/registry/
  autonomy/hooks/gc/ToyEngine/spec-draft）；v2 等价面由 mecha 仓 run_all
  （phase1-5 + capability_map + vocabulary + l8 + adr_format +
  known_limitations）守，不跨仓重复。
- `app_bridge`——V2Bridge 消费契约已在 mecha 仓 `phase5_bridge_selfcheck`
  钉死（同一形状两处测 = 双账）。
- `hub_bridge_contract`——HubBridge 双 transport 被同进程共 Gate 设计取代。
- `cockpit` / `cockpit_archive` / `cockpit_config_tree`——驾驶舱退役，
  Monitor 侧边栏接替（ADR 硬件互锁归属同族决定）。
- `interlock`——v2 无库内互锁（ADR 硬件互锁归属：Provider 层的事）。
- `gui_gc`——`mecha.gc` 在 v2 不存在；gc 垫片如实报告（D-9 触发再迁）。
- `fields`——物理守卫由 `drive_wave` 接替（门面类本身随 adapter 删）。
- `spec_adapter_parity`——对将删的 v1 adapter/spec-draft 的 parity 无意义。

**保留（纯领域，不碰 v1 门面）**：core/evolve/sweep/pair/mixed/hard/field_loss/
engine_contract/runspec_contract/cleanliness/checks_sentinel/dissip/levels/
static_ai/manybody_m0/m1/narrow_pulse/mw_pair/ai_h_snapshot/engine_params/
two_field/gui_run_flow 之外的 UI 判据（gui_inspector / gui_manybody）经
bridge 门面访问，v2 下原样跑绿（mecha 侧两修：params engine 族裸名、
validate 放行 None——均记独立提交）。

## Consequences

换来：EL 判据树全部站在 v2 真面上，v1 删除后无残留引用；退役项有名字清单可查，
将来第二项目需要 gc/互锁时按登记复活对应机制（触发事件见遗留登记簿）。付出：
`ops_threadsplit` 的 B 组覆盖面弱于 v1（spy 计数 → 后果断言），docstring 已注明；
`use_cache` 内容寻址、`overlap_warning`、`edit_wave` patch、arb 改道提示等
v1 Fields 面守卫在 v2 暂无等价判据（机制本身在 set_drive/validate_wave_list
里存在，缺的是判据覆盖——登记为缺口，不假绿）。

## Alternatives considered

**否决：退役判据全部改写成 v2 等价物。** 其中多数测的是 v1 库内核
（Session/Bus/registry/hooks），v2 的等价守卫在 mecha 仓 run_all 里已经存在且
更近（测库本身不跨仓）——跨仓重复一份 = 双账，正是本仓反复拆的东西。
**否决：留着红的判据等"以后再说"。** 红的基线会让下一次真红被淹没（D4：
假绿比红更危险的反面——长期红同样致盲）。
**否决：`ops_threadsplit` 保留 spy==0 断言、给 ElOps.execute 包一层可 spy 的
cache 代理凑绿。** 那是为判据形状改生产代码（测试戳私有成员的变体）；诚实
弱化为后果断言（工作线程不炸 SQLite 亲和），docstring 写明覆盖面变化。
