# 调用体验对齐 v1：默认值生效 / 回读自证 / 结构化错误 / 清零入口

> **状态**：implemented
> **作者**：mecha v2（回应《mecha-v2-AI调用体验实测报告》——使用者 AI 自写
> MCP 客户端全工作流实测）
> **日期**：2026-09-24

## Problem

实测报告（EL 仓 `docs/mecha-v2-AI调用体验实测报告.md`）逐条带证据地指出：
v2 架构对了，但**调用面比 v1 粗糙**——v1 做到的体验退化了。用户裁决：
**架构不让步，但努力实现同样的效果**。疼点按序：

- **P0-1 可选参数"有默认值"是假的**：`set_drive` 的 execute 签名写 `pol="π"`，
  description 也说"默认 π"，但宿主不套默认——根因在 hub 的 `_register`：给
  合成签名所有非 required 参数 `default=None`，宿主 pydantic 对**省略的参数填
  显式 null** 传进来，盖掉闭包真实默认。AI 照说明书省参数就崩（P0-2 的误导
  文案 `pol=None 不支持按 Rabi 换算` 也是它的下游症状）。
- **P0-3/P2-8 失败不可判别、形态不统一**：工具失败时 `isError=False`、错误当
  成功正文返回（`"Error executing tool ..."` 纯文本）。使用者 AI 因此差点把
  "参数崩了"当成"π 脉冲无效"的物理结论——静默错答案，D5 大忌。
- **P1-4 写入没有可核对的回读**：v1 的 `resolved`+`readback` 并排（"写一次就
  自证"）在 v2 退化成 `{ok,key,applied}`，每写一次多一次 `read_config` 往返。
- **P1-5 状态跨会话残留且无从清零**：没有 `reset` 入口，"每次上手都在别人没
  收拾的台面上干活"。
- **P1-6 `run_actions` 结果不好读**：`steps[].detail` 成功步为空串、`outputs`
  是位置数组——编排省下的回合花回对齐上。
- **P1-7 常见查询没升顶层**：看当前驱动要绕 `run_actions` 塞 `get_waves` op。

## Decision

全部落在**适配层与 Provider 层**，Gate/History/Authority/Surface 四件正职零改动：

1. **默认值生效（hub `_register`，P0-1）**：注册期从 execute 闭包签名派生
   `defaulted = {有非 None 默认值的参数}`；`_fn` 收到 `null` 且键在 `defaulted`
   ⇒ **丢弃该键**，让闭包真默认生效。语义边界：闭包默认本就是 None 的参数
   （如 `set_config.value` 必填、显式 null=清空回默认）不受影响——**null 的
   两种含义（"没给"与"要清空"）按闭包签名区分，不猜**。

2. **结构化错误过 MCP 线（hub `_register`，P0-3/P2-8）**：失败不再抛 ToolError
   文本（mcp 会给它加 `Error executing tool` 前缀、把结构化信息搅进散文），
   改为**直接返回 `CallToolResult(content=[JSON], is_error=True)`**——mcp 对
   CallToolResult 透传不加前缀。正文统一
   `{ok:false, error:{message, info:{kind,hint,suggest}}}`，与 v1 的机读形状
   同构；AI 读 `info.kind` 决定怎么改。

3. **回读自证（EL `tools._set`，P1-4）**：`set_config` 回执加
   `before`（写前快照值）/`resolved`（gate.set 落地事件的值）/`readback`
   （写后从快照读回）——对齐 `bridge.write` 既有形状，一份语义一处实现。

4. **清零入口（EL 新工具 `reset_config`，P1-5）**：对当前快照每个键
   `gate.set(channel, key, None)`——validate 放行 None=清空回默认是既有语义
   （GUI"留空=默认"同源），**不另造第二条落地路径**；逐键留痕，回执列
   `cleared` 清单。

5. **编排结果带名字（EL `_run_actions`，P1-6）**：`steps` 每步 `{index,op,ok,
   detail,output}`——output 直接挂进步里，顶层 `outputs` 位置数组退役；成功步
   detail 给短摘要（回执首个标量键值），失败步 detail 是教学原因。

6. **`read_waves` 升顶层工具（EL，P1-7）**：命名守卫禁 `get_` 前缀（架构不让
   步）⇒ 用 `read_` 动词与 `read_config` 同族；`DOMAIN_QUERY_OPS` 同步改名，
   `run_actions` 仍可达同一份实现（一份实现两处用）。**部分取代**
   `2026-09-23-EL驱动手感` 中"否决 get_waves 做成顶层工具"一条：该否决的
   理由是"读操作占工具面与投影折叠原则冲突"，但实测证明**高频常见查询藏进
   编排的回合成本 > 占一个工具位**——原则不变（读仍不建第二条实现），
   权衡随证据更新。

7. **判据活体钉回归**：`phase5_hub`（真 MCP 往返）新增——省略可选参数的
   `set_drive` 必须成功且 `wave.pol=="π"`（P0-1）、失败回执必须
   `isError=True` 且正文可 JSON 解析出 `info.kind`（P0-3）、`set_config` 回执
   带三口回读（P1-4）、`read_waves` 顶层直读（P1-7）；`phase5_el` 新增
   run_actions 步形状（output+detail、无位置数组）与 reset_config 全清断言。

## Consequences

换来：使用者报告的 P0/P1 全部消除，v1 的"写一次就自证、照说明书省参数、失败
机器可判别"体验回归；错误文案不再指错方向（pol=None 不再到物理层）。付出：
① 顶层工具 12→14（+`read_waves`/`reset_config`）——实测报告的回合成本证据
支撑，非手感膨胀；② hub 的 `_fn` 多一条 null-丢弃规则，其正确性依赖
"required 派生自闭包签名"这条既有单一来源（defaulted 集合同源派生）；
③ `run_actions` 回执形状变更是**破坏性**的（`outputs` 顶层键移除）——当前
唯一消费方是判据与 SKILL，同批改完，无第三方受害。

## Alternatives considered

- **否决"schema 里把可选参数全标 required、description 删默认"**（报告给的
  选项 b）：把宿主的默认值缺陷转嫁给每个调用方显式传参，说明书反而更啰嗦，
  且闭包真默认（物理正确值 π/0）仍在那儿无人用——治标且倒退。
- **否决给 `value`/可选参数统一加 type 声明**（坑 1 第一版思路）：宿主对
  `type:number` 可选参数缺省 float(null) 崩（坑 2），声明 type 反而是崩因；
  收编（工具层）+ null 丢弃（适配层）两层各治一半，都不需要宿主改。
- **否决 reset 走"删 History/重置快照"旁路**：History append-only 是硬纪律；
  清零=写一串 None 事件，台面干净与史实完整不冲突。
- **否决把结构化错误做成 MCP `structuredContent`**：`_fn` 返回 dict 会被
  output_model 校验路径接管（我们的回执形状多样、无统一 output schema），
  透传 CallToolResult+JSON 文本最小改动且客户端兼容面最广。
