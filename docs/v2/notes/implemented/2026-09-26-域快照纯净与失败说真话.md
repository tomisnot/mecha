# 域快照纯净 · 失败不许伪装成功 · 接口必须说真话

> **状态**：implemented
> **作者**：mecha v2（第三个项目 n=3 报告的发现 3 与 §9-1 / §9-4 的落地）
> **日期**：2026-09-26

## Problem

1. **审计混进了"配置快照"**：命令审计此前借 `gate.set` 落史 ⇒ 审计键
   （`command.<name>`）**进了域快照的键空间** ⇒ 在 `/config` 视图里变成"契约外的键
   （orphans）"，而快照的"后写覆盖"语义**对审计本来就没有意义**（同名命令只剩最后一次）。
   ⚠ 框架自己的 ADR 当年就承认过这件事（"审计键会进域快照的键空间（前缀隔离）……
   需要'域快照纯净'的读面要按前缀过滤"）——**它知道，只是没做到**。
2. **非标准信封被伪装成成功**：宿主回执既不是失败信封、又没有 `value` 时，
   MCP 投影取 `result.get("value")` = `None` ⇒ 返回 **`"null"`** 且 `is_error` 缺省为假
   ⇒ **模型看到「成功、内容是 null」**，而能力其实说了 `ok: false`。
   ⚠⚠ **报告的措辞比实际轻**：它写"模型只剩'调用失败'、没法自我纠正"，而**真实后果是
   「假成功」——不是信息丢失，是信息反向**（错报成成功比不报更坏：失败会让模型停下来，
   假成功让它以为拿到了东西）。
3. **一个什么都不告诉你的接口，在邀请调用方自己编**：`JobRegistry.cancel(jid) -> None`
   只置位取消标志、**什么都不返回** ⇒ 下游编出了「**取消已登记**」；而对**已经跑完**的
   job 说"已登记/已取消"是**谎话**（AI 会以为它停了）。

## Decision

1. **审计只记史、不改快照**：`Gate` 新增 `record(key, value, actor, reason, call_id)`
   （`set` 的第 4 步**也改调它** ⇒ 只有一份语义）；`_audit` 从 `gate.set` 改成 `gate.record`。
2. **非标准信封响亮失败**：`kind="bad_envelope"`，并把被丢掉的顶层键**截断透传**进消息
   （默认 200 字符 + `…`）——**透传**让模型能自我纠正，**截断**给模型可见面一个体积上界。
3. **`cancel` 返回真话**：`{"job_id", "state_before", "terminal", "cancel_requested"}`；
   终态 ⇒ `cancel_requested=False`。

## Consequences

**换来**：`/config` 里不再出现审计键（域快照纯净）；能力说 `ok:false` 时模型**看到的是失败**、
且能看到被丢掉的顶层键；取消的真实结果**写在返回值里**，下游编不出"已取消"。

**付出 / 放弃**：

- **放弃"审计借写快照顺手留痕"这个便利**：`_audit` 现在要显式拿 `Gate.record`
  （行为上是同一条 History，语义上分开了）。
- **放弃"错误消息尽可能短"**：非标准信封的消息里带一截**原样信封**（有界），
  因为"模型能不能自我纠正"优先级更高。
- **放弃旧的一条判据**（见下）与**旧的一条断言**（见下）。

### 迁移须知（三件，三个项目跟进照此）

1. **`/config` 的输出变了**：`orphans` **不再含审计键**；`n_snapshot_keys` **只数域键**
   （变小）。⚠ 断言过 `n_snapshot_keys` 数值的项目要自查。
2. **宿主不再需要给 `command.*` 前缀开 validator 白名单**：审计**不再经过**宿主 validator
   （这是**减负**，但行为确实变了）。⚠ 反过来说：**别再依赖"审计被 validator 拦下"这个路径**
   ——它不存在了；承诺"审计写不进去要 fail loud"**仍在**，但失败现在只可能来自 History。
3. **自定义 `ToolHost` 返回非标准信封 ⇒ 从"成功 + `null`"变成响亮失败 `bad_envelope`**；
   `cancel` 的返回值从 `None` 变成 dict（**加法**，忽略返回值的调用方不受影响）。

⚠ **两处判据的处置要留痕（都是"别把它改回去"）**：
- `phase6` 旧断言「宿主 validator 拒 `command.*` ⇒ `command_audit_denied`」**退役**——
  但**不是因为它错了，而是因为它守的那个契约不存在了**；"不静默"这条承诺被**改写**成
  新路径上的断言（用一份"拒写审计键"的 History ⇒ 仍 fail loud）。R13：改承诺、不写实现痕迹守卫。
- `phase6` 旧断言「快照里**恰好是** `{command.record_note}`」**翻转**——那描述的是**已知债**，
  不是承诺。

## Alternatives considered

**否决：只在视图层过滤（把 `/config` 的审计键滤掉）。** 它只遮症状：源头（快照）仍被污染，
而将来任何读快照的面都得再记得过滤一次；且"审计属于事件史、不属于域状态"是**数据形态**问题，
不是展示问题。

**否决：给 `ToolFailure.info` 加一个 `envelope` 键来放透传内容。** 那个形状
（`{message, info:{kind,hint,suggest}}`）被判据与消费者钉住；为了一个诊断字段动契约不划算
⇒ 塞进 `message`。

**否决：把非标准信封"猜"成失败并只丢一句通用的"调用失败"。** 那会丢掉"为什么"——
模型没法自我纠正；正是报告描述的那种（偏轻的）后果。

**否决：`cancel` 改为返回 `bool`。** 二值说不清"已完成的 job"与"运行中已请求"的区别
（前者不该说"取消成功"，后者也不该说"失败"）；调用方仍会**自己编**。列在返回值里的
`state_before` + `terminal` + `cancel_requested` 才编不出谎话。
