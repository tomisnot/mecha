# 账的保留策略可注入（`JsonlLogSink(keep=…)`）

> **状态**：implemented
> **作者**：主代理（consumer 触发：tutor 的账是资产，不能被裁）
> **日期**：2026-10-12

## Problem

`mecha/providers/log_local.py` 的模块 docstring 从第一版起就写着"归档位置只有一个常量
（消 D-9）：ARCHIVE_DIR_NAME，且**保留策略可注入**"，但实现里**只有一个模块常量**
`JOURNAL_KEEP = 1000`（2026-10-10 用户裁决："磁盘只存储最近一千条，旧的全删"）。
⇒ **那句话是假的**：任何项目都改不了保留策略，只能被裁。

这本来是"最近发生的事还能查"的**运维**策略，对"配置-运行"软件（EL/ML）成立。但对
**账是资产**的项目不成立——第一个真实 consumer 是 **tutor**（学习档案；本机路径不写——公开仓守卫禁）：

- 它的派生层（知识地图）**由账重放算出**（`History` fold 注入，见
  `2026-10-12-History-fold注入-从配置账到通用域状态史.md`）：旧事件一删，"任何时候可
  从账重算"就变成"算得出来但少一截"；
- 它的 `evidence` 指向历史事件的 `seq`（P4：判断可回推）：删了旧事件，回推指向**不存在**的序号。

⇒ 这不是"另一个默认值"，是**保留策略本身就是项目的领域知识**（原则 3）：框架给机制
（可裁 / 不可裁 + 怎么裁），项目给值。

## Decision

给 `JsonlLogSink.__init__` 加**可选构造参数** `keep: int = JOURNAL_KEEP`：

- **默认一字不变**（出厂仍是 1000 条、仍批量裁、仍**不静默**地打那行）；
- ⭐ **`keep=0`（或负数）＝ 不裁**（沿用 `_trim_if_needed` 里既有的 `keep <= 0 ⇒ return`
  分支，不新增第二条裁剪路径）；
- 该参数**不改变** seam 的形状：`Log` 的三原语（`append`/`since`/`last_seq`）与可选
  `precheck` 一个字没动，`History`、`Gate`、`assemble` 都不需要知道它。

## Consequences

- **换来**：docstring 那句承诺成真；账是资产的项目能自己开账（tutor 用 `keep=0`）；
  "裁剪"从**不可选的出厂行为**变成**声明出来的项目策略**。
- **付出**：`JsonlLogSink` 多一个构造参数 + 一条判据；没有别的调用方需要改。
- **风险与对策**：`keep=0` 会让账**只增不减**（磁盘增长由项目的运维策略兜）。
  ⚠ 它**不该是出厂默认**——判据里有一条 L7 对偶钉"默认仍是 `JOURNAL_KEEP`"。
- **不做**：不做"按体积裁"、"按时间裁"、"归档到别处"——今天没有消费者（R1）。

## Alternatives considered

- **让项目自己写一个 `LogSink`**（复制 `JsonlLogSink` 再删掉裁剪）：否决——那会把
  格式头、相邻边迁移链、**跨进程写租约**、`precheck` 一起复制一遍，四处可以与框架漂移；
  而项目真正不同的只有"留多久"这一个值。
- **改 `JOURNAL_KEEP` 常量为 0（全局不裁）**：否决——用户 2026-10-10 的裁决是给
  **面板/最近动作**那条口径的；把它全局改掉等于用 tutor 的需求覆盖另外两个消费方。
- **给 `History` 加参数（`History(keep=…)`）**：否决——保留策略是**落地点**（sink）的事，
  不是账（语义）的事；放在 `History` 上会让"账的形状"与"盘上留多少"耦合。
- **在项目侧继承 `JsonlLogSink` 覆盖 `_trim_if_needed`**：否决——跨包覆盖**私有**方法
  正是我们禁止的用法（私有面访问只允许出现在框架自己那一处，见 `providers/mcp.py` 的
  同一纪律）；而且它绕开了"这个行为是声明出来的"。
