# 下一步：资产按【入口】分开，让"两半串味"结构上不可能

> **状态**：待办（等 host 骨架落地后做）· 统筹者 2026-10-01 记
> ⚠ 这不是原则文档，是**一件已想清楚的活**，做完即销号。

## ⭐ 实测的依赖分层（**更正**：不是两层，是三层）

统筹者按**真实 import 语句**扫过（第一次用子串匹配把注释里的文件名也算进去了，误报；改用 `from '...'` 后得下表）：

| 层 | 件 | 真实 import |
|---|---|---|
| **纯**（零 import） | `mcp-bridge.ts`、`routes.ts` | —— |
| **+SDK**（不碰 `node:`） | `mcp-session-http.ts`（→ `./mcp-bridge.ts`） | `@modelcontextprotocol/sdk/...` |
| **node-only** | `config.ts`（`node:fs/promises`）、`monitor-url.ts`（`node:fs`/`node:path`/`node:http`） | —— |
| **浏览器安全**（面板侧） | `panel-config.ts`、`monitor-client.ts`、`panel-data.ts`、`panel-view.ts`、`MonitorTabBody.tsx` | 只 import 同层 + `react` |
| **测试** | 5 个 `.test.ts` | `node:test` 等（**不进 bundle**） |

⇒ 所以入口不是"panel / host"两个，而是：
- **`panel`**：浏览器安全面（client 半只许从这里 import）；
- **`host`**：node-only 面（`config.ts` / `monitor-url.ts`，以及将来的 host 骨架）；
- **`bridge`**（或并入 `host`）：`mcp-bridge.ts` + `mcp-session-http.ts` —— **结构上浏览器安全、
  但只被 host 消费**（依赖 MCP SDK，把 SDK 拖进浏览器 bundle 没有意义）。
  ⚠ 归到哪一边是**设计选择**，不是事实问题 ⇒ 定一次、写进 README 的"谁能在浏览器里 import"那节。

## ⭐ 切分的技术前提（统筹者实测，临时副本 + 真 `npm install file:` + 真 `tsc`）

在临时副本上模拟切分（件移入 `panel/` 与 `host/`、`exports` 由通配改为**显式入口**），然后：

| 写法 | 结果 |
|---|---|
| ① 直指文件 + `.ts` 后缀（`@mecha/dsh-panel/panel/routes.ts`）——**项目现在的写法** | ✔ **可解析** |
| ② 走入口名不带后缀（`@mecha/dsh-panel/panel`） | ✔ **可解析** |

⇒ **两种都成立**，切分不强迫项目改写法（`"./panel/*": "./panel/*"` 这类子路径映射同时保留即可）。
消费侧已有的 `preserveSymlinks` / `allowImportingTsExtensions` / `jsx` 三项**EL 都已具备**（实测），所以切分不会新增消费者配置负担。

⚠ 探针里出现过 `react` 解析不到（`TS2307`/`TS2875`）——那是**探针没装 react**（真消费者有），**不是切分问题**。
但它点出一件必须在 `exports`/README 写清的事：**`panel` 入口会拉进 `react` 类型** ⇒
**入口与 peer 依赖的归属要一起写**（`panel` → react；`host` → SDK；两者都不该把对方的 peer 拖进来）。

## 问题

资产 `mecha/dsh-panel/` 现在是**扁平**的：面板件（浏览器安全）、host 件（node-only）、
单测、参数块全在一个目录里，靠 **`package.json` 的三条通配 exports** 暴露。

后果：**"浏览器半不小心 import 了 node-only 的件"是一个可表达的错误状态** ——
所以三家各自养着一条 **`node:` import 闭包守卫**去拦它。

⇒ **那条守卫守的是"两半混在一个目录里、容易串"这个结构缺陷，不是真实行为。**

## 改法

按**入口**分开：

```
@mecha/dsh-panel/panel    ← 浏览器安全面（client 半只许从这里 import）
@mecha/dsh-panel/host     ← node-only 面（host 半用）
```

那么**"把 node-only 的东西带进浏览器 bundle"结构上不可表达**（那半不在这个入口下）
⇒ **三家的 import 闭包守卫随之可以删**（守的对象不存在了）。

## ⭐ 为什么现在是做的时机

- EL 当初**自己评估过这条**（"考虑过用包的 exports 结构消灭它，但那是设计变更 + 要动下游 import 路径"），
  **判定超出当时范围而保留**。
- 现在 **EL/GP 刚刚改完 import**（`./dsh-panel/x.ts` → `@mecha/dsh-panel/x.ts`），
  **正是同一次迁移的自然延伸**；再往后拖，改 import 的成本又要重付一次。
- 与我们刚做完的"A→B→判据退场"闭环同形（§3.6.12）。

## 注意

- ⚠ **入口名与 exports 映射要一次定死**（改名会动三家 import，属"只能做一遍"的事）。
- ⚠ `mcp-sdk-shims.d.ts` 与 `panel-config.ts`（注入点）落在哪一半要想清：
  - 注入点**两半都在用** ⇒ 可能需要**第三个共享入口**，或各自导出（别为省一个入口把两半又混起来）；
  - SDK 垫片是 host 专属（只有 `mcp-session-http.ts` import SDK）⇒ 归 host 面。
- ⚠ 单测放在哪：`.test.ts` 由 `node --test` 跑 ⇒ 属 host 面；但面板单测**测的是浏览器安全的件** ⇒
  按"被它测的件在哪一半"决定，别按"用什么跑"决定。
- ⚠ 改完**必须三家同步**（EL/GP 现在改；ML 未动，等它要用时按新入口做）。
- 验收口径不变：资产自测 + 类型检查全绿；三家 `tsc`/`npm test`/`bundle`（产物含资产符号）全绿。

## 做完这一件，预计能删

- 三家的 **`node:` import 闭包守卫**（EL `re0-panel.test.ts`、GP `panel.test.ts` 里那部分）；
- 资产 `package.json` 里的**通配 exports**（`"./*.ts"` 这类"把未来任何新文件都变成公开面"的写法）
  可收紧为**显式入口** —— 这本身就消灭了"新文件意外成为公开面"这一类错误。
