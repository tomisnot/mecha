## 0. 三十秒版

**这是什么**：一个叫 **mecha** 的框架 + 三个**真实的科研软件**（机器学习工具箱 / 里德堡原子仿真 / 论文抓取评审）。
框架要解决的**唯一新问题**是：

> ⭐ **AI 成了这台软件的【第二个操作者类别】。**

传统软件只有一个操作者（人），于是"门"这种事根本不存在。多了 AI 之后：
它**没有手、看不见界面、只能调接口** ⇒ 软件必须有一个**它能调、也值得调的面**；
它**会写代码、会连错、事后负不了责** ⇒ 行为必须**被可靠监控**。
⇒ **工作模式**：**AI 直接调接口干活，人通过一个面板监控，并随时接管。**

**用户要的交付形态**（一句话）：
```
一个人双击 → 一个 web 页面（唯一入口）→ 勾选要开哪些项目 → 全起来 → 一个 dsh
   → AI 在里面能用【所有开着的】软件
   → 同一个面板上：看谁活了/谁崩了、随时改哪个软件开着、随时「切到手动」接管
   → 改了某个软件的代码：把它滑块关掉再打开 = 新版本生效，dsh 不用重启
```

**现在到哪了**：见 **§3**。粗略说：**启动/交互/写权三层的机制基本通了**，
剩下 **EL/GP 改用框架件**、**无黑框入口**、**ML 门化**（见 §3.3）。

## 2. 用户的诉求（**最终版**；含**被作废**的说法，防误读）

### 2.1 两条**元诉求**（最容易违反，也最要紧）

| # | 诉求 | 原话/含义 |
|---|---|---|
| **M1** | ⭐ **框架要包下"启动"与"生存域"，下游项目只交【数据】** | *"我们为的是建设 mecha 框架，让以后的项目不用在启动、生存域这块费心，架构直接给安排好了"*；*"留给个体项目处理的东西应该越小越好"* |
| **M2** | ⭐ **不要拿"该选哪个"去问用户** | *"具体怎么设计我相信你，不需要问我怎么选择"*。⇒ **架构级问题自己给结论 + 理由，直接汇报**；只有**"他的事实"**（如某项目既有设计的取舍）才问。⚠ 我因为违反这条被批评过："为什么前面要我判断那么多的个别项目的问题？咱们不是在建立统一架构吗？" |

### 2.2 十二条需求（逐条；"现状"见 §3）

| # | 需求 | 关键约束 |
|---|---|---|
| 1 | **从 mecha 启动 ⇒ 永远是 AI 组** | ⛔ **不要任何"模式选择"界面** |
| 2 | **启动前选项目** | 一个 web 页面，列全部已接入项目（带简介），**默认全勾** |
| 3 | **纯 GUI 用户不走 mecha** | 他们自己去项目目录找入口；mecha 不管这条路 |
| 4 | **可反复切"AI / 手动"** | dsh 或面板上有按钮；⭐ **切写权不动进程、不动连接**（面板与 dsh 待命，写被拒、读照常） |
| 5 | ⭐ **多项目 + 一个 dsh** | AI 在**一个** dsh 里能用**所有开着**的软件；dsh 存活期间可临时开关软件 |
| 6 | **0 黑框 + 日志要留** | 子进程 `CREATE_NO_WINDOW`；⚠ **日志收进文件，绝不 DEVNULL** |
| 7 | **状态反馈** | 谁起来了/谁崩了/为什么；⚠ **"读不到"与"确实没有"措辞必须分开** |
| 8 | **生存域** | 支持多种"谁挂谁"（声明式：`restart` 类型 + `strategy` + `significant`/`auto_shutdown`） |
| 9 | **不跨软件共享状态** | 每个软件各自 `data_root` + 各自写租约 |
| 10 | **大改优先，不碰业务核心** | *"不要增量修改的懦夫思想…我们四个仓库还仍是开发状态，怎么大改都行"*；⚠ 但**门/账/监控面/能力面的语义不许动** |
| 11 | ⭐ **面板是长期存在的控制台** | 已注册项目清单**始终不变**；每项旁**开关滑块**，**启动前启动后都能动** |
| 12 | ⭐ **热更新** | 改了某项目代码 ⇒ **把它的滑块关掉再打开 = 新版本**；**dsh 与别家都不重启** |

### 2.3 ⚠ **被作废 / 被修正**的说法（**照这些旧话做就是错的**）

| 旧说法 | 定论 |
|---|---|
| "AI 模式 / GUI 模式 / 人机共用模式"作为**启动模式**，只提供一个就不弹框 | ⛔ **作废** ⇒ **没有模式选择**，改成"**选项目**"（需求 2） |
| `Service.manual: ChildSpec`（人那条腿是**要 spawn 的进程**） | ⛔ **错** ⇒ 它是**软件进程内的一个窗口**（或 Web 面） |
| "**切手动 = 换腿**"（停一条腿 → 起另一条，引 OTP `switch_leg`） | ⛔ **错** ⇒ **切手动 = 只切写权**（`Mode`）；`switch_leg` 已改名 `restart` |
| "**两条腿不能同时活**"（因为抢写租约） | ⛔ **错** ⇒ 写租约是**软件自己的**；腿是**客户端**，**可以同时挂** |
| v1 的 `implemented/2026-09-24-两模式启动-看门人交接与写权自动落位.md` 里的"**AI 物理看不见**"保证 | ⛔ **作废**（已**归档**到 `notes/archived/`）；用户裁决：*"没有参考价值，无视它或者删掉它"* |
| "**框架生成 .bat**" | ⛔ **撤回**（我提过，用户追问后我自己撤了）⇒ 装依赖是**项目知识**；框架只该给**无黑框入口** |
| `--dry-run` 可以有副作用 | ⛔ **不许**（已修：它在起页面之前返回，**零副作用**） |
| GUI 只能判"进程存活"（因为 GUI 不握手） | ⚠ 旧形态下成立；**新形态下窗口在软件进程内** ⇒ 随软件就绪，不需要单独探活 |
| `python -m mecha.launch` | ⛔ **错**（那是模块不是包，**会静默什么都不做**）⇒ 用 **`python -m mecha`** |

### 2.4 ⚠ 一条**用户亲口纠正过的**架构点

> *"状态在软件线程内，AI 和 GUI 都只是读取和影响它"* ·
> *"点击切换 GUI 时滑块不该关"*（滑块 = **软件是否存活**）·
> *"写权还是要硬切换…按下按钮后写权立刻交给 GUI"*

⇒ 这就是**三权分立**：**① 软件存活 ② 客户端连接 ③ 写权**，**三者正交**。
⭐ **切写权不动进程、不动连接、不动状态。**

### 3.5 ⚠ 门化逼出来的**框架**缺陷（已修，值得记）

```
第一次 open_manual_surface ⇒ 5.8 秒 ⇒ 报 control_protocol「协议错」
第二次                     ⇒ 0.2 秒 ⇒ {'ok': True, 'status': 'already-open'}
```

⚠ ⭐ **窗口其实【开成功了】**，只是 5.8s > 客户端**一刀切 3 秒**超时
⇒ 客户端掐了会话、报成"协议错" ⇒ **人看到"失败"，而窗口已经开着**
（本工程最忌的"**看着像失败、其实成了**"）。
⇒ 根因：设计 §7.1.1 把 3 秒的理由写成"软件可能在做个**小事**（记账/**开窗**）"，
⚠ 而**开窗不是小事**（= 起一个 UI，≈小启动）⇒ 已改成**按操作分别定超时**
（查询/切写权 3s，**开窗 60s**）。⚠ 教训：**"一刀切"的常数里往往藏着量级假设**。

### 3.6 ⭐ 一次**设计文档对账**（2026-10-09，用户要求"你得看"）

读完全文（633 行）逐条核，**发现并修掉一处真偏差**：
设计 §7.1.1 已裁定"**不按 `has_gui` 门控**控制端点"，理由是"否则 `has_gui=false`
的项目**再也切不了写权**，而人可能仍想**先把写权收回**"。
✅ 端点确实没门控；⛔ **但框架的控制器把那两件事又焊回去了**
（`write_authority_state` 一见 `has_gui=False` 就 `ok=False`）⇒ **盲区换个门又出现了**。
⇒ 已修（`mecha` `7fa018a`）：**"能不能切"与"有没有手动面"分开报**；
`has_gui=false` 的项目给「**收回写权（冻结）**」⇒ `locked`
（⚠ **不是** `human`：那会贴一个"写权归人"却谁也不能写的**骗人标签**）。
⚠ 教训：**裁决写在"端点"那一层，同一件事会在"控制器"那一层长回来** ——
说"别锁大门"不够，得说"**也别锁里屋的门**"。

### 3.4 ⚠ 已知缺口（**不许假装已通**）

## 4. ⭐ 怎么在这个工程里干活（**纪律；违反会付出代价**）

> 这一节是**血泪**。每条都对应一次真实事故；细节在 `框架准入线.md` 与各判据的 docstring 里。

| # | 纪律 | 背后的真实事故 |
|---|---|---|
| **1** | ⭐ **先改文档再改代码**（文档是权威；"改动本文 = 改设计"） | 设计文档是用户要求写的，就是为了**防止执行歪掉** |
| **2** | ⭐ **每条判据都必须能红**，且**红证要自证"扰动真落上了"** | R7/R16：补丁没打上 ⇒ 你得到的是"判据抓不住这种故障"这个**关于守卫的假结论** |
| **3** | ⭐⭐ **不许用替身去测"真路"** | **本工程最贵的教训**：**29 项零件判据全绿，而那个 web 面板从来起不来**（判据只调 `render_page(stub)`；替身还把 `sites` 写成方法，与真实现不同形 ⇒ 在坏实现上放行）。⇒ 关键路径要**真起进程 + 真 HTTP**（见 `endtoend_selfcheck.py`） |
| **4** | ⭐ **验收必须有一条"端到端目标场景"** | 零件绿 ≠ 机器能开。`endtoend_selfcheck.py` 就是那条；⚠ 它第一次跑就抓到两个真 bug |
| **5** | ⭐ **崩溃必须转成判据失败** | 否则退化实现**抛异常 ⇒ 用例中止 ⇒ "0 条红"** ⇒ 从输出看像"判据没测出问题"（**崩溃冒充失败**）。这个坑**两个不同的施工方各踩过一次** |
| **6** | ⭐ **删东西：全仓搜残留，不是跑门禁** | R14：删 `spill` 时漏了一处构造实参，**是 grep 抓到的、当时门禁是绿的**。⚠ **必须含被 gitignore 的构建产物**（`dsh/lib/*.js`）—— `python` 不读 JS，用 python 写的搜索脚本**看不到它**（实测漏过一处） |
| **7** | **改了 TS 就重建产物** | `dsh` 下 `npm run bundle`；否则源码改了、产物还是旧的 ⇒ AI **运行时会读到旧文案** |
| **8** | **git：只 add 自己改的文件，绝不 `git add -A`** | ⚠ **ML 仓里长期有别的会话的在飞改动**（二十多项）。我在那里踩过坑（把别人的活混进自己的 commit） |
| **9** | **提交信息用 `-F <文件>`，不要用 `-m`** | ⚠ 我踩过 **5 次以上**：消息里的 **反引号被 PowerShell 当命令替换**，`git commit` 报 `invalid path` |
| **10** | ⭐ **`Mode` 是 `str` 枚举** ⇒ 一律 `.value` | `str(Mode.AI)` 给的是 `'Mode.AI'` **不是** `'ai'`。⚠ 这个坑坑过**三个子代理 + 一家判据**；现在有判据 ⑮ 钉着 |
| **11** | **子进程输出落文件，别用 `stdout=PIPE`** | 没人读管道 ⇒ 子进程**日志写满管道、卡在 write** ⇒ 客户端看到"协议错 / TaskGroup 异常"，**现象像"挂死"**（真因是管道满）。**两个施工方独立踩过同一条** |
| **12** | **单实例锁靠"探活接管"，不用 `os.kill(pid,0)`** | Windows 上 `os.kill(pid,0)` 会**把被探的进程杀掉**；而且 pid 会被复用（实测：一个陈旧 pid 文件指向了 OneDrive） |
| **13** | **改了就重跑门禁**（两个 env 都设） | 不设 `MECHA_EL_ROOT`/`MECHA_TSC_ROOT` ⇒ 那些项 **SKIP→FAIL**（严格模式），容易误判成"我改坏了" |

### 沟通纪律

- **用户不喜欢"畏首畏尾"**：*"不要增量修改的懦夫思想，一切以效果和代码优美程度优先"*。
- **但汇报要诚实**：缺口、未验、假绿，**都要主动说**（用户明确要求"如实登记"）。
- **一次只派 1~2 个子代理**（用户要求"同时只有一个/两个"）。
- ⚠ **子代理会中途死**（配额 429 或上下文耗尽）⇒ ① **让它改完就 commit**（半成品躺工作树里最危险）；
  ② **关键路径优先自己动手**（我有两次子代理零产出）；③ 它报"完成"后**你要自己复现门禁/判据**，别采信。
