## 0. 一句话定位

mecha v2 = **人机同门**：一道写入门（Gate）、一份账（History）、
一个能力面（Surface）、一块人类监控面（Monitor）。GUI 和 AI 是两个**平级的操作者
适配器**，都过同一道门；软件不依附任何 harness（dsh 只是 AI 适配器当前挂的宿主）。

---

## 1. 全景：分层与依赖方向

```
                    ┌──────────────── 操作者（会增减，不是主子）────────────────┐
                    │  human adapter → GUI (Qt)        ai adapter → dsh ctx.tools │
                    │        [EL: src/v2_bind + examples/…/bridge.py:V2Bridge]     │
                    │        [EL: examples/…/hub.py:to_mcp（独立进程/headless）]   │
                    └───────────────┬───────────────────────┬────────────────────┘
                                    │ 写（经门）读（快照/史） │
   ┌────────────────────────────────▼───────────────────────▼─────────────────┐
   │  （软件自己的资产，不因操作者而存在；本包不 import dsh）               │
   │    Gate      唯一写入口：authority.gate → validate → 落执行器 → History    │
   │    History   append-only 账，可折叠快照，dsh 消失后独立可用           │
   │    Surface   能力面：Engine(4 必实现) + 注册项(QUERY/HOOK/CUSTOM_TYPE)      │
   │    Monitor   人类监控面：概括层 + 原始层，两层信任、原始赢                 │
   │    Authority 写权模式机（HUMAN/AI/OPEN/LOCKED）+ Channel（actor 由通道钉死）│
   └────────────────────────────────┬───────────────────────────────────────────┘
                                     │ 落盘 / 排队 / 大载荷 / 单次授权
   ┌────────────────────────────────▼───────────────────────────────────────────┐
   │  Provider 层（dsh 的 churn 全关在这里；出厂 = local，dsh 侧显式 opt-in）     │
   │    Log→JsonlLogSink   Jobs→JobRegistry   Artifacts→LocalArtifactStore（核心）│
   │    Approval→LocalApproval   CodeAct→actions-interp   Skills→catalog          │
   └──────────────────────────────────────────────────────────────────────────────┘
```

**依赖铁律**（`mecha/__init__.py` docstring 钉死）：`mecha` 包**不 import dsh**；dsh
只出现在 adapter 与 Provider 的 dsh 侧实现里。领域知识（EL 的物理）也**不进库**——
领域实现住**项目仓**（EL 仓 `mecha_v2/engine.py` 的 `ElEngine`，ADR
`领域参考实现搬回所属项目`），库经它消费领域，`core ↛ mecha` 反向也不成立。

## 2. 软件自己的四件正职

### 2.1 Gate —— 写入门（`mecha/gate.py`）

唯一变更口是 `set`，四步**顺序不可换**：

```
authority.gate(channel.side)   # 1) 此刻这个"侧"能写吗（写权看 side，不看 actor 标签）
validate(key, value)           # 2) 落地前校验；失败则快照一字节不动
self._snapshot[key] = value    # 3) 落到执行器——快照是 Gate 私有，外部拿不到可写引用
history.append(...)            # 4) 落地后才记，带当次 call_id
```

- ⭐ **门在执行器上，不在包装层**（硬纪律 1）：外部无法绕过 `set` 直写快照。
- 另有 `seed()`（装配期灌值，**不经写权门**，走同一落地路径，归因 actor='session'）
  与 `set_batch()`（**原子**批量：先全校验再全落地，坏一键全不写；真实调用方 =
  GUI 存档恢复）。没有 `set_many`——批量只有原子一种形态（ADR `set-batch-原子批量`）。
- `validate` 是**必填注入**（`Callable[[key,value], None]`）；真要"任何值都合法"
  须显式传 `accept_all` 哨兵（审查 P5-2：漏传校验器是静默坏事的温床）。
- `Channel`（同文件）是 frozen dataclass：`actor`（细标签，进史做归因）+ `side`
  （'human'/'ai'，定写权）。side 构造时钉死 ⇒ 请求内容改不了它（硬纪律 4）。

### 2.2 History —— 账（`mecha/history.py`）

- `Event(seq, kind, op, target, after, before, actor, reason, call_id, ts, undoable)`
  是 append-only 的单位；`seq` 单调。
  * `kind ∈ {"state", "history"}`：**`state` = 属于框架那份域状态快照；`history` = 只是记录**。
  * `op` = 动作名（state 事件固定 `"set"`）· `target` = 作用对象（state 事件 = 键名）·
    `after` = 后像 · `before` = 前像（键此前不存在 ⇒ `None`）。
  * ⚠ **旧名 `key` / `value` 已废止，无别名**。
- `fold(events) → snapshot` 是纯函数：**只折 `kind == "state"` 的事件**，按 `target` 取最后
  一个 `after`（后写覆盖先写）；启动时按日志重建。
- **两条写路径分工**（含糊的 `append` 已拆开）：
  * `gate.set` / `seed` / `set_batch` ⇒ **写 state**（改快照 + 记史），并带 `before`；
  * `gate.record` ⇒ **写 history**（只记史、**不碰快照**）—— 命令面审计走这条
    （`op = "command.<命令名>"`）。
  * 走这条路径的还有：**CodeAct 的编排日志**（`op = "codeact.<i>"`）与
    **项目自己的域动作**（项目把库里发生的动作也记进同一本账）。
  * ⇒ **"绕过"的定义**：两条都没走，才叫绕过。
- ⚠ **`command.` 前缀已降级**：现在它**只是 `op` 的命名习惯**，**不承担任何判定作用**；
  判定一律看 `kind`（旧注释里"前缀隔离"那套说法已不成立）。
- `subscribe(cb) → disposer` 供 GUI 面板实时刷新（回调抛错被吞，坏订阅者不拖垮写口）。
  `close()` 释放落盘 sink 的写租约。
- 落盘经注入的 `LogSink`（见 §4.1），本模块不自己碰文件系统：`assemble(log_sink=…)`
  **可以不传**（出厂默认本机 JSONL），**也可以传自己的实现**；
  `since(seq, *, actor=None, op=None, limit=None)` 可按人 / 按动作筛。
- ⭐ **账的落地点可以由项目提供**：框架给的是**账的形状与不变量** + 一个**可替换的落地点**；
  项目可以把账写进**自己的库**——关键是**与域状态变更同事务**。
  ⇒ 判据：**能不能做到"状态变更与记账同事务"**；能 ⇒ 就不需要第二本账。（已有一个项目这么做。）
- **它是软件自己的资产，与操作者无关**——人操作时也写。与 dsh 的"操作者行为史"是
  两份不同资产，靠每次 `set` 带的 `call_id` **互引**（"AI 做了什么"↔"域变成了什么"）。
- 落盘经注入的 `LogSink`（见 §4.1），本模块不自己碰文件系统。

### 2.3 Surface —— 能力面（`mecha/surface.py`）

一个 `Engine` seam = **Definition（我们拥有）+ Provider（项目引擎）+ Consumer（ops/tools 管道）**。

- `Engine` 是 ABC，**必实现只有 4 个**：`schema()` / `run(spec, context)` /
  `summary()` / `estimate(spec)`（`FRAMEWORK_CALLS` 常量钉死名单，Phase 2 判据用
  `__abstractmethods__` 对拍）。
- 其余全是**注册项**：`register(EntryKind, name, fn, called_by=…) → disposer`。
  `EntryKind ∈ {QUERY, HOOK, CUSTOM_TYPE}`。
- ⭐ **铁律**（硬纪律 3）：框架真会调的才配进 Definition；框架不调、只做分派目标的
  必须是注册项。`query(op_name, **args)` 分派 QUERY 项，**不经写权门**（只读动词不该被
  判不可逆——这是 D-4 的解法）。
- ops 管道逐条校验回执契约：`run` 缺 `schema()['run_output_required']` 里的键即抛；
  `estimate` 缺 `est_sec` 即抛（D7 契约先行，隐式键变显式）。
- `fire_hooks(point, payload)`：固定挂点调 HOOK 项，挂点不存在 = 空列表（不是错）。

### 2.4 Monitor —— 人类监控面（`mecha/monitor.py`）

与前三件**并列的第一层**，不是附属。**只读，无任何写回路径**（写回 ADR 已否决）。

- `read() → MonitorView(summary, raw_snapshot, disputed, dispute_reason)`。
- 两层信任：**概括层**（注入的 `summarizer` 纯函数产出，给人看、可能错）+
  **原始层**（`fold(events)`，权威）。
- 唯一硬纪律（硬纪律 5）：概括里凡是 `Claim(value, target=原始键)` 的复述，其值与
  原始折叠比对——target 不存在或值不等 ⇒ **原始赢**、整份读数 `disputed=True`。
  人话键名要能对账，必须显式写 `Claim(target=…)`；不做"键名等价推断"（那是假绿温床）。

## 3. Authority + Channel —— 写权模式机（`mecha/authority.py`）

dsh 的 approval **刻意窄**（one-shot、无 allow-always、无 grant store），所以"human
模式持续一段时间的写权互斥"必须自管：本模块只持 **mode 状态机**。

- `Mode ∈ {HUMAN, AI, OPEN, LOCKED}`；`DEFAULT_MODE = LOCKED`（`nothing ships enabled` 用在
  写权上——出厂谁都别想写，人类通道显式开闸）。`OPEN` **两侧都能写**（2026-09-26 加）：
  给"人机低冲突"的项目去掉那道多余的闸，⚠ 代价是**后写覆盖**（无先到先得、无 CAS）。
- `gate(side)`：LOCKED 拒一切（`authority_locked`）；`OPEN` 放行任何合法 side；
  其余模式 `side != mode.value` 拒（`authority_mode_mismatch`）。**写权看 side，不看 actor 标签。**
- `switch_mode(new_mode, side)`：**只有 human 侧能切**——AI 不能把自己解锁
  （`authority_switch_denied`）。参数是 `side` 不是 actor 标签（审查 2.4：把"同名不同义"
  从命名上根除）。
- mode 是**进程内协调态，不落 History**（它不是域状态；崩溃后回出厂 mode，
  丢失的只是协调态，域状态史本身完整可查——authority.py docstring 已声明）。
- `watch(callback) → disposer`：mode 不落史 ⇒ 史订阅收不到它，UI 要实时反映
  "此刻谁能写"订这里。**真变化才通知**（同模式重复切幂等不通知）、回调在调用线程
  同步执行（Qt 编组归宿主）、坏订阅者抛错被吞（与 `History.subscribe` 同纪律）。
  消费方：EL 的 dsh 监控面板（:8767 只读轮询）与看门人进程交接（ADR
  `两模式启动-看门人交接与写权自动落位`；取代旧 `写权模式UI面` 的消费面，
  watch 缝机制本身不变）。

> actor 标签（'gui'/'mcp'/'codeact'）→ side 的映射**在适配器层做**（EL 仓
> `mecha_v2/bridge.py:_ACTOR_CHANNEL`），库不认宿主词（硬纪律 4 的另一半）。

## 4. Provider 层 —— dsh 的 churn 全关在这里（`mecha/providers/`）

**出厂默认全是 local**（独立部署开箱即用）；dsh 侧 Provider 是显式 opt-in（§5.3）。
每个 seam 的 Definition 我们拥有，Provider 可整层替换（硬纪律 6）。

### 4.1 Log（`providers/log_local.py`）
`JsonlLogSink` 实现 `history.LogSink` 四原语（`append/since/last_seq/subscribe`）。
- 路径来自注入的 `DataLayout`（库不猜目录名，治 D-6）；每行一个 JSON，带 `format:"vN"` 头。
- 构造即抢**跨进程写租约**（见 §6.2）；`exclusive=False` 留给纯读投影绕过租约。
- 读取：格式头 + 相邻边迁移链（§6.1）+ 崩溃尾半行跳过（修复归消费方）。
- `subscribe` 未实现（当前无订阅消费者，n=0 不建机制——D-11 教训）。

### 4.2 Jobs（`providers/jobs.py`）
`JobRegistry`：一次长计算是一个 job（可轮询 `status()` / 可取消 `cancel()` / 断线可找回）。
- **单一注册表实例**（消 D-21：v1 双 JobRunner 会把另一实例在跑的 job 误翻 interrupted）。
- local 实现是单 worker 线程；真实并发度归项目引擎自己的线程模型（EL 的 SQLite 认线程
  是它的约束，不焊进库）。dsh 侧注册到 `ctx.jobs`。

### 4.3 Artifacts（`mecha/artifacts.py`，核心）——**唯一**的"落盘 + 不透明定位符"

> 原 `providers/spill.py`（`LocalSpillStore`：体积阈值 + `$<id>`）已于 2026-09-25
> 收口轮**删除**——它零消费者，且**连发起方都没有**（框架内没有一处会问
> `should_spill` 再 `put`；两下游零代码）。"该不该截断落盘"是**调用方的策略**，
> 不是 seam 的职责。

`LocalArtifactStore`：宿主把**自己的产物**（任意 bytes）交给它，拿回不透明定位符
`artifact-<n>`，此后 `retrieve` / `describe` / `exists`。**不含阈值语义**（不判断
"该不该存"）、**不解释** `kind`/`name`、不暴露真实路径；元数据 sidecar 含
`size`/`sha256`/`created_at`。判据 `checks/phase8_artifact_contract_selfcheck.py`。

### 4.4 Approval（`providers/approval.py`）
`LocalApproval`：单次授权决策，**fail closed**——无决策器一律拒绝，决策器抛错也按拒绝。
- 只管"此刻能不能"，不管"要不要持续放行"（后者归 §3 Authority 的 mode 机，两机制正交）。
- `require()` 拒绝时抛 `GateDenied`，可塞进 Gate 的 validate 做"每次写都问人"。

### 4.5 CodeAct（`providers/codeact.py`）
受限动作解释器：动作是**结构化 dict**（`Action(op, args)`），**不 eval 任意代码**
（库只编排自家工具，任意代码是宿主 code-runtime 的权力）。
- 动作集 = 内置 `run/summary/estimate/schema` + Surface 已注册 QUERY 项。
- 每步产 `SubCallLog`，run 结束一次性落 History（可归因）。不追 dsh 的 PTC（ADR）。

### 4.6 Skills（`providers/skills.py`）
`SkillCatalog`：目录**从 Surface 的 QUERY 注册项生成**，不手抄（消 16→18 漂移，L8）。
- 每项带 `modelInvocable`/`userInvocable` 两正向布尔（dsh 四象限）；`declare()` 未注册名直接报错。

## 5. 形状 + 可见性

### 5.1 tools（`mecha/tools.py`）—— 让工具"像自己的手脚"
- `define_tool(name, description, parameters, output_schema, execute, …)` **构造即校验**：
  坏形状注册不出来。命名守 `check_tool_name`：snake_case 动词_宾语、禁 `get_`/`list_`
  前缀（枚举是投影不是工具）、禁 `mecha_` 项目前缀。
- `description` 只含任务概念，禁实现词汇（`banned_words`）——模型可见文本逐字钉住（L4）。
- `output.schema.required` 显式声明回执必填键（消 D-15 的隐式契约）。
- `ToolRegistry.schemas()` 是**白名单投影**：只有 `name/description/parameters` 进模型
  请求，`execute/output/render` 绝不泄漏（消 D-25，不维护手写 TOOL_NAMES）。
- `execute(name, args)` 归一化失败为 `ToolFailure {message, info}`，并校验回执必填键。
- `CURRENT_CALL_ID`（contextvar）：MCP 层在调用前置本次请求 id，`gate.set` 读它写进
  History ⇒ AI 侧行为史与域史互引（审查 2.7）。

### 5.2 toolhost（`mecha/toolhost.py`）—— 工具定义与宿主传输分开
- **定义面**归 `tools.py`（形状/命名/回执契约/白名单投影的唯一来源）；**传输面**
  归 `ToolHost`（Protocol，不是 ABC）：`declare` 把声明交给宿主、`call` 执行一次
  调用并归一化失败、`schemas` 给模型可见投影、`teardown` 可逆释放（幂等）。
- `LocalToolHost(registry)` 是出厂 Provider（`declare` 只校验、`call` 委托
  `registry.execute`、`schemas` 委托投影、`teardown` 空操作）；**dsh/MCP 是另一个
  Provider**（注册进 `ctx.tools` 的实现住适配器侧，本包不 import 它，未接，见 ADR）。
- `declare` 对白名单外字段**拒收**（不静默过滤）：手工拼 schema 是"可调用对象
  差点进模型请求"的唯一来路，静默丢弃会让它不留痕（选择与理由在 ADR）。
- 宿主边界的失败全部结构化：句柄抛错 → `toolhost_error`；回执畸形（非映射 /
  `is_error` 非布尔 / 错误支形状坏 / 成功支缺 `value`/`content`）→ `bad_host_result`。
- 装配：`Software.toolhost`（`registry` 就是 `Software.tools`，非第二张表）+
  角色 `provider.toolhost`（def）/ `provider.toolhost.local`（provider, `in-process`）。
  判据 `checks/phase9_toolhost_selfcheck.py`。

### 5.3 可见性分级：**不存在**（`visibility.py` 已删除）

- v1 的 `autonomy.classify()` 靠硬编码 op 名表判"危险级"，把新项目自己发明的只读动词
  误判成危险 ⇒ 接进去就废（D-4 最高危）。v2 的解法是**取消分级**。
- 2026-09-23 曾落地 `ToolRestriction` / `VisibilityPolicy` 作为"可见性过滤"（不是危险
  分级）。但它**建好未接线**：`Surface.register` 从不调 `declare`、`schemas()` 不消费、
  全仓无第二处引用 ⇒ **零消费者**，于 2026-09-25 收口轮**删除**（ADR 两层传输上提的
  收口表第 4 行）。
- 现在的承诺改由**行为**保证：**注册即可见、可执行，没有第二份"可见性真值"**。
  判据 `checks/phase3_provider_selfcheck.py` 的
  `check_registration_is_the_only_visibility`（自有动词 `register` 即可分派 ＋ Surface
  上没有可见性/分级 API ＋ `schemas()` 不做任何过滤）。
- **升格触发**：出现"同一宿主要对不同 actor 暴露不同工具集"的真实需求时再加（届时写 ADR）。
- 也**不绑 permission-presets**（太新，3 周自我推翻过；ADR 绑定-permission-presets）。

## 6. 持久性与单写者（两件"地基级"机制）

### 6.1 格式版本化（`mecha/format_version.py`）
- `FORMAT_VERSION`（当前 =1）+ `JOURNAL_FILENAME`；只有结构性变化才 bump。
- `MigrationChain`：迁移**只声明相邻边** `vN→vN+1`，读取时组合；缺边拒绝、未来版本拒绝、
  `corpus 拒识清单` 按 (来源头,目标版本) 精确匹配故意不支持的转换。released-format 政策：
  已发布磁盘产物永不移动/覆盖/删除。

### 6.2 跨进程写租约（`mecha/write_lease.py`）
- History 的 `seq` 由宿主内存分配后落盘 ⇒ **两个宿主同指一个数据目录**会产出重复 seq，
  破坏按 seq 寻址与 call_id 互引。
- 一把 OS 级独占文件锁（Windows `msvcrt` / POSIX `fcntl`，**模块级导入**防解释器关闭期
  `__del__` 惰性 import 抛 ImportError 污染 stderr）钉住数据目录；第二个宿主构造即抛
  `writer_lease_held`（fail-closed）。锁随 fd 关闭自动释放，进程崩溃即解锁。
- 只"拒第二个宿主"，未实现"降级为只读客户"（并存部署各用各目录即可，n=1 不建）。

## 7. 装配单点 —— 唯一具名装配入口（`mecha/assembly.py`）

**L6/D-33：机制建好必须装配接上，判据从这里取数；真实部署路径也走这里**（否则

  （`role ∈ {definition, provider, consumer}`）。角色表集中在此、单点可读。

### 7.1 capability map —— 分类是生成的，不是手写的

## 8. 错误词汇 —— 可教学错误是 LLM 的 UI（`mecha/errors.py`）

- `MechaError(message, kind, hint, suggest)`：message 说清事实、hint 说清下一步、
  suggest 给替代操作。构造即校验（坏错误比没错误更坏，L3）。
- `to_failure()` 对齐 dsh `ToolFailure {message, info}`；`teaching_text()` 是模型可见文本。
- 子类：`GateDenied`（写入门拒）、`UnknownKey`（键不在声明面，`typo()` 用 difflib 生
  did_you_mean——v1 头号教学特征，L4）、`UnknownOp`、`InvalidSpec`。
- `kind` 是开放字符串（项目可扩），不维护封闭枚举表（L8）。

## 9. 操作者适配器：人机同门（EL 消费配置）

库是领域无关的；下面是 EL（Rb-87 里德堡仿真软件）如何把两个操作者接到**同一道门**。
**本节全部件住 EL 项目仓**（`mecha_v2` 包 + `src/v2_bind.py` + `launcher.py`），
不在框架仓——"个性知识归所属项目"（ADR `领域参考实现搬回所属项目`）。

### 9.1 GUI 适配器 —— V2Bridge（EL 仓 `mecha_v2/bridge.py`）
- `V2Bridge.for_gui(el_root, data_root)`：GUI 进程内装配（`ElEngine(own_thread=False)`，
  cache 建在主线程）；`for_shared(...)`：GUI 与后台 MCP 线程共享一个 Gate（cache 经
  `CacheProxy` 汇流到专属引擎线程，ARC SQLite 认线程，EL B-1①）。
- 接口对齐 v1 的 AppBridge（Binder 零改动复用）：`read/write/write_many/subscribe/
  can_write/mode/switch_mode/save/load/cache/session/activity`。actor→通道映射表在
  这层（`_ACTOR_CHANNEL`），库不认 'gui'/'mcp' 宿主词。
- `el_summarizer(events)`：领域人话概括（Monitor 概括层），复述键值一律用
  `Claim(value, target=原始键)` 显式指向，可对账（审查 P3-b）。
- `ElOps`（同文件）：GUI 运行路径 `prepare`（主线程 build_run 碰 cache）/
  `execute`（worker 线程 evolve_run 纯数值）/ `load_artifact`——线程模型照 EL 定论。

### 9.2 AI 适配器 —— MCP（EL 仓 `mecha_v2/hub.py` + `tools.py`）
- `build_tool_registry(engine, gate, surface, authority, channel, jobs)`：把能力包成
  dsh 原生形态的工具（`set_config`/`run_sim`/`set_drive`/`submit_job`/`run_actions`/…；
  清单以 `schemas()` 为准）。工具经 Gate 写、经 Surface 跑——**没有一条路径绕过写入门**。
- `to_mcp(stack)`：把 `ToolRegistry` 投影成 mcp 2.x `MCPServer`（streamable-http）。
- **两种部署形态别混**：① 同进程共门（`V2Bridge.serve_mcp`，EL 默认——GUI 进程内
  MCP 线程与 GUI 共一 Gate，一份真值一份史）；② 独立进程 headless（`hub.py:main`，
  无 GUI 时跑在 A 机、AI 从 B 机连，写权威落 `--data-dir`）。两者**不共享内存快照**，
  各写各的 journal（写租约各保各目录单写者，但互不见对方的写）。

### 9.3 EL 接线层（EL 仓 `src/v2_bind.py` + `launcher.py`）

两模式收拢（ADR `两模式启动-看门人交接与写权自动落位`）：用户面只有 **AI / GUI** 一个选择，
写权随模式自动落位；三态 Authority 机制（含 LOCKED、watch 缝）原样保留在库内。

- `make_v2_bridge(el_root, *, start_services)`：装配 `V2Bridge.for_shared`。
  - **GUI 模式**（`start_services=False`）：不起 MCP 端点、不起监控端点——纯本地软件，
    AI 物理看不见；写权恒 HUMAN。
  - **AI 模式**（`start_services=True`，`run_authority` 用）：起 MCP 服务器线程 + 起
    **只读监控端点**（`start_monitor_endpoint`：`GET /status` +
    `GET /activity?since_seq=` + `GET /history`/`GET /config`（v1 驾驶舱两页形状，
    ADR `驾驶舱呈现回归`），绑回环、加 CORS 供 dsh 页轮询）。写权自动落 AI
    （`switch_mode(AI, actor='human')`——
    看门人代理人启动意图开闸，非 AI 自解锁）。
  - 旧的"人工控制端点"（POST switch_mode/write + token + 网页控制台）已退役：控制权切换
    改由看门人编排进程交接，端点降级为只读监控面。
- `load_artifact` / `gc_report`（gc 未接线的如实报告垫片，见 D-9）。
- **看门人 `launcher.py`**（常驻，无窗口）：弹窗选一次模式 → spawn 进程组 → 轮询
  `.mode-request`（任一进程写它 = 切换意图）→ 交接（terminate 当前组 → **等进程真退出**
  释放写租约 → 按新模式 spawn → 删请求文件）。GUI 侧入口 = 文件菜单「切换至 AI 模式」；
  dsh 侧入口 = 「→ GUI」按钮经 `/re0-gui` command 让 host 写 `.mode-request`。
- `app_entry.py`：`--gui` 走 `run_gui`（MainWindow，`start_services=False`）、
  `--authority` 走 `run_authority`（headless，不起窗口）。GUI 模式不再挂 AI 监控侧边栏
  （`monitor_panel.py` 退役——两模式下都无存在场景）。

## 10. 运行时数据流（把前面串起来）

**人改一个参数（GUI 模式）**：
```
spinbox.valueChanged → Binder._write → bridge.write('field.B_gauss', 21.7, actor='gui')
  → V2Bridge._channel_for('gui') = Channel('gui','human')
  → Gate.set: authority.gate('human') ✓ → validate → snapshot[key]=21.7 → History.append(actor='gui')
  → History 通知订阅者 → Binder._on_event（actor 以 gui 开头 → 跳过自刷新，防回环）
```

**写权落位（两模式，无手动切换）**：
```
启动选 GUI：make_v2_bridge(start_services=False) → 出厂 HUMAN，恒人写（AI 端点根本没起）
启动选 AI ：run_authority → make_v2_bridge(start_services=True) → 出厂 HUMAN
            → bridge.switch_mode('ai', actor='human')  ← 看门人代理人意图开闸
            → authority 只认 side：actor='human'→side='human' 可切；AI 通道改不了 mode（§3）
```

**AI 改一个参数（AI 模式，MCP）**：
```
dsh → mcp__re0-mecha__set_config(key,value) → hub._register 的 _fn
  → CURRENT_CALL_ID.set(request_id) → tools.execute('set_config', …)
  → gate.set(Channel('ai','ai'), …): 此刻 ai 模式 → authority.gate('ai') ✓ → actor='ai' 进史
```

**跑一次演化（人机同路径）**：
```
GUI: ops.prepare(主线程 build_run 碰 cache) → RunWorker(QThread).execute(worker evolve_run)
     → 大数组落 artifact（load_artifact 取回绘图，I3 不内联）
AI:  run_sim → Surface.run(snapshot) → ElEngine.run（引擎线程）→ build→check→evolve→summary
     回执校验 run_output_required（ok/method）；长任务走 submit_job→JobRegistry→read_job 轮询
```

**人监控 AI（AI 模式，dsh 右侧栏「机甲监控」面板 = v1 驾驶舱两页呈现）**：
```
dsh MonitorTabBody → 每 3s fetch :8767/history + :8767/config
  飞行记录仪页：{events:[{seq,actor,target,before,after,reason}]}（before 由全史
    fold 重建）→ 逐行折叠（概括=seq/actor/reason，展开=before→after 全量）
  配置态页：{groups:{族:[{prefix,rows}]}}（schema join 现值+最后归因）→
    族→前缀二级分层树（显示名去前缀）
  徽标位：写权模式（human 绿 / ai 紫 / locked 黄）
  （原始记录说了算：面板显示的就是 History 里的 actor 归因，非 AI 自述——§2.4）
```

**模式切换（进程交接，经文件握手）**：
```
GUI 菜单「切换至 AI」/ dsh「→ GUI」按钮（/re0-gui command）
  → 写 <EL根>/.mode-request（内容 ai/gui）
  → 看门人轮询到 → terminate 当前进程组 → 等真退出（写租约释放）
  → 按新模式 spawn → 删 .mode-request（journal 同数据根 append-only + 单写者，状态不断档）
```

## 12. 已知边界与推迟（诚实声明，勿读成"已全有"）

- **gc（数据回收）未接**：v2 无 `mecha.gc`，EL 回收页走 `gc_report` 如实报告"未接线"
  （D-9 保留策略等第二项目）。
- **undo 未接**：History append-only，撤销按"反向 set 记一条新事件"实现（ADR
  `EL能力面取舍`），挂起至接 GUI 撤销按钮（真实调用方出现）。
- **Log.subscribe / 断线找回 / 异步审批 / scope 分层**：均 n=0/n=1 不预建，触发条件写进
  各模块 `Known Limitations` 与遗留登记（D-11/D-22 等）。
- **分类内容（哪些 seam 拆包）推迟到 n=2**（§5.4）：现在只交付"机制"（角色声明 +
  生成 map + 汇总就绪），不预先划界。
- **门禁全绿 ≠ UX 判据达成**：没有任何自动判据能证伪"没读文档的 AI 第一次就做对"
  （总纲 §7 Phase 4 终极验收）——那需要真模型跑快照 + 真人活体验收。
