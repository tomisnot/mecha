# 框架准入线（R 系列 · 改动纪律）

> **这份文档管什么**：**改动本框架时必须过的线。**
> ⚠ **第一次接入本框架**（而不是改它）请先读 [`../接入指南.md`](../接入指南.md)——
> 那是**顺序表 + 每步验收 + 边界**；本文是**纪律**，不是接入流程。
> **与 [`架构总纲.md`](架构总纲.md) §3 的 L1–L9 分工**：
> - **L 系列 = 设计原则** —— 框架**是什么**（一道写入门、追加史、可教学错误、领域凝练…），来源是"从 v1 保留什么"。
> - **R 系列 = 改动纪律** —— 怎么**改**它（加东西、搬东西、删东西、写守卫、定契约各有各的线），来源是 **2026-09 那次跨三仓提取工程**的实战。
> - 两者**不重复**：L 系列不写改动流程，R 系列不重复设计原则。重叠处见 §4 对照表。
>
> **R 系列的每一条都是"踩过才写下的"** —— 每条都附**真实实例**。没有实例的规则不许进这份文档（同 L 系列标准）。
>
> **外部参照**：DSH 的同题实践见 [`外部实践研究/DSH-对本轮悬案的答案.md`](../外部实践研究/DSH-对本轮悬案的答案.md)；本文 §7 给出逐条对应。
>
> **工具与测量层面的坑**（都实际踩过，写法是"症状 → 怎么认出 → 正确做法"）：[`操作陷阱.md`](操作陷阱.md)。**本文只留规则**，操作细节与互链在那边（一个事实一个家）。

|---|---|---|---|---|

## 4. 写守卫时

> 这一组是 R 系列里最厚的一组，因为**"假绿"是本工程付出代价最多的一类缺陷**（L3 已立为设计原则，R 系列给出**怎么防**）。

| # | 规则 | 由来 | 怎么守 | DSH 对应 |
|---|---|---|---|---|
| **R7** | **每条新守卫必须配「能红」的证据**（致死性/灵敏度判据）。只绿不红的守卫等于没有。**「能红」不得依赖概率性手段。** | 40 轮压测在**缺陷实现**上实测有约 **20% 概率假绿**（压 10 次未修实现得 `0,0,1,1,4,6,7,9,12,13` /40，两次为 0）⇒ 必须构造**确定性判别子**，并证明**两个方向**：「不修则红」且「修好则绿」。红证可用**运行时 patch**（不改仓内文件） | 每条守卫配一条"能红"证据；红证要能在评审时重放 | ✅ **L7 已引**：DSH 有 snapshot corpus + 拒识清单；其 Known Limitations 也明写"哪个机制不强制" |
| **R8** | **判「相同 / 通过」的守卫，必须自证「数据真的到了」。** 逐字节相同与零失败在**退化输入**下同样成立：空表 vs 空表、离线 vs 离线、0 轮 vs 0 轮。**比较型/汇总型守卫必须同时断言"非退化"**（非空、非离线、轮数 > 0、样本数 > 0），并把该证据打出来。 | EL 第 2 段**自己抓到**的假绿：新旧实现面板 HTML 逐字节相同，但**两边都是"权威离线"**（fetch 替身递归调自己）。修正后每次渲染自证 `离线=false 事件行=5 配置族=3` | 比较型守卫必须打印非退化证据 | — |
| **R9** | **守卫的期望值必须取自「被检对象之外」的独立信源。** 从被检对象自身推导期望 ⇒ 它一坏、期望跟着变 ⇒ 守卫**自动跳过**该样本 ⇒ **空洞的绿**。 | EL 的 `default` 守卫第一版：期望取自**被检声明** ⇒ 漏声明时 `defaulted` 变小 ⇒ 该组**跳过那个参数** ⇒ **分区红而行为组绿**；且"spy 看到的值 == 真默认"在真实现上**恒被跳过**（垫片的行为是**把键丢掉**，不是填默认值）⇒ **双向空洞**。修法：期望改取**闭包签名**；边界观测量改成"键必须不存在 / 必须存在且为 None" | 守卫的期望值必须能在被检对象改坏时**保持不变** | — |
| **R11** | **观测量必须能变。** 一个**恒定值**的观测量不携带信息——它**区分不了通过与失败**，等于没有。 | EL 自查：判据里 `getattr(res, "isError", False)` —— 字段真名是 `is_error`（`isError` 只是序列化别名）⇒ 该项**恒为假** | 每个观测量两方向都验（坏状态读得到、好状态读得到） | — |
| **R12** | **新守卫拦下你的测试替身时，先怀疑替身失真，不要削弱守卫。** 替身若不**如实**反映它托管的状态，它就是一个"恒定的观测量"（R11 同族）——在真实现上放行、在坏实现上也放行。 | 加"工具宿主绑表核对"守卫时，它第一次跑就拦下了**自己的** `_SpyHost`（其 `schemas()` **恒回空表**——**那正是"绑错表"的形状**）。处置：**不削弱守卫**，把替身改成如实报出托管的注册表 | 守卫拦下替身 ⇒ 先修替身 | — |
| **R15** | **守卫必须自证「它声称要检查的每一个成员都真的被检查了」。** **枚举 ≠ 处理**：一个 `except: continue` 就能把成员静默丢掉，而守卫照旧全绿。枚举型守卫必须**打印「枚举了多少、真处理了多少、跳过了哪些」**。 | EL 自查：新的「机器事实只在一处」守卫加了 G 组后，**红证据第一次没能让它红**。 根因：`git ls-files` 默认对**非 ASCII 路径加引号转义**（`"docs/\344\272\244..."`）⇒ `_read()` 对所有中文名文档抛错 ⇒ 被 `except: continue` **静默跳过** ⇒ **守卫对本仓大多数文档失明，却一直绿着**。 修法：① `-c core.quotepath=false`；② 新增 **R8 自证**「tracked 238 个 / 读到 238 个 / 读不到 `[]`」，把「静默跳过」变成可见。 <br>⚠ 与 R8 的关系：**R8 管「数据真的到了吗」（值层面），R15 管「成员真的都被处理了吗」（集合层面）**；而**发现它靠的是 R7**（红证据没红 ⇒ 说明守卫本身有问题）。 |
> **三条空洞的分工**（不是规则，是索引）：**R8** 管「两边都退化所以相同」；**R9** 管「守卫会不会跳过该报的样本」；**R11** 管「这个观测量本身有没有信息」；**R15** 管「成员有没有被静默丢掉」。

## 5. 定契约时

| # | 规则 | 由来 | 怎么守 | DSH 对应 |
|---|---|---|---|---|
| **R5** | **无 `type` 声明 ⇒ 注解 `Any`**（不是 `str`）。**`defaulted` 的唯一权威来源是声明里的 `default` 键**，三分法：有非 None default → 丢显式 null；有 None default → 保留 null；**无 default 键 → 视同 None，保留 null**。实现**不得**读包装后的闭包签名。 | `_py_type` 跨项目冲突：缺 `type` 映射成 `str` 会让一方**拒收所有非字符串值**；单看任一项目都发现不了 | 跨项目参数类型与默认值的**唯一权威**是声明，不是实现 | — |
| **R6** | **MCP 工具声明不得带 `output_schema`。** 客户端不得假设 `MCPServer.call_tool()` 可进程内直调。⚠ **本条是权宜条款，不是终点** —— 我们的输出声明是**假的**（由 `return_annotation=str` 派生、谎称返回 `{result: string}`），**允诺一个假契约比不允诺更坏**。**升格路径**：当包装不再伪造签名、声明能为真时，**改为"如实声明 + 框架渲染 + 框架校验"**。 | 源码 grep `outputSchema` **零命中**、协议层却有；且两家下游**用的不是同一个 MCP 客户端**（一家内置、一家自建桥）——这解释了为何"只对一家成立" | 声明不得撒谎；撒谎时要显式记为权宜并写明升格路径 | ✅ **DSH 是终点形态**：`defineTool` 带 canonical output declaration，`execute` **只返回声明的 JSON 值**，SDK 负责 **advertised output-schema validation**，且明确"不接受替代物、不绕过校验" |

## 6. 文档纪律（D 系列）

> **与 R 系列划界**：**R 管"改代码时怎么证明你做对了"；D 管"写文档时怎么让它不撒谎"。**
> 两者**不同族**，**不许混编号**（D 不并进 R1–R15）。D 系列同样**只收踩过的**，格式同 R。
>
> **为什么单立一族**：本工程付出代价最多的一类缺陷是"**文档与实物不符、而无人拦**"
> （A6 的手抄清单漏列、接管报告给未裁决草案上位权威、README 里 `spill` 多躺一轮、
> EL 那份 448 行判据在手抄表上打补丁）。R 系列管得住"代码改动"，管不住这些。

| # | 规则 | 由来（真实实例） | 怎么守 | DSH 对应 |
|---|---|---|---|---|
| **D1** | **分层"一个事实一个家"**：每个事实**只在一个层**陈述；别处**链接**过去，**不复述**。 | **正例就是本仓现成的**：R 系列（改动纪律）在本文件、工具与测量层面的坑在 [`操作陷阱.md`](操作陷阱.md)、两者**互链不重复**——2026-09-25 收尾轮亲手分的。**反例也是现成的**：① `mecha/__init__.py` 的 `__all__` 漏列模块（A6，最后靠**删掉名单**才解决）；② `spill` 删除后仍在 `README.md` 的仓库地图里躺了**一整轮**（R14 实例，M 自己的漏检） | 写之前先问"**这件事的家在哪一层**"；已在他处写过 ⇒ **只留链接** | ✅ `docs/AGENTS.md:17`「Each fact has one home: the tier whose job it is; elsewhere, link there.」；分层表 `:19-33` |
| **D2** | **AI 可见面是一等公民契约**：每个能力/工具回答**三问**——**模型看到什么**（含被拒时看到什么）/ **token 影响** / **KV cache 影响**；答案要**能对账**（"模型看到什么"是可验证行为）。 | 本轮 `outputSchema` 事故：**源码 grep 零命中、wire 上却有**，且两家下游用的**不是同一个 MCP 客户端** ⇒ "源码写了什么"与"模型看到什么"根本不是一回事（与 R3 同源） | 答案是**生成物 + 新鲜度门禁（`--check`）**守，不是手写散文。⚠ **今天不要求任何项目补写**（无消费者，R1）；**升格触发见本节末** | ✅ `packages/core/tools/README.md:158-221`；模板见 [`外部实践研究/DSH-对本轮悬案的答案.md`](../外部实践研究/DSH-对本轮悬案的答案.md) §3.2 |

| **D4** | **manifest 登记制**：凡"**对外声明的名单**"（`__all__`、能力表、工具清单、表面登记表）都属"**可以撒谎而无人拦**"的一类。两条出路：**(a) 删掉名单**，让单一来源（注册表 / 文件系统 / 生成器）说话；**(b) 非要留就登记**——让"**漏登记**"本身成为违规。 | `__all__` 漏列（A6 的处置是 (a)：整份删除）；EL 的 `SURFACES` 表是 (b) 的成熟实例（漏登记 / 死登记**都算违规**）。DSH 原话：**"`verify-type-equiv` 只能抓'粘贴件漂了'，抓不到'从未被记录的新类型'"** | 加任何"名单"之前先答"**它的单一来源是什么**"；答不出 ⇒ 删名单 | ✅ 答案文档 §3.5；`docs/AGENTS.md:39-46` |

**升格触发（写在此处，不许沉默推迟）**：**D2 的生成物化**（把三问做成"生成 + 新鲜度门禁"）等 **n=3** —— 出现**第三个有 AI 可见面、且需要一个守卫的项目**时再做（届时可拿 EL 的 `checks/ai_surface_selfcheck.py` 当规格）。
**今天不做**，理由是 2026-09-25 的实测：**ML 全仓 0 份 `SKILL.md`、0 套机制**（唯一相关缺陷是一个**悬空指针**，一行可修），**mecha 自己也是 0 份 `SKILL.md`** ⇒ 按 R1 无消费者；EL 有真实需求但**已自建并跑通**（其判据 448 行里通用部分仅约 90–130 行，抽取要动一处正在工作的守卫 + 新增零消费者库模块）。

## 8. 这份文档自己的准入线

R 系列**只收有真实实例的规则**（与 L 系列同标准）。一条规则要进来，必须能回答：

1. **它拦下过一次真实的事故吗？**（附实例与代价）
2. **它和已有的 L 或 R 重复吗？** 重复就**并进去**，不新立编号。
3. **它守得住吗？** —— 说得清"怎么守"（判据、流程、或评审时能重放的证据）。说不清 ⇒ 那是感想，不是纪律。
