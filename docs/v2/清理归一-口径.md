# 清理归一 · 口径与逐处判定规则

> **依据**：用户裁决 *"不要留旧架构残留的代码、注释、说明等"*（2026-10-08）
> **状态**：施工用口径（本文件是**判定标准**，不是设计）

## 0. 什么叫"旧架构"

**旧模型**（已被 [三层架构](软件-交互-写权-三层架构.md) 取代）由这几件构成 ——
⭐ **凡把其中任何一件当【现状】来陈述的代码/注释/文档/判据，都是残留**：

| # | 旧模型的东西 | 现在的定论 |
|---|---|---|
| 1 | **每个项目自己的看门人**（`launcher.py`）：弹窗选模式、编排进程交接 | 编排**整块归框架**（`python -m mecha`）；项目**不再自己编排** |
| 2 | **两模式**（AI 模式 / GUI 模式）+ **进程交接** | 三权分立：存活 / 连接 / 写权**正交**；切写权**不动进程** |
| 3 | **握手文件** `.mode-request`（切换意图）/ `.mode-state`（当前模式） | 控制端点 `.control-port`；⚠ `.mode-state` 本来就是**无代码读者的装饰品** |
| 4 | **"人那条腿"是一个 `ChildSpec` 子进程**（`Service.manual`） | 人那条腿是**软件进程内的窗口**（或 Web 面），**不是子进程** |
| 5 | **`switch_leg` 换腿语义**（停一条腿 → 起另一条腿） | 切写权**不动进程**；`switch_leg` 已改成 `restart` |
| 6 | **换腿 / 看门人 / 两模式** 这些词 | 词本身可出现在**换代说明**里（见 §2），**不许用来描述现状** |

## 1. 逐处判定的三类处置

| 类 | 判据 | 处置 |
|---|---|---|
| **A · 删** | 该代码/文件**只为旧模型存在**（删了没有别的消费者） | 删掉；⚠ **按 R13**：先写清"它守的是什么承诺"，把它改写成**行为级判据**（不是写"这东西不存在"的守卫） |
| **B · 改** | 它描述的**关系仍然成立**，只是**名字/机制换了** | 改写成新机制的名字；⚠ **不许只删词**（那会留下一句没头没尾的话） |
| **C · 留** | ⭐ **诚实的换代说明 / 历史记录**：讲"我们推翻了什么、为什么" | **留** —— ⚠ 用户自己说过：*"架构换代时最贵的不是'新的是什么'，而是'旧文哪一部分还在生效'"* |

### ⚠ C 类的具体白名单（**别把这三类当残留删掉**）

| 允许出现旧词的地方 | 为什么 |
|---|---|
| 架构文档 / 施工方案里的 **"本文替代了什么"**、"作废的旧裁决" | ⭐ 那是**换代记录**，删了没人知道旧路走不通 |
| `docs/v2/notes/archived/` 与 `implemented/` 里的 ADR | 决策史是资产 |
| 判据里 **"旧名/旧字段已不存在"** 的**反向断言**（如 `assert not hasattr(svc, "manual")`） | ⭐ 那正是 **R13 要的**行为级守卫 |
| 代码里 **"⚠ 曾经有 X，已删，因为……"** 的注释（**简短**） | 防止下一个人"好心加回来"；⚠ 但**不许长篇复述旧机制** |

## 2. ⚠ 两条硬要求（今天都踩过）

1. ⭐ **残留搜索必须覆盖被 gitignore 的构建产物**（`dsh/lib/*.js`、`.map`）——
   `python` 不读 JS ⇒ **用 python 写的搜索脚本看不到它**；⚠ **改了源码要重建**（本仓：`npm run bundle`）。
   **判据是"搜到 0 命中"，不是"门禁绿了"**（R14）。
2. ⭐ **删了机制要跑一次"真装配"**：光跑门禁不够 ——
   门禁只覆盖它**走到**的路径（R10：EL 迁移后 `--fast` 30/30 全绿，而 AI 工具面**列得出来、调不动**）。

## 3. 判定"该删还是该改"的一个实用问法

> ⭐ **"如果我把这段删掉，读者会缺什么信息？"**
> - 什么都不缺 ⇒ **删**（纯旧模型残留）；
> - 缺"这段关系为什么还在" ⇒ **改**（B 类）；
> - 缺"为什么不能走老路" ⇒ **留**（C 类）。
