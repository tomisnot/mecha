## 1. 用户流程（**先看这个：所有设计都是从它推出来的**）

### 1.1 唯一入口

**双击一个 `.bat`** ⇒ **打开一个浏览器页面**（不是黑框、不是原生小窗）。

```
┌──────────────────────────────────────────────┐
│  AI 机甲 · 选择要接入的项目                    │
├──────────────────────────────────────────────┤
│  ☑  Machine Learning                        │
│     传统机器学习 / 神经网络 / 自动调参          │
│     上次：3 天前 · 健康                        │
│  ☑  Energy Level                            │
│     能级仿真 · 量子轨迹 · EIT 扫描              │
│     上次：11 天前 · ⚠ 端口文件残留（会自动清）   │
│  ☐  Get Paper                               │
│     论文抓取 / 评审 / 简报                      │
│     ⚠ 依赖 npm，上次启动失败（点这里看原因）      │
├──────────────────────────────────────────────┤
│              [ 全部启用 ]  [ 启动 ▸ ]          │
└──────────────────────────────────────────────┘
```

- **默认全勾**；
- 每项显示：项目**自己声明的简介** + **上次状态/健康**（从 `runtime/site.json` 读，**不猜**）；
- 不勾的项目**不起**，其工具**不出现在 AI 面前**。

### 1.2 点「启动 ▸」后：**同一页原地**变成状态页

```
  ● aggregator   起好      端口 …
  ● svc:ML       起好      pid 1234  ← 探活通过
  ● svc:EL       启动中 …  已等 6.2s
  ○ dsh          等待中（依赖上面两个）
```

⇒ 全部就绪后**自动打开 dsh**（AI 界面）。

### 1.3 「切到手动操作」（dsh 里的按钮）

```
dsh 里点 [切到手动操作]
  → supervisor: 停该项目【AI 那条腿】→ 等真退出（写租约随之释放）
  → supervisor: 起该项目的【human adapter】（GUI，同一 data_root）
  → 状态页写清这次交接
切回同理（反向）
```

⚠ **"状态连续"的正解是"账不断"，不是"两个进程共享内存"** —— 见 §3 铁律 4 与 §6.1。

### 1.4 收尾

关掉 dsh ⇒ supervisor **逆序**停（dsh → aggregator → 各软件），每个都**等真退出**，
清掉自己写的端口/状态文件 ⇒ 状态页显示"已收尾"，窗口自己关。
也可以在状态页点 **[收尾退出]**。

### 1.5 ⭐ 纯 GUI 用户**不走这条路**

想完全人工操作 ⇒ **去项目目录自己找入口**，**mecha 不参与**。
⚠ 这不是遗漏，是刻意设计：**从 mecha 启动就一定是 AI 组**（见 §3 铁律 5）。

## 2. 架构

### 2.1 进程形态

```
supervisor（框架）
  ├─ aggregator     MCP 服务端；挂给 dsh 的【唯一】端点
  ├─ svc:ML / EL / GP   各自一条脊椎（各自的 MCP 服务端）
  └─ dsh            连 aggregator；工具名 mcp__<聚合端点名>__<软件>__<工具>
```

### 2.2 职责分工（**这条定了，后面全是细节**）

| | 归 supervisor | 归 aggregator |
|---|---|---|
| 管 | **进程的生老病死** | **工具表的内容** |
| 人看 | 谁起了/谁崩了/为什么 | 哪些软件开着、各有哪些工具 |
| AI 能碰 | ✗（**AI 不许启停进程**） | ✔ `query_software` / `open_software` / `close_software` |

### 2.2.1 ⚠ 聚合后的**工具命名律**（**别自己起名，框架有明文律**）

聚合端点把各后端的工具暴露给模型时，名字必须过**框架自己的** `mecha/tools.py::check_tool_name`：

```
^[a-z][a-z0-9]*(_[a-z0-9]+)*$      ← 只收小写 + 单下划线
禁 get_ / list_                    ← "视图/枚举不是工具，是 schema 的投影"
禁项目前缀（mecha_）                ← 库自身包名不许写进模型可见文本
```

⇒ 因此：

| 项 | 规则 | ⚠ 为什么 |
|---|---|---|
| 暴露名 | ⭐ **`<svc_id.lower()>_<tool>`**（**小写 + 单下划线**） | 我最初草稿写的 `<svc_id>__<tool>`（双下划线）**不匹配**命名律（`ML__x` 既大写又连续下划线） |
| 元工具 | ⭐ **`query_software` / `open_software` / `close_software`** | 我最初写的 `mecha_list_software` **两处违规**（`mecha_` 前缀 + `list_` 枚举动词）；官方惯例是 `list_*` ⇒ `query_*` |
| `Service.id` | `^[A-Za-z][A-Za-z0-9_-]*$`（**允许大写**，如 `ML`） | 但暴露名会**小写化** ⇒ ⭐ **两个只差大小写的 id 会静默撞名**，故 `Site.validate` **大小写不敏感地查重**（已加守卫） |

⚠ **不许为了让名字通过而放宽守卫** —— 那是"改判据让它变绿"（L3/R13）。
**名字不合规就改名字**，不是改守卫。

### 2.3 项目只提供**声明**（内容），框架提供**机制**

项目侧只写一份 `mecha_site.py`（约 25 行）：

```python
SITE = Site(name="…", services=(Service(id="ML", brief="…", argv=(…), cwd=…,
                                         ready=ReadySpec(…), data_root=…,
                                         manual=ChildSpec(…)),),
            dsh=DSHSpec(…), strategy=Strategy(…))
```

**框架不管项目内部**；项目不管进程编排。**这条边界不许模糊。**

## 3. 铁律（**每条都带根因，别绕过**）

### 铁律 1 · 0 个黑框，但日志必须留

**做法**：`CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP`；
stdout/stderr **重定向到 `runtime/logs/<id>.log`**（带滚动上限）。**绝不 `DEVNULL`**。

**根因（实测）**：
- EL `launcher.py:42` 与 ML `launcher.py:100` **逐字相同**的
  `_FLAGS = getattr(subprocess, "CREATE_NEW_CONSOLE", 0)` ⇒ **每个子进程一个新黑框**
  （AI 模式 4 个）；
- ML `dashboard.py:100-102` 是全仓**唯一真静默**的子进程（`DEVNULL`）⇒ **诊断黑洞**。

⚠ **顺序不能反**：先"把输出收进文件"，**才可以**加"不开窗"。
反了就是把诊断信息一起扔掉。

### 铁律 2 · 就绪必须是**真探活**，不许查文件

**做法**：spawn 前记 `(port, mtime)` 快照 → 必须"**文件消失过，或内容/mtime 变了**"
→ 再**真探活**（HTTP 或 TCP）→ 超时**响亮失败**。

**根因（实测）**：EL `launcher.py:68-78` 的 `_wait_mcp_port` **只要文件存在且非空**即通过。
实测现场：EL 的 `.mcp-port` = **264.5 小时前**的残留、**没人在听**，**会被判成就绪**（假绿）；
且超时后**照常起 dsh**。

### 铁律 3 · 停必须"先礼后兵 + 等真退出 + **内核保证的整组死**"

**做法**：
- **Windows：Job Object + `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`** ✔（已落地，`supervise.py:182-252`）
- **POSIX：进程组 `killpg`**（⚠ 见下方局限）
- 先礼（`terminate`）→ 等 `stop_timeout` → 兵（关 job / `killpg`）

**根因（实测）**：只 terminate 直系子进程会留下**持端口的孤儿** ——
ML `launcher.py:529-551` 的注释记着实测：`dsh.CMD → cmd.exe → node`，
只 terminate 父进程会**留下一个仍持有 3081 的 node**，后果是"端口莫名被占"、
`pick_dsh_port()` 一路漂到 3082/3083。

#### ⚠⚠ 执行中发现的第二层坑（**下一个人最容易踩**）

**`taskkill /T /F` 治不了这个根因。** 它是**沿父 PID 走子树**的：
"先礼"一旦成功、父进程就没了，**它就找不到那棵树**了 ⇒ 实测**孙进程照样活着占端口**。

⇒ 正确机制是 **Job Object**：把子进程塞进一个 job，job 上带
`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，**关掉 job 句柄时由内核杀光 job 里剩下的所有进程**
—— 这是**机制保证**，不是"趁父还在赶紧 taskkill"那种竞态。

⚠ **POSIX 侧没有 job 的等价物**（现用进程组）。若子进程**自建会话（detached）**，
孙进程仍会逃逸。**如实登记为已知局限，不假装覆盖** ——
AI 组不产生该形态；若将来要覆盖，那是 cgroup 级别的事，单独立项。

### 铁律 4 · ⭐ 同一数据根**只能一个写宿主** ⇒ **两条腿不能同时活**

**做法**：换腿 = `Supervisor.switch_leg(stop_id, start)`：
**停一条腿 → 等真退出（写租约随之释放）→ 起另一条腿**。
⚠ **顺序不能反**（反了抢不到租约 ⇒ `writer_lease_held`）。

**根因（框架硬约束）**：
```
mecha/write_lease.py:8-10   OS 级独占文件锁（msvcrt.locking / fcntl.flock）
                            抢不到 ⇒ MechaError(kind="writer_lease_held")（fail-closed）
```

⚠ **我在设计讨论中一度写成"两条腿同时接在同一条脊椎上"，那是错的。**
框架文档 §4.5 说的"两条腿**平级**"是"**都接同一组门/账/能力面**"，**不是"同时活着"**。

⇒ ⭐ **"切手动" = 交出写权 + 换一条腿；账 / 数据根 / 领域状态一个都不动。**
这就是框架自己那句话的落地：**账是软件的；当前状态是它的折叠。**

### 铁律 5 · 从 mecha 启动**永远是 AI 组**

**做法**：**没有"启动模式选择"这回事**。项目选择在 §1.1 那个页面上勾。

**根因（用户裁决）**：
> "根本不需要让用户选择模式，如果从 mecha 框架启动，那肯定是带着 AI。"
> "如果用户想开 GUI 模式，那就跟 mecha 完全没关系，自己去项目目录找入口文件。"

⇒ 因此**禁止**再出现：`choose_mode()`、`.mode-request`、`.mode-state`、
"两模式整组重启交接"协议。

### 铁律 6 · 实际端口必须**回读**，不许写预选值

**根因（实测）**：ML `.ml-mecha-runtime.json` 里的 `dsh_port` 写的是 `pick_dsh_port()`
的**预选值**，不是 dsh 实际绑的端口 ⇒ **状态文件自己写错值**。
另：`pick_dsh_port` 是"先 bind 试探再释放"，存在 **TOCTOU 窗口**。

⇒ `state()["port"]` **一律是回读值**；`DSHSpec.port_preference` 只表达**偏好**。

### 铁律 7 · 状态只有一个真值来源

`runtime/site.json` + 状态页 + 聚合端点的工具表，**三处对同一事实必须一致**
（关掉一个 svc 后三处**同时**变）。**不许有第二份真值。**

### 铁律 8 · "消失了"与"读不到"必须不同措辞

启动失败的文案 ≠ 读不到状态的文案。**不许都写"未知"。**

## 4. 冻结的接口（2026-10-08 定；三家按此集成）

### 4.1 `mecha/supervise.py`

```python
RestartPolicy = Literal["permanent", "transient", "temporary"]

@dataclass(frozen=True)
class ReadySpec:
    port_file: str | None = None     # 相对项目根的端口文件名（如 ".mcp-port"）；None=不看文件
    probe: str | None = None         # 形如 "http://127.0.0.1:{port}/health"；{port} 由回读填入
    tcp: bool = False
    timeout_s: float = 90.0
    #: 探活可接受的状态码；None ⇒ **默认只接受 2xx**。
    #: ⭐ `()` ⇒ **任何 HTTP 响应（含 4xx）都算"在听"**。为什么需要它见下方注释。
    ok_codes: tuple[int, ...] | None = None
```

⚠ **`ok_codes` 的由来（实测，不是设想）**：
某项目的 MCP 端点在 `GET /mcp` 上回 **406（不是 2xx）**，而该端点上**没有**任何回 2xx 的
只读路由（`/summary` / `/runs` 等属于**监控端点**，是**另一个端口**）。
而"就绪"要表达的是"**这个服务真的在听**"—— 项目原有的判据正是
"**有 HTTP 响应即算在听（4xx 也是响应）**"，理由是"TCP 连得上还不够，同端口可能是别的东西"。
⇒ 若框架只认 2xx，**该项目会永远判不就绪**。
⇒ 故 `ReadySpec` 必须能表达"**任意 HTTP 响应即算在听**"，且**默认仍是严格的 2xx**。

⚠ **使用纪律**：`ok_codes=()` **只用于"有响应即证明服务在听"** 的场景；
不许用它来掩盖"端点返回错误码"的真故障。**默认严格，放宽要写理由**。

```python
@dataclass(frozen=True)
class ChildSpec:
    id: str                          # 全局唯一；同时是日志名 runtime/logs/<id>.log
    argv: tuple[str, ...]
    cwd: Path
    env: Mapping[str, str] = field(default_factory=dict)   # 与父环境合并（后者覆盖）
    ready: ReadySpec | None = None
    restart: RestartPolicy = "permanent"
    significant: bool = False        # 供 aggregator / auto_shutdown 用
    stop_timeout: float = 8.0

class Supervisor:
    def __init__(self, *, log_dir: Path, state_path: Path | None = None) -> None: ...
    def start(self, child: ChildSpec) -> None
    def stop(self, child_id: str) -> None          # 停进程、保留 spec（= OTP terminate_child）
    def shutdown(self) -> None                     # 逆序收尾全部（幂等）
    def set_active(self, child_ids: Sequence[str]) -> None
    def clean_stale(self, stale: Sequence[StaleItem]) -> list[str]   # ⭐ 返回"实际清掉了什么"
    def switch_leg(self, *, stop_id: str, start: ChildSpec,
                   timeout: float = ...) -> dict  # ⭐ 铁律 4：停→等真退出→起
    def state(self) -> dict
```

`state()["children"][i]` 固定键：
```python
{"id", "pid", "state",        # stopped|starting|ready|running|unhealthy|exited
 "port",                      # ⭐ 永远回读值
 "ready_evidence",            # 人可读："port_file 变化 + HTTP 200" / "超时(90s)未就绪：…"
 "last_error", "restarts", "exit_code", "log",
 "holds_write_lease"}         # ⭐ 现在是谁在写（换腿时人最需要知道）
```

### 4.2 `mecha/site.py`

```python
ServiceId = str   # 全局唯一，将来也是工具前缀；[A-Za-z][A-Za-z0-9_-]*

@dataclass(frozen=True)
class Service:
    id: ServiceId
    brief: str                                # 选择页上一句话
    argv: tuple[str, ...]
    cwd: Path
    ready: ReadySpec
    data_root: Path                           # ⭐ 该软件自己的写租约根（不跨软件共享）
    manual: ChildSpec | None = None           # ⭐ "接手动" = 本项目的 human adapter（§4.5 既有词）
    default_on: bool = True
    env: Mapping[str, str] = field(default_factory=dict)
    log_id: str | None = None

@dataclass(frozen=True)
class DSHSpec:
    command: tuple[str, ...]
    cwd: Path
    patches: tuple[Path, ...] = ()
    port_preference: int = 3081               # ⚠ 只表达偏好；实际端口回读
    port_tries: int = 10
    plugin_artifacts: tuple[Path, ...] = ()   # 就绪前置检查；不存在 ⇒ 响亮失败
    env: Mapping[str, str] = field(default_factory=dict)
    ready: ReadySpec | None = None

class StrategyMode(str, Enum):        # 与 OTP 同名（不造新词）
    ONE_FOR_ONE = "one_for_one"; REST_FOR_ONE = "rest_for_one"; ONE_FOR_ALL = "one_for_all"
class AutoShutdown(str, Enum):
    NEVER = "never"; ANY_SIGNIFICANT = "any_significant"; ALL_SIGNIFICANT = "all_significant"

@dataclass(frozen=True)
class Strategy:
    mode: StrategyMode = StrategyMode.ONE_FOR_ONE
    max_restarts: int = 5
    period_s: float = 60.0
    auto_shutdown: AutoShutdown = AutoShutdown.NEVER

@dataclass(frozen=True)
class Site:
    name: str
    services: tuple[Service, ...]
    dsh: DSHSpec
    strategy: Strategy = Strategy()
```

**声明发现点**：文件名 **`mecha_site.py`**、暴露模块级 **`SITE: Site`**。
搜索根 = 环境变量 **`MECHA_SITE_ROOTS`**（`os.pathsep` 分隔）优先，缺省用启动时 CWD；
根下递归找（跳过 `.git`/`node_modules`/隐藏目录）。
⚠ **零声明 ⇒ 响亮失败**（不静默起个空站）。

## 5. 三家现状与改造难度（**2026-10-08 实测**）

### 5.1 对照（全部实测）

| | **EL** | **GP** | **ML** |
|---|---|---|---|
| 可双击入口 | ✖ **没有**（`build.bat` 已删） | ✔ `开始.bat:52` | ✔ `启动 ML Toolbox.bat:14` |
| 怎么选模式 | Qt 弹窗 | ✖ **硬编码 `ai`** | Qt 弹窗 + 控制台手势 |
| 黑框 | **3 个**（AI） | ✔ **1 个** | ⚠ **4 个**（AI） |
| 就绪判据 | ✖ 只看文件非空 | ✔ TCP 探活 | ✔ 双条件 |
| 杀进程树 | ✖ 只 terminate | —— | ⚠ 有 `taskkill /T /F`，但**它治不了根因**（见铁律 3 第二层坑） |

### 5.2 ⭐ 两个 launcher 是**同一套骨架的两次复制**

`start_group` / `choose_mode`(`_choose_mode`) / `await_authority`(`_wait_mcp_port`) /
`pick_dsh_port`(`_pick_dsh_port`) / `_spawn_dsh` / `_terminate_group` / `await_exit` /
`read_request`(`_read_request`) / `clear_request` / `write_state` —— **函数名几乎一一对应**。

⇒ **"统一启动"不是从零设计，是把存在两遍的骨架收进框架一次。**

### 5.3 "接手动"的难度**三家不同档**（关键，别一刀切）

| | 结构 | 难度 |
|---|---|---|
| **GP** | **单进程一条脊椎**：`cli.py:291` `build_stack(...)` + `:293 make_host(...)`；人写走 `web.py:77 _gated` | ⭐ **小**（换界面焦点） |
| **EL** | **两套入口一条脊椎**：`v2_bind.py` `V2Bridge.for_shared(...)` 是**同一构造点**，GUI 只是 `start_services=False`（`app_entry.py:109`） | ⭐ **小**（换装配路径） |
| **ML** | ⚠ **"一个执行器、两个调用者"**：GUI 写 = 直调 `runner.run_one`（`ui/worker.py:48`），**不经 Session、不经门**；两条路**共用同一执行器与同一落盘**（`api.Session.run:207` 也是 `runner.run_one`） | ⚠ **中**（缺一层，见下） |

⚠ **ML 的准确形状**（一位施工方用证据纠正过我的初判）
**不是"两套状态"，而是缺"执行器之上那一层"**。所以按**两段**走：

| 段 | 内容 | 应用层改动 |
|---|---|---|
| **第一段** | 一个**项目内的窗口进程**读**同一份 `runs/`** | ⭐ **0 改动**（今天就已经技术连续：两边都从同一个 `runs/` 渲染） |
| **第二段** | 才谈"会话连续"（经通道） | 6 个写点 / 3 个文件 + 一个 GUI 侧会话模块 |

⇒ ⭐ **第一段就是 human adapter 的最小可用形态**，**它今天就能交付**。

### 5.3.1 ⭐ human adapter 的 `ready` 判据（**ML 侧实测结论，其他家请照此自查**）

⚠ **ML 的 GUI 今天没有任何可探的就绪信号**。证据：在 `ml_toolbox/ui/**` / `app.py` /
`app_entry.py` 里 grep `QLocalServer|QLocalSocket|socket|http.server|SingleApplication`
**零命中**；GUI 的最后一步就是 `win.show(); app.exec_()`（`app.py:61-63`）——
**不监听、不写端口文件、不握手**。

⇒ 今天**诚实**能做的只有两档：

| 档 | 含义 | 判不了什么 |
|---|---|---|
| **(a) 进程存活** | `poll() is None` ⇒ 没当场崩 | 窗口是否可用 |
| **(b) 存活 + 超时** | 例如 15–20 s 内没退出 ⇒ 判"起来了" | 同上（Qt 可能在缺字体/插件/无显示时**窗口空白而不崩**） |

⇒ ⚠ **建议采用 (b)，并在 `ChildSpec` 注释里写明"只能判存活"**。
**不许**编一个假判据（"窗口存在"这种猜）。
对照：ML 的面板用的是**真探活**（`panel_web` 读端口文件 + 打 `/health`）—— GUI 恰恰没有这条。

⭐ **若要真 `ready`**：需要 GUI 侧加**一条显式握手**（最小：`win.show()` 之后写一个
`<root>/.gui-ready` 标记文件；或起一个 `QLocalServer`），并配一条判据
（照"未注入即抛"那种"**显式即响亮**"的姿势）。**这是代码改动**，
按 §7.3 的"第二段"处理，**不要塞进步骤 1**。

### 5.4 ML 侧三条硬约束（各自独立、指向同一结论）

1. ⚠ `ml_mecha` **不许 import `ml_toolbox.ui`**（AST + 运行时双判据在守）
   ⇒ **门与 GUI 只能在框架进程里通过"一条通道"相遇**，不能在 ML 侧 import 成一体；
2. ⚠ `engine._resolve_data_path` 的 `dataset_roots` 是 **fail-closed 白名单**，GUI 完全没有
   ⇒ 强行同门要么**给 GUI 开洞**（破坏"AI 不许读任意路径"），要么**给 GUI 加白名单**（行为变更）；
3. ⚠ **写租约只允许一个写宿主**（铁律 4）⇒ "AI 在跑时人同时在 GUI 写"**今天就是被禁止的**。

⇒ 三条合起来：**ML 的"切手动"不是接线问题，是缺一层。**

### 5.5 ⚠ ML 接入的具体事实（**照做，否则会出现"切了但看着是空的"**）

#### (1) `runs/` 同源**成立，但有一个环境变量开关**

```python
ml_toolbox/core/runs.py:19-21   resolve_dir(): os.environ.get("ML_TOOLBOX_RUNS") or <包根>/runs
ml_toolbox/core/persistence.py:21   RUNS_DIR = _runs.resolve_dir("ML_TOOLBOX_RUNS")
```

⇒ **默认两侧同源**（都在仓根 `runs/`）。
⚠ 但它**可被环境变量改到别处** ⇒ 若 supervisor 给两条腿的 `env` 不一致（或哪条腿没继承），
**GUI 会看到另一份 `runs/`** —— **这正是"切了但看着是空的/老的"那类假象。**

⇒ ⭐ **`ML_TOOLBOX_RUNS` 必须由 supervisor 在两腿的 `env` 里显式钉死到同一仓根，不许留给继承。**

#### (2) `PYTHONIOENCODING=utf-8` 注入 ⇒ **归 supervisor**

理由：它是**所有子进程**的共同需求（ML 权威 / GUI / EL / GP 都一样），且必须在 `spawn` 那一层
（`launcher._spawn` 的注释写明"`setdefault`，调用方显式给的优先"）。
放进 `mecha_site.py` 只会把同一纪律在每个项目复制一遍。

⚠ **别把这当成小事删掉**：它防的是"子进程 stdout 被重定向 ⇒ 退回 cp936 ⇒
网络代码一句 `print("⚠…")` 让整个后台任务崩"（**用户实测、本机可复现**）。
`app_entry.py` 里的 reconfigure 只是**兜底**，不是替代。

#### (3) `dataset_roots` 白名单 ⇒ **内容归 `mecha_site.py`，传参归 supervisor**

依据：
- 它是**宿主策略**（`engine._resolve_data_path:871-900`：无 roots ⇒ **连 csv 都拒，fail closed**）
  ⇒ 属项目内容，**不能进框架**；
- 今天的来源是 `dataset_roots.txt`（**人写的白名单文件**，实测存在、被 `.gitignore` 忽略、
  内容是本机绝对路径），由 `launcher._dataset_roots_argv` 解析
  （含 `utf-8-sig`/`gbk` 兜底、`expandvars`、相对路径按文件所在目录 resolve、
  **每个路径带一次旗标**——注释里记着"曾经不带旗标 ⇒ 权威 exit=2"的坑）。

⇒ **裁决：保留 `dataset_roots.txt` 作为人写的白名单**，**解析搬到 `mecha_site.py`**
（这正好是那 25 行的天然内容），由它把"服务要怎么被起"交给 supervisor。

#### (4) 聚合端点的 overlay 归属

MCP 基地址今天**只**写在 `launcher.dsh_patch_text` 生成的**入库外** overlay 里
（`- insert:` + `@deepseek-ai/dsh-mcp-client` + `url: http://127.0.0.1:<port>/mcp`
→ 落 `runtime/dsh-ml-mcp.patch.yml`）。
⇒ ⭐ **换架构后这份由框架生成**（指向聚合端点），**ML 侧不承接**。

⚠ 但 `dsh/cordis.project.patch.yml`（入库）**不必改**——它是 **dsh 自身 webserver 的
端口隔离层**（`host`/`port` → `!!js ctx.webStartup.*`），**不含 MCP 端点**。
两处要留意：① 其中的 `?? 3080` 是**回落** ⇒ **若框架不再传 `--port`，dsh 会绑 3080（撞官方实例）**；
② `dsh/cordis.patch.yml` 的注释里写死 `--port 3081`（纯注释）。

#### (5) ML 侧硬编码假设清单（迁移时**逐条核对，别丢**）

| 位置 | 内容 | 处置 |
|---|---|---|
| `launcher.py`（`toolCallTimeoutMs`） | **600000 ms** | ⚠ **迁走时别丢** —— 默认 60 s 会让**长训练"假失败"** |
| `launcher.py`（overlay 里） | serverName `mltoolbox`、`/mcp` 路径 | 随 overlay 归框架，**名字要保持稳定**（工具前缀有它） |
| `dsh/cordis.project.patch.yml` | `127.0.0.1`、`?? 3080` 回落 | 见 (4) |
| `dsh/src/ml-panel-params.ts` | `portFile: '.ml-monitor-port'` | ⚠ 必须与 `ml_mecha/runtime.py` 的常量**一致**（**跨语言单一事实**） |

### 5.6 ⚠ 全局陷阱：**环境变量不一致 ⇒ 两腿看不同的世界**

ML 的 `runs/` 是最典型的例子（见 §5.5(1)），但**任何"路径来自环境变量"的东西都有这个风险**
（数据根、端口文件目录、日志目录）。

⇒ ⭐ **设计要求**：supervisor 起两条腿时，**凡影响"看到哪份状态"的环境变量，
必须由 supervisor 显式钉死**，不许依赖继承或项目默认值。
⚠ 这条要有判据（换腿前后两侧解析出的 `runs/` / `data_root` 必须相等）。

#### 7.1.1 ⚠ 步骤 1 实施中发现的三条（**不写就会被下一个人重踩**）

**① 日志泵不能用 `read(n)`**

朴素写法 `out.read(4096)` 会**阻塞到缓冲满**才返回 ⇒ **子进程只写一行时，
日志文件根本不出现**（判据 2 第一次就是红的 —— 它真的激怒了实现）。
⇒ **必须按行迭代**（`for line in stream`）。已落地 `supervise.py:428`。

**② `taskkill /T /F` 治不了铁律 3 的根因** ⇒ 见铁律 3 的"第二层坑"（**用 Job Object**）。

**③ ⭐ 判据 3 的造法必须比"最朴素造法"更狠**

最朴素的造法（"造一个**没人听**的旧端口文件"）**红不了**：
那时是**探活**在拒绝它 —— 把"快照比较"退化成 `return True` **照样绿**。

⇒ 必须让**旧值那个端口也有人在听、也回 200**：于是"文件存在且非空"与"探活通过"
**两条都成立**，唯一还能识别出问题的只剩"**这个文件是 spawn 之前就有的**"（快照比较）。
这才是 EL 那个假绿的真实形状。已落地 `checks/launch_selfcheck.py:99-121`（另补 ③b 覆盖原始形状）。

⚠ **这条经验是通用的**：**判据如果连"故意退化实现"都红不了，它就不是在测那件事。**
写这类判据时，**先问"我怎么退化成错的还能让它绿"**，然后按那个形状造数据。

#### 7.1.2 已裁决的运维语义（步骤 1 遗留问题）

| 问题 | 裁决 |
|---|---|
| `--all` 起完**不退出**（留着状态页） | ⭐ **就该如此**：supervisor 必须活到子进程结束；**退出靠页面「收尾退出」或 Ctrl-C**。不许"起完即退"（那会连带收尾整组） |

| POSIX 无 job 等价物（detached 孙进程会逃逸） | 如实登记为**已知局限**，不建 cgroup 机制（见铁律 3） |

## 8. 术语（避免走歪）

| 本名 | 含义 | ⚠ 易混 |
|---|---|---|
| **human adapter** | §4.5 既有词：人那条腿（GUI） | **不是**"启动模式"，也**不是**"另一条脊椎" |
| **换腿**（switch leg） | 停一条腿→等真退出→起另一条腿 | ⚠ **不是**"两条腿同时活"（铁律 4） |
| **账不断** | 状态连续的正解：账只追加，当前状态是它的折叠 | ⚠ **不是**"内存共享" |
| **生存域** | 用 `ChildSpec.restart` + `Strategy` 表达（OTP 形状） | ⚠ **不是**新概念，是**已有装配关系的配置** |
| **聚合端点** | 挂给 dsh 的**唯一** MCP 服务端 | ⚠ **不是**第二个 dsh |
