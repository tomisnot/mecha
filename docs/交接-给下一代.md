# 交接：给下一代开发者（mecha）

> 读完这份大约 20 分钟。**规范源是 `docs/v2/`**（尤其「架构总纲」），本文只做"从哪进、往哪看"。
> 凡本文与代码冲突 ⇒ **以代码为准，并回来改本文**（见第 10 节）。

## 1. 一句话：这个仓是什么

**mecha 是"一台软件的操作者无关层"**：给成熟软件装上**人机同路的写入门、一份自己的账、一个能力面、
一个给人看的监控面**，以及一层把宿主差异关起来的 Provider 层。

它**不是**一个自给自足的 AI 框架，也**不是**某个宿主的组件：dsh 之类的宿主只是它的**一个操作者
适配器**，与 GUI 平级；宿主消失时，数据、账、监控面照常，只少一个操作者。（完整口径：`README.md`
的「它是什么 / 不是什么」）

## 2. 最短上手

```bash
git clone https://github.com/tomisnot/mecha && cd mecha
python checks/run_all.py        # 门禁一条跑全
```
* **前置**：Python ≥ 3.10。⭐ 核心**不依赖任何第三方**（`pyproject.toml` 里 `dependencies = []`）；
  只有 MCP 投影那条路要可选依赖（`mecha[mcp]`）。
* **成功的标志**：末尾打印 `run_all: 全部门禁 PASS`，并给出 `PASS / FAIL / SKIP` 三个数，
  以及**按名列出**跳过的判据。
* **想看框架长什么样**：`docs/接入指南.md`（六步接入 + 每步验收）是给"新项目"的入口；
  `scripts/demo_projection.py` 是一次性演示（不是判据），跑它能看到"命令声明 → AI 工具面"。

## 3. 目录地图

**主干**（改这些要先读规范源）：
```
mecha/gate.py       写入门：四步 set（写权 → 校验 → 落快照 → 记史）、seed、set_batch、record
mecha/history.py    账：Event 形状、fold（只折 state）、两个写口；LogSink 契约 = append/since/last_seq 三原语 + 一个可选能力 precheck（经 getattr 发现，缺失即无预检；subscribe 不在契约里）
mecha/surface.py    能力面：Engine 四个必方法 + 注册项（EntryKind）
mecha/monitor.py    人类监控面：两层（概括层 / 原始层）+ 存疑裁决
mecha/authority.py  写权模式机：LOCKED / HUMAN / AI / OPEN（DEFAULT_MODE = LOCKED）
mecha/scopes.py     (side, scope) 细粒度授权：默认拒绝，可显式放行
mecha/commands.py   命令面：声明即契约（参数/回执/side_effect/审批/可取消）
mecha/tools.py      工具形态层：ToolDefinition / define_tool / ToolRegistry / 命名律与禁用词
mecha/toolhost.py   工具定义与传输分离（local 出厂 = 进程内直调）
mecha/projection.py ⭐「缝」：命令声明 → AI 工具面（纯投影）
mecha/assembly.py   **具名装配点** `assemble()`：真实部署路径也走它
mecha/cockpit.py    监控面的只读 HTTP 传输（四路由 + 各种投影函数）
mecha/portfile.py   端口**发现规则**（"等这个端口文件出现"，路径由调用方给）
mecha/data_layout.py 数据目录布局（root 由宿主给、目录名由项目注入；**不猜路径**）
mecha/artifacts.py  宿主产物托管（不透明 locator；核心唯一的"落盘 + 句柄"机制）
mecha/roles.py      角色/能力图：每个缝声明 Definition / Provider / Consumer
mecha/errors.py     错误类型与跨边界投影（MechaError / ToolFailure / GateDenied）
mecha/format_version.py 持久格式版本 + 相邻边迁移链（已发布的磁盘产物不许移动/覆盖）
mecha/write_lease.py 跨进程写租约（同一数据目录只允许一个写宿主）
mecha/providers/    Provider 层（宿主的 churn 关在这里）：log_local / jobs / approval / skills / codeact / mcp
```
**外围**：`checks/`（门禁，见第 7 节）· `scripts/`（生成器与一次性演示）· `docs/`（规范源与 ADR）·
`mecha/dsh-panel/`（**共享面板资产**，四仓各一份副本——**除参数块 `panel-config.ts` 外**逐字一致；复制约定与迁移顺序见它的 `README.md`）· `pyproject.toml` · `README.md`。

## 4. 本仓固定用语（每个一句人话）

| 词 | 一句人话 |
|---|---|
| **缝 / seam** | 一个可替换的接缝；框架声明契约，宿主给实现 |
| **Definition / Provider / Consumer** | 缝的三方：契约（我们拥有）· 实现（项目给）· 谁在用它 |
| **Gate** | 写入门：所有域状态变更的唯一入口 |
| **账 / History** | append-only 的域状态史；**它属于软件，不属于操作者** |
| **快照 / snapshot** | 从账**折**出来的当前域状态（`fold`，后写覆盖先写） |
| **state / history 事件** | `Event.kind` 两档：`state` 会被折进快照；`history` 只是记录 |
| **Surface / 能力面** | 软件对外暴露的能力（`Engine` 的四个必方法 + 注册项） |
| **Channel** | 一条操作者通道：`side ∈ {human, ai}` 定写权；`actor` 只是归因标签 |
| **具名装配点** | `assemble()`——唯一被认可的装配方式（生产路径也走它） |
| **Provider 层** | 把宿主的 churn 关起来的那层（日志/任务/审批/技能/编排/MCP） |
| **capability map** | 生成的"能力 × 角色"表（`docs/capabilities.md`，禁止手改） |
| **面板资产** | `mecha/dsh-panel/`：四仓共用的监控面板源码（不是框架能力） |
| **命名律 / 禁用词** | 工具名（= **AI 看得见的面**）的形状约束与禁用词表；见第 6 节第 12 条 |

## 5. 跟着一条数据流走一遍（**最值得花力气的一节**）

**A. 人类/AI 改一个域状态**
```
操作者（GUI 或 AI 适配器）
  → Channel('gui','human') / Channel('ai','ai')        构造期钉死 side（mecha/gate.py:Channel）
  → gate.set(channel, key, value, reason, ...)          mecha/gate.py
      ① authority.gate(side)  写权：LOCKED 谁都拒；OPEN 两侧都放行；否则只放行当前 mode 那一侧
      ② validate(key, value)  宿主注入的校验器（不校验请显式传 accept_all）
      ③ 落快照（Gate 私有；预检失败则一字节不动）
      ④ history.append_state(target, after, before, …)  记史（带前像）
  → LogSink.append(record)                              默认 mecha/providers/log_local.py（JSONL + 写租约）
  → 磁盘 journal.jsonl
```
**B. 读回来（两条路，都只读）**
```
History.events() → fold(events) → 快照            mecha/history.py（fold 只折 kind=="state"）
Monitor.read()   → MonitorView(summary, raw_snapshot, disputed, summary_error)
                    概括层与原始层对账；不一致 ⇒ 原始赢 + disputed=True（mecha/monitor.py）
cockpit 四路由（/status /activity /history /config）→ JSON   mecha/cockpit.py
                    事件投影：history_records / activity_records / config_tree
→ 面板（mecha/dsh-panel/，宿主挂载）→ 人看见
```
**C. AI 走命令面/工具面（推荐路径）**
```
AI → MCP → tools（ToolRegistry）→ ToolHost（local 或远程）→ 命令体
              ↑ 工具面由命令声明投影而来：mecha/projection.py::project()
命令面：commands.invoke(name, args, gate=…, channel=…, approval=…)
  → scope 检查 → authority 检查 → 审批 → 参数校验 → handler
  → 审计事件：gate.record(op="command.<名>", …) ⇒ append_history（**永不进快照**）
```
⭐ **只有两条写路径**：`append_state`（改快照 + 记史）与 `append_history`（只记史）。
**"绕过"的定义就是：两条都没走。**（文档口径：`docs/v2/架构详解.md` §2.2）

## 6. 改代码前必须知道的坑

1. **别让审计进快照**：审计曾经借 `gate.set` 落史 ⇒ 用含审计事件的日志重启会把 `command.*` 折进
   快照。现在 `fold` 只折 `kind == "state"`。⇒ 新写史一律用 `append_history`。
2. **`command.` 前缀只是命名习惯**：判定一律看 `kind`（旧注释里"前缀隔离"那套说法已不成立）。
3. **两面 `parameters` 不同形**：命令面是**完整 JSON Schema**（`type/properties/required`），
   工具面 `define_tool` 要的是**逐键属性表**。`project()` 负责转对（`mecha/projection.py`）。
4. **投影产物必须可调**：`project()` 的 `execute` 是**必填**（忘了给 ⇒ 构造期抛）；
   "列得出、调不动"是本仓列过的六大缺陷类之一。
5. **判据必须"能红"**：新加判据要配"把扰动打上去它真的红"的证明，且**自证扰动确实落上**。
   写不出红证的判据 ≈ 没有判据（见 `docs/v2/框架准入线.md` 的 R 系列）。
6. **不许手抄计数**：文档与判据里都不写"多少个/多少条"（会漂）。要规模就写"逐条/少量/很多"，
   或指到命令上让人自己数。
7. **"共享默认"要用临时清空来测**：不许假定"项目没填过参数块"——那会把消费者照文档行事变成破坏判据。
8. **本机路径不许进仓**：`checks/personal_paths_selfcheck.py` 会红。
   ⚠ 判定必须在 **Python** 里做（PowerShell 会给非 ASCII 路径加转义，导致"读不到"冒充"没命中"）。
9. **严格 tsconfig**：`mecha/dsh-panel/` 要在 `--strict --noUncheckedIndexedAccess` 下编译
   （越界索引一律 `?? ''`），并且它**随包发货**（`pyproject.toml` 的 `package-data` 要列 `.tsx`）。
10. **写租约**：同一数据目录只允许一个写宿主（`mecha/write_lease.py`）；只读投影用 `exclusive=False`。
11. **别改判据让它变绿**：判据是"能红的守卫"，不是"待办的清单"。看到红先问"它守的东西是不是真坏了"。
12. **工具面就是 AI 可见面 ⇒ 命名律与禁用词是接入方必须知道的一部分**：
    `mecha/tools.py` 的 `check_tool_name` 会拒"视图/枚举式"命名与项目前缀，
    `define_tool(..., banned_words=…)` 让**项目按自己的领域词表**加禁用词。
    ⇒ 三个接入仓都在用它；**接入时不给词表，等于把领域词直接写给模型**。

## 7. 判定 / 门禁

* **一条跑全**：`python checks/run_all.py`（清单在 `checks/run_all.py` 的 `CHECKS`）。
  输出给 `PASS / FAIL / SKIP` 三个数 + **按名列出跳过的判据**；`--require-external` ⇒ 跳过即失败。
* **单跑一条**：`python checks/<名字>.py`（每条都能单独跑，报错栈更完整）。
* **"能红"是什么意思**：本仓的判据大多带**对偶**（"能抓坏" + "不许误报"）与**自证**
  （例如个人路径守卫会打印"实际读到几个文件"）。改判据时**两边都要动**。
* **怎么读红**：先看 `FAIL` 项的名字，再单跑它看完整栈；⚠ **别用自己的 grep 把输出过滤成只剩计数**
  （会把 FAIL 藏起来）。
* 判据的写法纪律：`docs/v2/框架准入线.md`（R 系列）· 常见测量陷阱：`docs/v2/操作陷阱.md`。

## 8. 已知问题 / 挂起项（含**故意挂着的**）

* **"命令声明 → AI 工具面"的缝**：原先挂着等 n=3（"n=1 不预建"），**现在已定**，
  落点 `mecha/projection.py`；`commands.py` 里那句"契约未定"的注释已改成"契约已定"。
* **`LogSink.since` 的筛选**（按 `actor` / `op` / `limit`）：实现已在（`mecha/providers/log_local.py`），
  **消费者还没接**（谁要按人/按动作查，接上即可）。
* **`Event.undoable`**：槽位有、三态（`None` = 未声明），**今天没有项目在传**；
  "能不能撤"是领域知识 ⇒ 框架只给槽位，不据此实现撤销。
* **`ToolDefinition.kind / scope / reversible`**：由投影器发出，**框架内今天没有消费者**；
  在"声明必须被消费"的三态表里如实登记为 `deferred`（`checks/capability_map_selfcheck.py`）。
* **概括层的"故障"档**：`Monitor.read()` 故障时返回**降级读数**（原始层照给 + `disputed=True` +
  `summary_error`）；⚠ `summary_error` **今天没有任何人能看见它**（面板不消费）⇒ 表里登记 `deferred`，
  **等一个真会显示它的界面出现**再转 `consumed`。
* **Provider 的推迟登记**：见 `checks/capability_map_selfcheck.py` 的 `DEFERRED_PROVIDERS`
  （加了新 Provider 却不声明消费者 ⇒ 判据红，逼"推迟不许沉默"）。
* **触发条件**：挂起项一律**绑条件**（"等第二个消费者"/"等某个界面出现"），条件到了就该做，
  不是"有空再说"（纪律见 `docs/v2/ADR制度.md`）。

  › **已知空白（只登记，不建机制）**：各仓的指纹表是**手抄常量**、跨仓一致性今天靠各自的

* **框架改了之后，三个接入仓按什么顺序同步**（可执行步骤）：

  框架侧的跨仓判据才验得到）。

## 9. 与另外三个仓的关系

* **`mecha`（本仓）= 框架**；`energy-level` / `get-paper` / `ml-toolbox` 是**用它的三个真实项目**
  （各装自己的领域内容；**mecha 里没有任何领域实现**）。
* **共用面**：端口**发现规则**（`mecha/portfile.py`）· 监控四路由（`mecha/cockpit.py`）·
  面板源码（`mecha/dsh-panel/`，四仓各一份副本、**除参数块 `panel-config.ts` 外**逐字一致；
  复制约定与各家的副本落点见该目录的 `README.md`，改动要同批改并更新指纹）· 事件形状与账的
  **落点契约**（项目可把账写进自己的库，关键是**与域状态变更同事务**）。
* ⚠ **四仓的出厂写权模式不一样**（别以为"四仓出厂一样"而在另一个仓上撞墙）：
  框架 `mecha/authority.py` 的 `DEFAULT_MODE = LOCKED`；EL 硬写 HUMAN（`v2_bind.py:174`）；
  GP 的库默认 LOCKED，而它的 CLI 启动模式默认 `open`（`hub.py:77` / `hub.py:195`）；ML 为 LOCKED。
  ⚠ 后两处行号来自横向检查，**我未在本机逐条核对**。
* ⚠ **跨仓验证的真实覆盖**：框架侧跨仓判据**只覆盖 EL**（`MECHA_EL_ROOT`）⇒
  **ML 与 GP 从不被框架的门禁验证** —— 这是目前唯一的真实耦合缺口。
* 新项目接入：读 `docs/接入指南.md`（六步顺序 + 每步验收 + 「该由谁提供」）。

## 11. 给 AI 代理的三条

1. **从哪道门进来**：AI 侧走 `Channel(side="ai")` → `commands.invoke(...)`（有声明、有审计），
   或走**工具面**（MCP → `ToolHost`）。**不要**试图绕开门去改域状态（快照是 Gate 私有的）。
2. **不许做的事**：不许**自我开闸**（`switch_mode` 只认 human，出厂是 `Mode.LOCKED`）；
   不许伪造通道（`Channel` 在构造期钉死 `side`，细标签只能进 `actor`）；不许**改判据让它变绿**；
   不许在文档或判据里**手抄计数**。
3. **最容易违反的两条纪律**：①把"改判据"当成"修 bug"——**红必须先是真的坏**，
   判据守的东西坏了才改判据；②用"删判据/跳过判据"换绿——`skipped > 0` 在本仓被视为**红**
   （"跑起来了但没有用例真的跑"是最坏的一种绿）。
