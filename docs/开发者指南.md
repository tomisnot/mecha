# mecha 开发者指南

mecha 为有长期状态的软件提供操作者无关的治理层。软件拥有自己的状态、事实记录、生命周期和监控面；人、AI、CLI、GUI 和调度器只是不同操作者。

## 设计原则

- 状态属于软件，不能依附某个会话或 AI 宿主。
- 所有操作者共享同一写入治理和事实记录。
- 框架提供通用机制，项目保留领域模型、参数语义和业务策略。
- 先用架构消除错误空间，再用少量针对风险的验证确认结果。
- 事实记录与派生读模型分开；原始事实始终可查。

## 核心对象

| 对象 | 作用 | 主要代码 |
|---|---|---|
| `Authority` / `Gate` | 写权模式、写入校验、归因和审计 | `mecha/authority.py`, `mecha/gate.py` |
| `History` / `Event` | 只追加事实流、序号、操作关联和项目投影 | `mecha/history.py`, `mecha/operations.py` |
| `Surface` | 查询、钩子和类型注册项的分派面 | `mecha/surface.py` |
| `CommandRegistry` | 具名动作的参数、回执、作用域、审批、估时和调用 | `mecha/commands.py` |
| `ToolRegistry` / `ToolHost` | 把项目能力投影给 AI 或其它宿主 | `mecha/tools.py`, `mecha/toolhost.py` |
| `JobRegistry` | 长任务状态、取消、进度和结果引用 | `mecha/providers/jobs.py` |
| `ArtifactStore` | 大结果和文件产物的非透明定位符 | `mecha/artifacts.py` |
| `Monitor` / `Cockpit` | 只读状态、历史和派生摘要 | `mecha/monitor.py`, `mecha/cockpit.py` |
| `assemble` | 统一装配入口 | `mecha/assembly.py` |

mecha 不定义计算引擎或通用 `run` 协议。计算、训练、抓取和学习动作由项目自己实现，再注册为命令、查询或 Jobs。`ExecutionContext` 只提供通用取消和进度。

## 数据流

```text
操作者 → ToolHost / CLI / GUI → CommandRegistry 或 Surface.query
       → Authority / Gate → 项目状态与业务事件
       → History / 项目事务账 → Monitor、投影和产物引用
```

命令由 `CommandSpec` 声明，处理函数由项目提供。命令执行会建立 `operation`，使审计事件、业务事件、错误和结果引用可以关联。项目可以把 `History` 接到自己的事务数据库，但必须保证状态与事实的落点一致。

## 扩展方式

1. 用 `assemble()` 接入 `Gate`、`History`、`Surface`、命令表、Jobs 和产物存储。
2. 只读能力用 `Surface.register(EntryKind.QUERY, ...)` 注册。
3. 有副作用的动作用 `CommandSpec` 和 `CommandRegistry.register()` 注册。
4. AI 工具从命令和查询投影，不另写一套执行实现。
5. 长任务使用 Jobs；大结果使用 ArtifactStore；领域语义留在项目侧。

详细的稳定接入步骤见 [接入指南](接入指南.md)，当前能力清单见 [capabilities.md](capabilities.md)。阶段性决策和已废弃方案位于 `docs/history/`，不属于当前接口。
