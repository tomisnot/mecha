# mecha 接入指南

本指南描述当前 API。长期目标见[设计愿景](设计愿景.md)，模块职责与限制见[开发者指南](开发者指南.md)。mecha 帮助 AI 操作软件，项目继续负责自己的状态、领域规则和执行过程。

## 1. 选择接入边界

先找出项目已有的查询、修改和执行入口。人、AI、CLI 和 GUI 应复用这些业务实现。能力可以是局部修改、组件操作或诊断，不必都收敛成提交完整配置再运行。

`assemble()` 提供 Authority、Gate、History、Surface、Commands、Jobs、Artifacts、Monitor 和本地工具宿主。已有数据库的项目可以保留业务状态，并通过 `log_sink` 接入自己的事件存储。框架不要求再复制一份业务数据库。

## 2. 最小装配与查询

下面是可直接运行的最小例子。数据目录按项目需要选择；示例显式使用 OPEN，让人和 AI 都可写，默认装配则为 LOCKED。

```python
from pathlib import Path
from mecha.assembly import assemble
from mecha.authority import Mode
from mecha.errors import MechaError

def validate(key, value):
    if key != "gain" or type(value) not in (int, float) or not 0 <= value <= 10:
        raise MechaError("gain 必须是 0 到 10 的数值", kind="invalid_gain")

software = assemble(
    root=Path("."),
    data_dir_name=".mecha",
    project="my-project",
    summarizer=lambda events: {"event_count": len(events)},
    validate=validate,
    mode=Mode.OPEN,
)

software.surface.register(
    "query", "describe_state", lambda: software.gate.snapshot,
    called_by="project-adapter",
)
print(software.surface.query("describe_state"))
```

`Surface.register()` 返回注销函数。查询回调接收 `query()` 透传的命名参数；返回值的可序列化、分页和体积控制由项目负责。查询应保持只读。

## 3. 注册与调用命令

接着上面的例子，注册一个局部修改动作：

```python
from mecha.commands import CommandSpec

spec = CommandSpec(
    name="set_gain",
    description="只修改 gain，保留其它配置",
    parameters={
        "type": "object",
        "properties": {"value": {"type": "number"}},
        "required": ["value"],
    },
    output_schema={"type": "object", "required": ["gain"]},
    side_effect=True,
    wants_channel=True,
)

def set_gain(*, context, channel, value):
    software.gate.set(channel, "gain", value, reason="调整 gain")
    return {"gain": software.gate.snapshot["gain"]}

software.commands.register(spec, set_gain)
receipt = software.commands.invoke(
    "set_gain", {"value": 2, "reason": "调试当前配置"},
    context=None,
    gate=software.gate,
    channel=software.channels["ai"],
)
print(receipt)
```

有副作用的命令缺少 `gate` 会在执行前拒绝。省略 `channel` 时使用 AI 侧默认通道，权限检查、`wants_channel` 注入和审计使用同一通道。实际接入应显式传入对应入口的通道。只读命令不需要 Gate。

框架检查必填参数、未声明参数和必填回执键；这不等于完整 JSON Schema 类型校验。参数范围、单位、跨字段约束仍由项目执行。默认参数也应由处理函数或适配层明确提供。

`CommandSpec` 的策略字段包括 `side_effect`、`scope`、`approval_required`、`cancel_supported` 和 `estimate_sec`。当前没有 `writes_state`、`risk` 字段。`scope` 需通过 `commands.bind_scope_policy(policy)` 绑定策略才会检查；声明需要审批时，还必须向 `invoke()` 传入 `approval`。

如果状态在项目数据库或设备中，命令处理函数可调用项目自己的事务或服务。Gate 的前置检查和命令审计不要求把业务数据搬进键值快照，也不自动为外部动作提供事务或设备互锁。

## 4. 记录操作与结果

`invoke()` 在处理函数执行期间建立 operation 上下文。项目可用 `mecha.operations.current_operation_id()` 将业务事实关联到本次操作。输入中的 `reason`、`call_id`、`operation_id` 默认作为框架元数据；处理函数需要接收其中某项时，必须将其列入参数的 `required`。

处理函数可返回普通映射，或 `CommandResult(ok=..., values=..., error=..., result_ref=...)`。`result_ref` 是项目定义的结果引用，会随命令审计记录；需要在调用回执里提供查询入口时，也应将相应引用放入 `values`。

当前命令审计在处理函数返回或抛错后写入。它不是完整的执行阶段账本；进程骤停可能缺少结束记录。业务提交与审计写入也不构成自动跨系统事务。结果不明时应查项目事实，不能从缺少记录推断动作没有发生。

## 5. 长任务

下面示例同样接着最小装配运行：

```python
items = [1, 2, 3]

def work(ctx):
    total = 0
    for index, item in enumerate(items, start=1):
        if ctx.cancelled:
            return {"partial_total": total}
        total += item  # 实际项目在这里执行工作
        ctx.report_progress(index / len(items), f"item {index}")
    return {"total": total}

job = software.jobs.submit(work, command="build_index", cancel_supported=True)
print(software.jobs.wait(job.id, timeout=5))
```

`ExecutionContext.cancelled` 表示收到取消请求；`report_progress(frac, stage)` 报告进度，`progress()` 读取进度。上下文没有 `job_id` 或通用日志接口，任务 ID 从 `submit()` 返回的 Job 获取。

默认 Jobs 每次提交创建一个 daemon 线程，不提供资源队列、并发上限或跨重启恢复。`wait()` 返回当前任务状态，等待超时不会把任务改成 failed；`job.wait(timeout)` 可直接返回是否等到终态。

项目负责检查取消请求、处理部分结果和判断业务成功。当前实现会在函数返回时根据取消标志归为 cancelled，即使函数没有提前停止；不能用这个状态证明设备已经停止。普通返回值中的 `ok=False` 也不会自动转成 failed。后台线程不会自动继承 operation 上下文，接入方需要显式传递并建立关联。

## 6. 产物与收尾

```python
locator = software.artifacts.put(b"example result", kind="text", name="result.txt")
print(software.artifacts.describe(locator))
assert software.artifacts.retrieve(locator) == b"example result"
software.close()
```

本地产物保存字节和元数据，返回不透明 locator。当前 locator 的解析依赖当前 store 实例的内存映射；跨重启查询应接入项目已有的持久结果索引。不要将大数组、完整日志或二进制塞进操作回执。

`software.close()` 当前关闭 History 并释放其存储资源；项目还需自行停止任务、关闭 HTTP 服务和释放设备等资源。不要在任务仍可能写账时先关闭 History。

## 7. 工具、监控与宿主

查询和命令注册不会自动成为 AI 工具。项目使用 ToolRegistry 注册工具，可通过 `mecha.projection.project()` 将命令声明投影为工具定义，并提供调用 `commands.invoke()` 的执行适配。保持领域失败在工具面仍然是失败，避免把失败回执包成成功结果。

`MonitorSource.from_software(software)` 与 `start_monitor_endpoint()` 提供只读 HTTP 观察；`schema_rows`、`status_extra` 和额外路由由项目按需提供。`/history` 保留事件原始字段，`/activity` 提供含操作关联的轻量事件。两者的事件 `kind` 为 `state` 或 `history`，动作名称看 `op`；HTTP 最多返回最近 100 条。当前没有自动关联所有 Jobs、Artifacts 与领域页面的通用视图。

项目可用自己的页面解释领域结果。接入 dsh 或 Codex 的启动方式见 [README](../README.md)。软件是否可用、当前写权、任务是否完成是不同事实，应分别查询。

聚合调用断线后会尝试重新发现后端，但不会自动重放原调用；返回 `backend_outcome_unknown` 表示执行结果无法确认。超时仍返回 `backend_timeout`。这两种情况都应先查询任务、操作记录或实际状态，再决定是否重交动作。

## 8. 接入验收

- 查询不依赖 AI 会话存活，也不隐式改状态。
- 人和 AI 复用领域实现，未授权动作在执行前被拒绝。
- 参数与回执契约真实，失败路径保留可查询的结果依据。
- 项目账本与操作关联可查，任务取消和恢复行为有明确说明。
- 大结果可通过回执中的引用读取，监控能定位相应业务事实。
- 断线、超时和重启后不会凭模糊失败盲目重复有副作用的操作。
