# mecha 接入指南

本指南面向希望让已有软件同时接受人和 AI 操作的项目。接入从软件状态和业务动作出发，不要求项目拥有统一的计算引擎。

## 最小装配

```python
from pathlib import Path
from mecha.assembly import assemble
from mecha.gate import accept_all

software = assemble(
    root=Path("./data-root"), data_dir_name=".mecha",
    summarizer=lambda events: {}, validate=accept_all,
    project="my-project",
)
```

项目应把自己的校验函数替换 `accept_all`，并在关闭时调用 `software.close()`。

## 注册能力

只读能力注册为 `Surface` 查询；有副作用的动作使用 `CommandSpec` 和 `CommandRegistry`。命令声明参数、回执、作用域、估时和取消能力；处理函数只实现领域动作，写权、审批、操作关联和审计由框架处理。

把命令和查询投影到 `ToolRegistry`，再交给 `LocalToolHost`、MCP Provider 或其它宿主。工具描述只写任务语言，不暴露框架模块、线程、数据库表和传输细节。

## 长任务和大结果

长任务交给 `software.jobs.submit()`，通过 `ExecutionContext` 报告进度并响应取消。文件、长文本、图表和模型产物交给 `software.artifacts`，工具回执返回非透明定位符和必要摘要。

## 账与投影

`History` 是事实记录，不是业务对象的替代品。项目可以记录配置变化、业务事件和命令结果，并用 `fold` 或项目投影重建当前读模型。事实流只追加；派生缓存可以丢弃和重建。

## 验证

验证写权前置、能力投影一致、结构化失败、长任务终态、结果引用和监控原始事实。只按改动和风险运行检查，不为文档格式或重复结构增加门禁。
