# 接入指南：让一个新项目接入 mecha

> **这份指南回答两件事**：① **框架给你什么**（必选 / 可选，各是什么、不做会怎样）；
> ② **你要干什么**（按依赖排序的清单，每步带验收）。
>
> 形态上，接入 = **一份声明**（`mecha_site.py`）＋ **一个带闸门和账的软件进程** ＋ **几个回调**；
> 编排、两条腿、工具面、面板由框架提供。⚠ 读之前先看 `架构总纲.md` §5.5–§5.7（三层与两条腿、
> 启动功能）与 `架构详解.md` §13–§14（建成态：谁住哪、一次启动发生什么）。

---

## 0. 先自问：**该接入，还是该自己写**

接入的收益是**编排与两条腿**（进程编排、写权四档、AI 工具面、人侧控制台与面板）；
代价是**你得接受框架的形状纪律**（声明是数据、领域值不许进框架、控制操作不进 AI 腿、
每条守卫要有能红的证据）。

⚠ **n=1 的忠告**：只有你一个消费方时，任何"通用化"都可能只是你的形状被固化。
框架存在的理由是**第二个项目接入时不用重写**——所以接入时**别要求框架替你分类**
（哪些是 core / seam / bundle 之类），只要求**机制**（`docs/v2/架构总纲.md` §5.4）。

## 1. ⭐ 框架提供什么（盘点）

### 1.1 编排层（你**不用写**的部分）

| 能力 | 住哪 | 你得到什么 |
|---|---|---|
| 唯一入口 + 多站点平铺 | `mecha/__main__.py` · `mecha/launch.py` | `python -m mecha --all` 把 N 个站点的服务平铺进同一个 supervisor；`--stop` 收尾、`--dry-run` 只打印计划 |
| 进程编排 | `mecha/supervise.py` | spawn / 重启策略 / **真探活就绪** / 日志轮转 / **整组死**（内核保证）/ 陈旧残留清理 / 状态**唯一真值源** |
| 陈旧残留清理 | `supervise.plan_startup` → `clean_stale` | 孤儿进程与**陈旧端口文件**在起之前清掉，并记进状态页（"清掉了什么"要能被核对） |
| dsh 启动 + overlay 生成 | `launch.py` · `aggregate_runtime.overlay_text` | 第三层 overlay 由框架按**回读端口**生成（地址不进你的声明） |
| 聚合端点装配 | `launch.build_aggregate_wiring` | AI 那条腿（见 1.3）**全自动**：起端点、挂后端、就绪/退出时同步工具表 |
| 常驻控制台 | `mecha/providers/status_page.py` | 人的启停滑块 + 写权按钮 + 「打开监控面」+ 收尾退出 |
| dsh 侧面板 | `mecha/dsh_panel.py` · `mecha/dsh-panel/` | 每个服务一个监控 tab + guide 页 + **你的附加页**；地址路由由框架按**端口文件**现取 |

### 1.2 软件进程内的地基（库，你**必须用**）

| 件 | 住哪 | 一句话 |
|---|---|---|
| 写入门 + 账 + 能力面 | `gate.py` · `history.py` · `surface.py` | **每次写都经闸门、记一条事件、可归因**；`Engine` 是你要实现的四件事 |
| 写权档 | `authority.py` | `locked` / `human` / `ai` / **`open`（AI 与人共用）**；出厂 `LOCKED` |
| 工具定义与注册表 | `tools.py` | `define_tool` + `ToolRegistry`；`schemas()` 是**模型可见面的单一来源** |
| 传输 seam | `toolhost.py` | `LocalToolHost`（同进程）与 MCP Provider（跨进程）**同一套调用契约** |
| 装配单点 | `assembly.py` · `roles.py` | `assemble()` 是唯一具名装配入口；`declare_roles()` 是 capability map 的生成源 |
| 可教学错误 | `errors.py` | `message` + `kind` + `hint` + `suggest`：错误消息是给 AI 的 UI |
| 目录 / 数据根 / 写锁 / 版本 | `data_layout.py` · `write_lease.py` · `format_version.py` | 目录名由外部注入（库不猜路径）；**同一数据根只有一个写宿主**；相邻边迁移链 |
| 端口发现 | `portfile.py` | 启动前清陈旧、收尾**只删自己写的那个**（按内容判归属） |
| 只读监控传输 | `cockpit.py` | status / activity / history / config 四路由 + **`add_route` 扩展点**（你的附加页取数） |
| MCP 传输 Provider | `providers/mcp.py`（**extra**） | `schemas()` → `MCPServer`；核心**不** import 它 |

### 1.3 **两条腿**（框架提供，形态由你声明）

| 腿 | 走哪条道 | 谁用 | 你要做的 |
|---|---|---|---|
| **AI 腿** | 框架**聚合端点**（一个端点承载全部软件） | AI | **零**：起端点、挂后端、命名律、**工具表热同步**（对账 + 声明 `tools.listChanged` + 服务端主动广播）、墓碑语义，全在框架 |
| **人手腿** | 常驻控制台（框架）＋ **你自己的人面** | 人 | 交 **3 个回调 + 2 个值**（见 §3 第 4 步）＋ 选一种人面形态（§3 第 6 步） |

**AI 工具命名律**（框架定的，**别自己起名**）：`mcp__<聚合名>__<软件>_<工具>`。
聚合名是框架级常量（站点顺序无关），软件前缀由你的 `Service.id` 小写化而来。

**框架元工具**（AI 面自带，你不用写）：写权**只读**自省（一次报全部在跑的软件）、
开关某个软件、列软件。⛔ **切写权与开人面绝不进 AI 面**（那是控制操作）。

### 1.4 制度与守卫

| 件 | 你要做的 |
|---|---|
| ADR 制度（`docs/v2/ADR制度.md`） | 做出**不可协商**的决定时写一篇；发现架构文档没覆盖的情况也写 ADR，**不许在代码里静默决定** |
| capability map | 用 `declare_roles()` 声明角色；改完跑 `scripts/gen_capability_map.py`（`--check` 进框架门禁，**禁止手改产物**） |
| 框架门禁 | `python checks/run_all.py`（缺外部依赖会跳过并打印判据名；严格模式 `--require-external`） |
| 你自己的判据 | ⚠ **最容易偷懒的一步**：每条守卫都要有**能红的证据**（R7），且要**确定性**的 |
| `Known Limitations` 段 | 模块 docstring 里如实登记"想做什么但没做"，并写**重新考虑的条件** |

## 2. ⭐ 必选 / 可选（一张表看清你要交什么）

| # | 你交什么 | 必选？ | 不做会怎样 |
|---|---|---|---|
| 1 | `mecha_site.py`（模块级 `SITE`） | **必选** | 框架发现不了你 ⇒ 起不来 |
| 2 | 软件进程：`Gate` + `History` + `Surface` + `assemble()` | **必选** | 没有门和账 ⇒ 无归因写入，不成立 |
| 3 | 一个"起服务"的形态（如 `--mcp`）＋ **写端口文件** | **必选** | 框架等不到就绪 |
| 4 | 就绪判据（`ReadySpec`） | **必选** | 无判据 = "起了就算在跑"（⚠ 假绿温床） |
| 5 | 写权闸门（`authority.gate(side)`） | **必选** | AI 与人无区别 ⇒ 写权四档无意义 |
| 6 | 工具面（`define_tool` + `schemas()`） | 可选¹ | AI 看不到/调不动你的东西 |
| 7 | 控制端点（3 回调 + 2 值） | 可选² | 人不能切写权 ⇒ 只能 `locked`/`ai` 起步后不动 |
| 8 | 监控面（`cockpit` + `add_route`） | 可选 | 面板看不到你的状态/活动/历史/配置 |
| 9 | `MonitorSpec` 声明（含附加页） | 可选³ | 面板里没有你的 tab / 附加页 |
| 10 | 人面（进程内窗口 / 浏览器页 / 只读 web 侧车） | 可选⁴ | 人只有控制台，没有"做事的面" |
| 11 | dsh 半（空载体 + 一行 bootstrap + patch entries） | 可选⁵ | AI 那条腿仍然通（聚合端点不需要你写 dsh），但没有你的面板贡献 |
| 12 | 你自己的判据 + `Known Limitations` | **必选** | 守卫是空的 ⇒ 下次改动只能靠人记 |

¹ 只要 AI 要调你的东西就**必选**。² 只要人要在运行时切写权就**必选**。
³ 要面板里出现你的页就必选（`route_path` + `port_file`）。
⁴ 只给 AI 用、没人要看的项目可以不交（`has_gui=False`）。
⁵ 方案 A 之后**工具面不走项目 dsh**；dsh 半只承载"面板贡献"，可以后补。

## 3. 接入顺序（每步带验收）

### 第 0 步 · 先划线：哪些是**领域**，哪些是**机制**

- 领域（你的）：`Engine` 的四件事、工具名与参数语义、工具说明文案、配置字段、目录名、
  数据根的**唯一解析点**、人面长什么样、`how_to_open` 那句原话。
- 机制（框架的）：门/账/写权/能力面/形状、编排、两条腿、面板、端口发现规则、错误词汇。
- ⚠ **不许把项目词放进框架**：一旦框架里出现你的项目名/路径/端口，它就不再是框架。

**验收**：能一句话说清"这条东西为什么住在我这儿"。

### 第 1 步 · 写 `mecha_site.py`（**它是数据，不是逻辑**）

导入期**零 I/O**：不起线程、不连网络、不读业务状态。字段（`mecha/site.py` 是权威）：

| 对象 | 字段 | 必选 | 说明 |
|---|---|---|---|
| `Site` | `name` · `services` | ✅ | 站点名（面板/控制台显示）、服务列表 |
| | `dsh`（`DSHSpec`） | | 站点声明 dsh 时给；全都不声明 ⇒ 框架用默认 |
| | `strategy`（`Strategy`） | | `mode` / `max_restarts` / `period_s` / `auto_shutdown` |
| `Service` | `id` · `brief` | ✅ | `id` 决定工具前缀（小写化）；`brief` 是人看的一句话 |
| | `argv` · `cwd` | ✅ | 怎么起**软件自己** |
| | `ready`（`ReadySpec`） | ✅ | 就绪判据（见 §4 第 2 条坑） |
| | `data_root` | ✅ | 你的写租约根（**同一数据根只有一个写宿主**） |
| | `initial_mode` | | 出厂 `LOCKED`；⭐ 只有一种模式的项目声明 **`Mode.OPEN`（共用档）** |
| | `has_gui` | | 有没有"人做事的面" ⇒ 控制台据此显示「切到手动」 |
| | `how_to_open` | | 给 AI 看的"怎么切写权"**原话**（⚠ 别写端口/凭据） |
| | `monitor`（`MonitorSpec`） | | 监控面：`route_path`+`port_file` 必填；`title`/`extra_pages` 可选 |
| | `default_on` · `env` | | 默认开不开；**环境变量钉死**（见 §4 第 1 条坑） |
| `ReadySpec` | `port_file` · `probe` · `tcp` · `timeout_s` · `ok_codes` | | 判据 = **端口文件相对 spawn 变化** **且** 真探活通过 |

**验收**：`python -c "from mecha.launch import load_sites; load_sites(['.'])"` 能吃下你的声明
（`validate()` 不抛）；⚠ 引用旧文档/写死项目词的地方一律不要。

### 第 2 步 · 软件侧装配（门 + 账 + 能力面）

1. 实现 `Engine` 的四件事（`surface.py` 的 ABC）；
2. 用 `assemble()` **单点装配**（唯一具名入口）；
3. 用 `declare_roles()` 声明你的角色（capability map 的生成源），跑 `gen_capability_map.py`；
4. **写权闸门**：每条写路径先 `authority.gate(side)`（`side` 由通道决定，不由调用方给）；
5. 数据根**唯一解析点**（一处解析、一处派生目录），写租约交给 `write_lease.py`。

**验收**：`read_write_authority()` 能如实报你此刻谁能写；`local` 与 MCP 两条传输**同一套调用契约**。

### 第 3 步 · 注册工具（要 AI 调就做）

- `define_tool(name, description, parameters, output_schema, execute=…)`，说明文案是**给模型看的**
  （它决定 AI 会不会用错）；
- `schemas()` 是**模型可见面的单一来源**；`required` 由框架从你的签名派生（别手抄一遍）；
- ⚠ 有副作用的长任务要有非零预估（AI 据此决定挂不挂后台）；**并发度归你自己的线程模型**
  （框架的 local Jobs **不排队、不限流**）。

**验收**：从注册表取一条工具直接调（**别靠进程内 `MCPServer.call_tool`**，那条路没有
`request_context`）；真实验收走**真传输链路**。

### 第 4 步 · 起 MCP 投影（`mecha[mcp]` extra）

- 用 `McpEndpoint` 起你的语义通道，**写端口文件**（名字由你定，如 `.mcp-port`）；
- 端点**只发** `schemas()` 里那些工具；失败归一化成 `{is_error, error:{message, info}}`；
- ⚠ `ok_codes` 只在"有响应即证明在听"时放宽（**默认只认 2xx**），放宽**必须在声明处写理由**。

**验收**：真起子进程 → 端口文件出现 → **真探活**通过；杀进程后端口文件被清（或下次启动清陈旧）。

### 第 5 步 · 接控制端点（人侧专用，`.control-port`）

- 用 **`mecha.software_control`**（`build_control_registry` / `start_control_endpoint`）——
  **唯一实现**，你只交 **3 个回调 + 2 个值**（`authority` / `switch` / `audit` / `open_surface` /
  `how_to_open`）；
- 三个操作：`read_write_authority`（只读自省）· `set_write_authority(mode)` · `open_manual_surface()`；
- ⛔ **地址只进端口文件**，不进日志、不给 AI（AI 面上**没有**这两个写操作，有判据钉着）；
- `open_manual_surface()` 必须**如实**（三种结局）：真开出来了 ⇒ `opened`（之后 `already-open`）；
  人面**常开**（浏览器页随服务在）⇒ **恒 `already-open`**；真的没有人面 ⇒ **响亮失败**
  `no_manual_surface`。⚠ 把"常开"报成失败 = 假故障。

**验收**：起一条真控制端点，三个操作都能调；**不带人面的形态**调开人面 ⇒ 响亮失败（可教学）。

### 第 6 步 · 接监控面（可选）

- 用 `mecha.cockpit` 起只读监控端点（**回环 HTTP**，与 MCP **分开端口**），
  `add_route()` 挂你的附加数据路由（**JSON-only**，回 `{rows: [...]}` 那种形状）；
- 在声明里给 `MonitorSpec`（`route_path` + `port_file`，可加 `extra_pages`）：
  ⚠ 附件页**只装数据**（页签文案/路径/列名与取值字段），渲染归框架的共享资产；
- ⚠ 需要 HTML + 资源的"全套面板"（如 TensorBoard）属于**另一个独立服务**，
  不要塞进只读路由；它该有自己的端口文件与生命周期（见第 6 步的人面形态③）。

**验收**：面板里出现你的 tab；取不到数据时**画可读错误**（不许画空表）。

### 第 7 步 · 接人面（可选，按项目各自安排）

三种形态，选一种（或多种）：

| 形态 | 起法 | 收尾 |
|---|---|---|
| **进程内窗口** | 起服务时带能力旗标（如 `--with-gui`）；控制端点 `open_manual_surface` 在**本进程内**开 | 随软件进程 |
| **浏览器页** | 让服务形态**同一个栈**同时提供 Web + MCP + 监控 + 控制（一个进程四个面） | 随软件进程；页面地址写端口文件供人发现 |
| **只读 web 侧车** | 独立进程 + 端口文件（如 `.mlweb-port`）；**由你自己的启动方起** | 收尾**只收自己起的那个**；起不来如实报 `ready:false` + 原因 |

⚠ **窗口按需开，不启动就开**（热更新时窗口会跟着死 —— 这正是"开在软件进程内"的代价）。
⚠ "**把面板带到眼前**"是项目自己的选择（开浏览器/给链接），不是框架替你决定。

**验收**：控制台点「切到手动」⇒ 写权 + 开面**分两步如实报告**（哪一步没成都说出来）。

#### ⭐ 形态旗标**词汇表**（约定：让"带不带那一档"三家用同一套词）

框架不规定你怎么解析 argv，但**形态这件事请用这套词**（同一件事两套说法，读代码与写判据都要翻译）：

| 词 | 含义 | 现有例子 |
|---|---|---|
| `--mcp` | 起**语义通道**（AI 面）那个形态 | EL / ML / GP |
| `--with-gui` | 本进程**带人手面窗口**（**按需**开，不是启动就开） | EL / ML |
| `--with-web` | 本进程**同时伺服交互式网页**（人的工作面就在同一个栈里） | GP 的 Web 工作台 |
| `--with-panel` | 另起一个**只读网页侧车**（独立进程 + 端口文件） | ML 的面板服务 |
| `--no-open` | **不要**自动开浏览器 | 任何有网页面的形态 |

⚠ 两条纪律：① 这些词一旦采用就是那个含义（自己特有的旗标另起名，别**重名反义**）；
② **形态由启动者选**（声明里的 argv 决定）⇒ "改了声明要**重启整站**才生效"是正常的（不是 bug）。

#### ⭐ 端口：**不要自己写**那一套

端口的规则（清陈旧时机 · **只在真的在听之后才公布** · 收尾只删自己写的那个 · 探活 ·
`0.0.0.0` 归一 · 挑空闲端口 · 被占则响亮失败）已有**单一实现**：`mecha.portfile`。

```python
from mecha.portfile import PortBinding

b = PortBinding(port_file=root / ".your-port", host="127.0.0.1")   # 文件名叫什么归你
b.clear_stale()                       # 起之前无条件清陈旧
b.adopt(server.server_address[1])     # 首选：服务自己 port=0，回读真端口 ⇒ 公布
try:
    ...
finally:
    b.clear()                         # 收尾按内容清（从没公布过 ⇒ 什么都不做）
```

- **子进程**形态（端口必须在 spawn 前给）：`pick_free_port()` + `b.publish_when_listening(port)`
  （⚠ 有 TOCTOU，起不来要**如实报**）；
- **固定端口**形态：`ensure_free(host, port, label=…)` 被占即**响亮失败**（别留半残态）；
- 想"就绪后把页面带到眼前"：`b.open_when_ready()`（best-effort，开不了不算失败）；
- ⚠ `is_listening` 只探 TCP，"有人听"不等于"那是我们的服务"：要更强的一档就在自己那侧
  再探一次业务路由（例如某个 `/health`）。

**验收**：杀进程后端口文件被清（或下次启动清陈旧）；**没人听时绝不留下一个端口文件**。

### 第 8 步 · 接 dsh（可选：只为"面板贡献"）

方案 A 之后**工具面不经过项目 dsh**（框架聚合端点一条腿）。项目 dsh 半只剩：

- `dsh/src/index.ts` = **空载体**（`inject: string[] = []`、`apply()` 不收参数）；
- 一条 bootstrap 行（client 半）+ 入库的两层 patch（交付层 + 项目层）；
- 声明里给 `DSHSpec.patches` 与 **`plugin_artifacts`**（产物不存在 ⇒ 起 dsh **前**就响亮失败）。

**验收**：换一台机器/新克隆 ⇒ 补丁与产物都在（别用 dev 产物顶替交付产物）。

### 第 9 步 · 立判据（最容易被偷懒的一步）

- 每条守卫都要**能红**（R7），而且**确定性**（不靠概率/网络抖动）；
- 你改的那条路径，**要有判据真的走它**（R10）；
- 别手抄对外名单（`__all__` / 能力表 / 工具清单）：要么删掉让单一来源说话，
  要么让"漏登记"本身违规（D4）；
- 模块 docstring 里写 `Known Limitations`（想做什么、为什么没做、什么条件下重新考虑）。

**验收**：把你的某条守卫**故意弄坏**，判据必须红。

## 4. ⚠ 三条最贵的坑（先记住，能省你一天）

1. **环境变量不一致 ⇒ 两腿看不同的世界**：配置路径 / 数据根 / 日志根 / 语言编码
   都要在声明里**钉死**（连同"必须置空"的那些：空串 = **显式取消**该变量）。
   ⚠ 事故实录：某项目的开关变量被继承进来 ⇒ **服务端根本不起**，而症状是"就绪超时"。
2. **就绪判据的假绿**：只判"端口文件存在且非空" ⇒ 一个**几百小时前的陈旧文件**也能让它绿。
   判据必须是"**端口文件相对 spawn 前变化过** **且** 真探活通过"。
   ⚠ 造红证时要让**旧端口也有人在听、也回 200** —— 否则你测的是"探活在拒绝"，不是"快照比较"。
3. **端口文件族与归属**：框架只提供**规则**（启动前清陈旧 / 收尾**只删自己写的那个**，按**内容**判归属），
   **文件名归你**。常见族：`.mcp-port`（语义通道）· `.control-port`（人侧控制，⛔ 不进日志）·
   监控面端口文件 · `.web-port`（浏览器页）· 只读 web 侧车自己的端口文件。

## 5. 该由谁提供（**别把领域塞进框架**）

| 框架给（机制） | 项目给（值 / 领域 / 宿主知识） |
|---|---|
| 写入门、账、写权、能力面、形状 | 你的 `Engine`、工具名与参数语义 |
| MCP 投影、`required` 派生、null 垫片、失败归一化 | 工具说明文案、领域收编（按声明类型收编回数值） |
| 聚合端点、命名律、**工具表热同步** | 无（你只在声明里给 `id`） |
| 控制端点实现（3 操作） | 3 个回调 + 2 个值（尤其 `open_manual_surface` 的语义） |
| 监控端点四路由 + CORS + `add_route` 扩展点 | 你的附加路由与取数 |
| 端口**发现规则** | **端口文件名**（端口号一律现取，不进声明） |
| 「起进程 / 优雅终止 / 超时杀**进程树**」 | 起哪个 exe、argv、重启策略、超时值 |
| 「三个生命周期正交」的机制 | 你的人面属于哪一形态、何时开 |
| 面板与附加页的渲染器 | 页签文案/列名/取值字段（**只装数据**） |
| 错误词汇的形状 | 你的 `kind`/`hint`/`suggest` 文案 |

### ⚠ 三条别指望框架替你兜

1. **并发度归你**：框架的 local Jobs 每次 `submit` 新起线程，**不排队、不限流**。
2. **`estimate_sec=0` 等于不告诉 AI 任何事**：有副作用的命令给非零预估（框架不强制）。
3. **"读 / 写 / 读+遥测"三档归你声明、也归你对账**：框架看不到你的工具体内部到底写没写痕 ⇒
   加档位换不来机械能力，只会多一处"声明了没人喂"。

## 6. 真机验收清单（起整站看这些）

- [ ] `python -m mecha --all` 起得来；每个软件**真探活**就绪（不是"端口文件在"）；
- [ ] AI 那条腿：聚合端点里**能列出并真的调到**你的工具（**经端点真调**，不是只列名字）；
- [ ] 软件起来/退出时，AI 的工具表**跟着变**（新工具出现、退出的变**墓碑**）；
- [ ] 人那条腿：控制台能启停你、能切写权；人面按你声明的方式来（窗口/页面/侧车）；
- [ ] 监控面：面板里你的 tab 与附加页正常；读不到时**画错误**而不是空表；
- [ ] 收尾：点「收尾退出」或 `--stop` ⇒ 进程真的退出、**端口文件被清**、没有孤儿；
- [ ] 断线/重启：软件重启后 AI 仍能调它（工具表**回到可用**，不是停在墓碑）。

## 7. 接完自查（逐条回答，答不出就是没接完）

1. **我改的那条路径，有哪条判据真的走它？**（R10）
2. **每条守卫都有**能红的证据**吗？而且是确定性的、不是概率的？**（R7）
3. **有没有"手抄的对外名单"？**（`__all__` / 能力表 / 工具清单）——要么删掉让单一来源说话，
   要么让"漏登记"本身违规（D4）
4. **框架里有没有混进项目词？**（项目名/路径/端口/领域取值）
5. **声明里有没有写死端口号或凭据？**（端口一律现取；给 AI 的文本不许带地址）
6. **控制操作有没有漏进 AI 那条腿？**（切写权/开人面**只能**在人侧）
7. **`Known Limitations` 写了吗？**（想做什么、为什么没做、什么条件下重新考虑）
