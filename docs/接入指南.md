## 1. 先自问：**该接入，还是该自己写**

接入之前，先用 **R1 的三角色**过一遍你要做的东西：**定义 / 实现 / 具名消费者**，三格在哪？
**只占一格不叫接缝**，**"将来可能需要"不算消费者**，**判据不算消费者**。

⚠ **边界（L5：领域凝练）——这条最容易搞错**：

> **领域知识不进框架。** 你的工具名、参数语义、类型收编规则、阈值策略、文档文案、UI 交互、
> 端口号、超时值、文件名——**全是你的**。框架给的是**机制**，不是**值**。

**本工程真实拒绝过的东西**（照这个尺度自查，别重复提）：

| 提的东西 | 为什么拒 |
|---|---|
| `VisibilityPolicy`（可见性分级） | **零具名消费者**（R1）⇒ 删 |
| `spill`（带阈值的大文本落盘） | **零消费者、连发起方都没有**（R1）⇒ 删。且"该不该截断"**是调用方的策略**，不是 seam 的职责 |
| 框架提供 SKILL 登记制 | 框架会**吃进项目文档语义**（中文豁免词表、对照表解析）——**没人能替项目判"这句是不是有意引用"** |
| 文档字数预算门禁 | **为不存在的规模问题建机制**（那是给 266 包 monorepo 的规模控制） |
| 把 `3080/3081` 写进框架签名 | 那是 **dsh 的约定**，不是机制 ⇒ 应作**项目参数**传 |
| 抽 ML 的单例锁 | **只有 ML 有** ⇒ 是"额外能力"不是"重复的那部分"，**无第二消费者** |

## 2. 接入顺序（六步，每步带验收）

### 第 1 步 · 定义你的 `Engine`（**领域只出现在这里**）

`Engine` 有**四个必方法**：`schema` / `run` / `summary` / `estimate`。
经**具名装配点** `assemble()` 组装（**别绕过它手搭 ctx**——那正是 L6 要防的）。

- **验收**：`assemble()` 成功；`Surface` **注册即可见**；`gate.set()` 经门落史、`gate.snapshot` 读得到
- ⚠ **出厂是 `LOCKED`**，人类侧要先 `switch_mode(Mode.AI, side="human")` 才写得进去（L1：操作者无关的**一道**写入门）
- 最小可跑例子在根 `README.md` 的「怎么起（30 秒）」

### 第 2 步 · 注册工具（若你要让 AI 调你的东西）

`ToolRegistry` + `define_tool`。**工具名与参数语义是你的领域词。**

- **验收**：`schemas()` 投影出的工具面 == 你注册的；`required` 恒回 `[]`；
- ⚠ **R5 三分法（本工程踩过，代价很实）**：**`defaulted` 的唯一权威来源是声明里的 `default` 键**——
  有非 `None` default ⇒ 丢显式 `null` 让真默认生效；无 `default` 键 ⇒ 视同 `None`、保留 `null`。
  **漏一个声明 ⇒ 显式 `null` 会以 `None` 到达你的工具体**（EL 真实发生过）。
- ⚠ **缺 `type` 声明 ⇒ 注解 `Any`**（不是 `str`）。映射成 `str` 会让**跨项目一并就坏**。

### 第 3 步 · 起 MCP 投影（`mecha[mcp]`）

用 `mecha.providers.mcp` 的 `build_mcp_server` / `McpEndpoint`。**投影、`required` 派生、
null 垫片、失败归一化、SDK 私有面垫片全在框架里**——**你不要再写第二份**。

- **验收（⚠ 这条最容易被跳过，也最危险）**：**真 MCP 客户端**连上 → `list_tools` →
  **真调一个写工具** → 断言 ①调用成功（不是 `unknown_tool`）②**journal 真落了那条写**
- ⚠ **R10（本工程最贵的一条）**：「**全绿**」只对判据**覆盖到的路径**成立。
  EL 迁移后 `--checks --fast` **30/30 全绿**，工具面却**列得出来、调不动**——
  **抓到它的是另一个仓的跨仓判据，不是它自己的门禁**。
  ⇒ 接完**先自问**：我改的那条路径，**有哪条判据真的走它**？
- ⚠ **不要传 `toolhost=`** 一个来自装配点的注册表：`assemble()` 建出的 `sw.tools` 是**空表**，
  传它会让工具"列得出、调不动"。框架**已在构造期拦这个**（`toolhost_registry_mismatch`），
  但知道原因有用。
- ⚠ **`outputSchema` 不要声明**，除非你的声明**是真的**。框架的 MCP 工具面**不带**它——
  因为由返回注解派生的那玩意儿会**谎称**返回 `{result: string}`。**允诺一个假契约比不允诺更坏。**

### 第 4 步 · 接监控面（可选，`mecha.cockpit`）

只读监控端点。**四路由 + CORS + POST 只读**都在框架里。

- **验收**：四路由**逐字段**；CORS 覆盖；`/runs` 这类空表**必须报可读错误，不许假装空**
- ⚠ **别硬编码端口**——用 `mecha.portfile` 做发现（**启动前清陈旧、收尾只删自己的**）

### 第 5 步 · 接 dsh（若你要 AI 真的能操作它）

**先读** [`外部实践研究/DSH-实例并存与启动组合.md`](外部实践研究/DSH-实例并存与启动组合.md)（含实测与源码行号）。

**三条硬知识**（都是坑，不是建议）：
1. **永不选 3080**（官方 dsh 的端口）
2. `--patch` **可重复**，**overlay 放最后**（端口的实际决定权在**组合链最后一层**）
3. **同 id 的 patch 是「整块替换 config」，不是深合并** ⇒ 还原时要照抄**全部字段**

⚠ **进程组终止**：Windows 上 `Popen(["dsh.cmd", …])` 起的是 **`cmd.exe`**，`node` 是**孙进程** ⇒
**只 `terminate()`/`kill()` 直系进程会留下一只仍占着端口的 `node` 孤儿**（已实测：`probe` 收尾后
`:3081` 仍在听）⇒ 必须**杀进程树**。（详见 `操作陷阱.md` 与 `launcher` 相关 ADR。）

### 第 6 步 · 立你自己的判据（**最容易偷懒的一步**）

框架的门禁**验不了你的领域正确性**。你必须自己写，而**怎么写**才是重点——
**R7–R15 全部是关于「守卫怎么写才不是假的」**：

| 规则 | 一句话 |
|---|---|
| **R7** | 每条守卫必须配**能红**的证据，且**不得靠概率**（40 轮压测在缺陷实现上有约 **20% 假绿**） |
| **R8** | 判「相同/通过」的守卫要**自证数据真的到了**（空表 vs 空表也是"相同"） |
| **R9** | 期望值必须取自**被检对象之外**（取自被检对象 ⇒ 它一坏期望跟着变 ⇒ 守卫跳过该报的样本） |
| **R10** | 「全绿」只覆盖**走过的路径** |
| **R11** | **观测量必须能变**（恒定值不携带信息） |
| **R12** | 守卫拦下你的**测试替身**时，**先怀疑替身**，不要削弱守卫 |
| **R13** | 删机制时把它守的**承诺**改写成**行为级**判据，不要写「这个东西不存在」的守卫 |
| **R14** | **删除类改动的收尾是全仓搜残留**，不是跑门禁（门禁只覆盖它走到的路径） |
| **R15** | 守卫必须自证**它声称要检查的每个成员都真的被检查了**（枚举 ≠ 处理；一个 `except: continue` 就能把成员静默丢掉） |

## 3. 该由谁提供（**别把领域塞进框架**）

| 框架给（机制） | 项目给（值 / 领域 / 宿主知识） |
|---|---|
| 写入门、域状态史、写权、能力面、工具形态层 | 你的 `Engine`、工具名与参数语义 |
| MCP 投影、`required` 派生、null 垫片、失败归一化 | 你的工具说明文案与领域收编（按声明类型把数字串收编回数值） |
| 监控端点四路由、CORS | 你的路由附加与面板取址方式 |
| 端口**发现规则** | **端口号**（`3081` 起、永不选 3080） |
| 「等这个端口文件出现」（**路径由调用方给**） | 文件**叫什么**（`.mcp-port`） |
| 「起进程 / 优雅终止 / 超时杀**进程树**」 | 起**哪个** exe、argv、分几组、**超时值** |
| 「读/写/清一个请求文件」（路径显式） | 文件名与取值（`.mode-request` / `gui` / `ai`） |
| 「一个事实一个家的分级」「三问模板」「slop 清单」 | 你的文档内容 |

## 4. 接完自查（逐条回答，答不出就是没接完）

1. **我改的那条路径，有哪条判据真的走它？**（R10）
2. **每条守卫都有能红证据吗**？而且是**确定性**的，不是概率的？（R7）
3. **有没有"手抄的对外名单"**？（`__all__`、能力表、工具清单）——要么删掉让单一来源说话，要么让"**漏登记**"本身违规（D4）
4. **每个对外声明的事实，是不是只在一个地方陈述**？别处只放链接？（D1）
5. **我有没有把领域词塞进框架**？（L5）
6. **删除类改动**收尾时，**全仓搜过残留**了吗？（含仓根文件与隐藏文件，R14）
7. 我的 `.gitignore` 里有没有 **AI 可见面**（SKILL/提示词/面板文案）？——**基于 git 的验收看不见它**（`操作陷阱.md`）

## 5. ⭐ 如果你是 **n=3**：这个框架**等你来证伪**

**诚实的前提**：这个框架到今天**只有 n=2** —— 它**只被它从中提取的那两个项目验证过**。
它自己的纪律里写着「**不从 N=2 决定架构**」，所以好几处**故意挂着**（见下）。
**你是它第一次遇到"陌生人"。**

**请务必回答这四个问题**（第三个最有价值）：

1. **你有没有被迫往框架里塞领域词？** 若塞了，塞在哪、为什么绕不过去？（**L5 的检验**）
2. **R1 的准入线真的拦住了你，还是你能绕过？** 举实例。
3. ⭐ **你在别处复现了哪个"跨项目缺陷类"？**
   —— 本工程最值钱的六个缺陷**没有一个是"读源码"读出来的**：
   `_py_type` 缺 `type`（两家一并就坏）· wire 上的**假 `outputSchema`**（源码 grep 零命中）·
   EL 工具"**列得出调不动**"（**抓到它的是另一个仓的判据**）· POST 不 drain 的 Windows RST
   （只在压测下现形）· 删 `spill` 漏的构造实参（**门禁当时是绿的**）· `:3081` 孤儿（**实测才有**）。
   **若你的接入也抓到这一类，那才是框架真的成立。**
4. ⭐ **框架哪条规则在你这儿不成立？** —— **这条最有价值，请务必报回来。**

### 已知的、**等你来解**的挂起项

| 项 | 状态 |
|---|---|
| **C2 并表归属**（框架做并表判据 vs 并表归下游） | **架构分叉，故意挂着等 n=3**。已定的部分：并表是**生成物纪律**（每层只生成不手抄），不是"谁维护那张表" |
| **D2 的升格**（AI 可见面守卫生成物化） | **触发条件写死就是 n=3** |
| **C1-5 launcher 抽取的边界** | 两份 launcher 是**同一个状态机**（13+ 同名机制、逐行同一）；**抽取前要先做"逻辑级并排清点"**（含不同名函数），否则边界可能偏小 |
| **EL 的 `:3081` 孤儿** | **已知真缺陷、未修**（ML 已实测并修好，EL 未修） |

## 6. 三条最贵的坑（先记住这三条，能省你一天）

1. **源码 ≠ wire ≠ 面板渲染 ≠ 模型可见面。** 读源码不算验证（R3）。
2. **gitignore 的文件逃出验证。** 以 `git diff` / `git status` 为准的验收**看不见**被忽略的文件——
   而那往往正是 **AI 真正加载的那一份**。
3. ⭐ **「在某作用域内搜不到」≠「不存在」。** 报"不存在"之前先写明**你查的是哪个作用域**：
   「**仓内** 0 命中」与「**不存在**」是两句话；「**git 里**没变」与「**没变**」也是。（R3 的作用域强化）

## 7. 遇到分歧怎么办

- **加东西**：过 **R1 三格**；拿不准**先报**，别自己定
- **要写进文档的**：先问"**这件事的家在哪一层**"（D1）
- **要写守卫的**：先想"**它怎么才能红**"（R7）
- **要删东西的**：先想"**它守的是什么承诺**"（R13）+ 收尾**全仓搜残留**（R14）
- **要上提进框架的**：先给一份"**值不值得**"的判断，**含行数级代价与具名消费者清点** ——
  **"不值得上提"是合格答案，甚至是好答案**（本工程六项候选里，四项这么收的）
