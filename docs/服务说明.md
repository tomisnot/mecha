 # mecha 服务说明

 mecha 为已有软件提供一组可组合的运行服务。它不替你实现业务逻辑，而是让软件在多人、多入口和长任务环境中保持一致。

 ## 能力总览

 | 服务 | 解决的问题 | 主要接口 |
 |---|---|---|
 | 状态与写权 | 谁可以在当前模式下写入 | Authority、Gate |
 | 操作关联 | 一次调用涉及哪些事实和产物 | operation_id、call_id |
 | 事实记录 | 发生过什么，为什么发生 | History、Event |
 | 查询面 | 读取状态和能力 | Surface.QUERY |
 | 命令面 | 统一执行副作用动作 | CommandRegistry |
 | 后台任务 | 长任务如何排队、观察和取消 | JobRegistry |
 | 产物 | 大结果如何引用和读取 | ArtifactStore |
 | 工具投影 | AI、MCP、CLI 如何发现能力 | ToolRegistry、ToolHost |
 | 监控 | 如何查看运行和事实 | Monitor、Cockpit |
 | 启动聚合 | 多项目如何统一启动和发现 | launch、site、aggregate |

 ## 适用场景

 - 科研计算和仿真；
 - 机器学习训练；
 - 文献抓取和评审流水线；
 - 长期学习档案；
 - 带 GUI 和 MCP 的桌面软件；
 - 有运行目录、任务队列和结果文件的工作台。

 纯函数库和一次性脚本可以只使用少量投影接口，不必引入全部组件。

 ## 使用者获得的行为

 ### 统一动作

 人和 AI 调用同一个领域命令，回执的身份、错误和结果引用一致。

 ### 可追踪事实

 每次写入都有操作者、理由、时间和操作号；项目业务事实可以使用同一个操作号关联。

 ### 长任务可观察

 提交任务后可以查询状态、进度、日志尾、结果引用和终态。等待超时与任务失败分开表达，取消请求与已终止分开表达。

 ### 大结果可控

 大数组、文件、模型、日志和报告通过引用读取，不把完整内容塞进对话或监控事件。

 ### 宿主自由

 同一能力可以投影到本地调用、MCP、GUI、CLI、CodeAct 或其它宿主。宿主只是访问方式。

 ## 接入后的责任分工

 mecha 负责通用机制：

 - 写权、作用域和审批；
 - 命令声明和参数投影；
 - 操作关联和通用事实；
 - Jobs 的生命周期；
 - 产物引用；
 - 工具和监控接线；
 - 启动、端口和服务发现。

 项目负责领域内容：

 - 数据结构和业务状态；
 - 算法、计算和外部服务；
 - 参数的单位和意义；
 - 业务校验；
 - 失败恢复和 checkpoint；
 - 结果解释和领域页面。

 ## 典型调用体验

 使用者通常先查询能力和当前状态，再调用一个领域命令。命令回执给出稳定的 id、摘要、警告和后续查询入口。长任务回执给 job_id，结果回执给 run_id 或 result_ref。所有 id 都用于后续查询，不用显示名代替。

 ## 运行边界

 mecha 不保证：

 - 算法结果正确；
 - 领域参数一定适合；
 - 任务可立即取消；
 - 外部 API 永远可用；
 - 物化读模型永不失效；
 - 项目结果可以跨机器直接恢复。

 这些责任必须由项目文档和代码说明。

 ## 选择接入深度

 - 只需 AI 发现能力：注册 ToolRegistry；
 - 有只读状态：增加 Surface 查询；
 - 有副作用动作：增加 CommandRegistry 和 Gate；
 - 有长任务：增加 Jobs；
 - 有大结果：增加 ArtifactStore；
 - 有多人/多入口操作：接入 Authority、History 和 Monitor；
 - 有多个项目：使用统一站点和聚合启动。

 mecha 的价值在于让这些边界可以组合，而不是让每个项目重复一套脚手架。
