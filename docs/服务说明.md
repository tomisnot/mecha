# mecha 服务说明

mecha 帮助寄宿在 dsh、Codex 等 AI 宿主中的助手操作有状态软件，也让 skill 拥有能维护状态、执行任务的软件后端。项目保留领域模型和自动化能力，框架提供共同的操作与协作基础。

长期目标见[设计愿景](设计愿景.md)。下表描述当前提供的服务，具体 API 与限制见[开发者指南](开发者指南.md)。

| 服务 | 当前能力 | 项目仍需负责 |
|---|---|---|
| Authority / Gate | 写权模式、操作前检查、默认键值状态写入 | 领域约束、数据库事务、设备互锁 |
| History / operation | 状态及审计事件、操作号与调用号关联 | 业务证据、重要执行阶段、跨系统一致性 |
| Surface / Commands | 查询分派、具名命令、策略检查和回执 | 领域动作、增量操作、诊断接口 |
| Jobs | 本地线程任务、进度、取消请求和等待 | 资源排队、并发预算、实际停止与恢复 |
| Artifacts | 字节落盘、元数据和 locator 读取 | 长期索引、结果保留策略和领域解释 |
| ToolHost / 宿主接入 | 本地调用、MCP 工具传输、dsh 与 Codex 接线 | 工具使用知识、业务回执与操作语义 |
| Monitor / Cockpit | 摘要对照、状态与事件的只读观察 | 训练图、实验信号、业务页面等专业展示 |
| Site / Aggregate | 软件声明、发现、启动接线与工具聚合 | 项目的启动、停止和恢复行为 |

## 默认基础设施与项目实现

`assemble()` 提供完整默认装配，适合希望快速接入的软件。已有数据库、调度器或可视化的项目应继续使用它们，通过共同的操作身份和结果引用接入。当前 `log_sink` 可在装配时替换，其它 provider 的装配替换能力还不完整。

Authority 支持人类独占、AI 独占、共享和锁定模式。写权与审批按项目协作方式选择；它们不能代替业务校验，也不意味着每一步都要人工确认。

## 当前可以依赖的行为

- 通过 CommandRegistry 执行有副作用的命令时，必要的 Gate、写权、已绑定作用域和声明的审批在处理函数执行前检查。
- 命令审计与默认配置快照分开；监控历史保留账本事实及操作关联，不把不同命令伪造成同一个状态的前后变化。
- 大结果可以存入产物服务或项目存储，回执提供引用。
- 聚合调用断线时恢复后端发现，但不自动重复提交结果不明的原操作；超时也不被解释为执行失败。

## 当前不能据此推断的事情

命令审计在执行后写入，不保证进程骤停时已有完整开始与结束记录。项目事务与外部设备动作也不自动和审计共同提交。

默认 Jobs 不提供资源队列或跨重启恢复。当前 cancelled 状态也可能出现在函数正常返回但取消标志已置位的情况，不能证明设备已停止。项目应查询实际执行状态并提供必要证据。

本地产物文件会保存，但 locator 解析依赖当前 store 实例的内存映射；长期查找结果需要项目持久索引。`Software.close()` 目前只关闭 History，不能代替项目的完整资源清理。

Monitor 提供基础读面，尚未自动贯通所有操作、任务、产物和项目页面。领域可视化需要项目继续建设，并使用操作号、任务号和结果身份建立关联。

## 接入路径

从[接入指南](接入指南.md)的最小装配开始，先接一条真实查询和一条真实动作，再根据项目需要接入任务、产物与页面。只有查询或纯函数能力的项目可以使用局部组件。实验室接入应直接暴露软件操作能力和低层诊断接口，由软件负责实时执行。
