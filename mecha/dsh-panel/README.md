## 它是什么 / 解决什么

dsh 插件的 client 半**不能自己读磁盘**，而监控端点的端口是**动态分配**的
（`mecha.cockpit` 用 `port=0` 起端点，把实际端口写进项目根的一个裸端口文件）。
于是"地址"必须由 **host 半**转一次：host 读端口文件 → 同源只读路由回 `{base}` →
client 半 fetch 同源路由拿到地址。本目录就是这一层 + 取数骨架的参考实现。

**三家项目各自写过一份，而且已经分叉**：其中一家今天**坏在静默空白**（地址来源被硬编码/
回落，面板打不开却什么都不说），另一家的 host 半是前一家 `host/*` 的近似逐字复制、**唯独
漏掉了地址路由这一个文件**。⇒ 本资产的存在理由不是"少写几行"，是**让"漏一个文件"这件事
变成机械可抓**。

## ⭐ 复制约定：「除参数块之外逐字一致」

复制本目录进项目后：

* **只许改 `panel-config.ts`**，且只许改那几个字段的值；
* **其余文件必须与 mecha 仓里的参考实现逐字一致**。

为什么把可变量**单独一个文件**：只有收进唯一一处，**逐字比对才是机械的**。若允许"就地改
几行"，比对立刻失效，只能退化成人工 review ——而人工 review 正是本工程反复失手的地方。

**判据怎么写**（建议放**项目自己仓里**）：

* **按内容读文件**，**不要经 `git`**——本工程有两次教训：gitignore 的文件逃出 `git diff`
  验收；目录 junction 让"两条路径"其实是同一个文件（两者都骗过我们）；
* ⭐ **优先「钉常量指纹」，判据运行时不要读上游**（本工程 A8 的裁决 + 一次真实使用验证）：
  把参考实现**提交态**的正文指纹（`sha256`）**写成你判据里的常量**，
  **`REFERENCE_REVISION` 只作出处说明**（写清"取自哪个提交"），比对靠那组常量。
  ⇒ 这样**零跨仓读取**：**上游任何在飞改动都不会红你的判据**（照"运行时读上游提交态"做，
  上游每次提交都会红你一次——而那不是你的问题，**噪声化的门禁等于没有门禁**）。
  上游真发新版时：**整份重新复制 + 同步更新常量**，而不是就地打补丁。
  ⚠ 同一纪律对"生成物新鲜度"也成立：**判提交态，不判工作树**。
* ⭐ **比的是「归一化行尾后的正文」**：`core.autocrlf` 会让"同一内容"在不同检出状态下
  **字节不同**（实测过）⇒ `\r\n` 归一成 `\n` 再取指纹。**裸字节比对会被行尾配置打败**。
* ⭐ **区分两件事**：**"复制时逐字抄"** vs **"指纹表里钉哪些"**。
  - 复制时：**除 `panel-config.ts` 之外的文件一律逐字抄**（含 `README.md`）；
  - 指纹表：**只收"行为载体"**（代码 + 单测）。`panel-config.ts` **必然不同**（它是参数块）；
    `README.md` **不进表**——prose 的就地批注不改行为，钉它只制造噪声。
* **R7 红证**：在副本的**参数块以外**改一个字符 ⇒ 判据**必红**（否则它是哑守卫）；
* ⚠ **不要改共享单测**。项目要加"自家历史默认端口"这类**反面语料**，请**另建一个
  项目自己的测试文件**（共享单测里不许出现任何项目字面量，见下）。
* ⭐ **抄完照 R17 自查一遍**：**有没有"声明了却不被读"的形参**（尤其被 `_` 前缀标成
  "故意不用"的占位）？—— 这种**看起来能注入、其实注入不进去**的缝会在 review 里过关。
  参考实现**自己就犯过一次**（`fetchMonitorBase` 的第二个形参曾是死的、且零覆盖）；
  而**它是三份副本的源头 ⇒ 它犯的错会被复制三遍**。每个注入点都要配一条
  「**换掉它、结果就变**」的用例。

## ⭐ 你该用哪半边：**看面板形态**（这条决定了会不会"误用"）

| 你的面板形态 | 用得到的 | **用不到 / 不该硬套的** |
|---|---|---|
| **原生面板**（自己 `fetch` 四基础路由再渲染） | `fetchMonitorBase` + `readJson` + **`panelState`** + `monitorStats`/`isNonDegenerate`/`statsLine` | — |
| **iframe / 两跳**（挂一个内层页） | `fetchMonitorBase` + `panel-config` + `assertNever` | ⛔ **`panelState` 不适用**：它要的是**四基础路由的取数结果**，而 iframe 压根不做那些取数 ⇒ 硬套只会**恒落 `empty` 档**（那是**误用，不是覆盖**） |

⭐ **`panelState` 的适用条件**：**只适合"自己做取数的原生面板"**。
iframe 形态的状态输入是**另一组**（地址 + 内层可达 + 视图 + 容器是否在）。
⚠ **但模式可以照搬**：**可移植的是「判别联合 + 没有空白档 + `assertNever` 兜底」这个模式，
不是那个函数**——本项目已有一个实例：某 iframe 面板自己写了个渲染层判别联合
（`ready | error`，明写"**空白不是一种状态**"），并明确拒用 `panelState`。
⇒ **不要把 `panelState` 的签名改成"什么形态都能塞"**：那是为"被用上"而改接口
（R1：今天只有一个 iframe 消费者，而它已经自己解决了；R17：不许为了被用而改签名）。

## ⚠ 资产**管不到**的那一半（**项目侧义务**，必须自己兜住）

这份资产**只做"地址 + 取数 + 状态"**，**完全不含 DOM、不含渲染、不含挂载**（渲染与文案
按边界归项目）⇒ 下面这两族缺陷**资产结构上无法覆盖**，**不许假装它覆盖了**：

1. ⭐ **挂载失败必须可见**：找不到右栏容器 / 挂载点 / 宿主注入的句柄时，
   **禁止静默 `return`**（那种写法会渲染出一片空白，**且不抛错**——"面板打不开"与
   "面板没数据"从此无法区分）。**必须**把失败呈现成**可读文本**（可以是"没有可挂载的容器"
   这类一句话），或至少**抛/记录**到能看见的地方。
2. **两跳（iframe）必须可诊断**：若面板形态是 iframe（**合法选项**），内层服务的失败要能被
   外层看见——不许出现"外层 200、内层空白"这种**静默空白**。
   ⚠ 本条与 `panelState` 的 `empty` 档是**两件事**：`empty` 管**数据**层，"外层 200 内层空白"
   是**渲染/挂载**层；**两层都要防**。
   **参考形状**（**约定，不是代码**——它的路径与语义是项目值）：**挂之前先探一次内层可达**：
   对**你项目自己的健康端点**发一个 **`no-cors`** 请求（`no-cors` 下读不到状态与正文，
   所以它只回答"**那个地址上有人讲 HTTP 吗**"），**绝不抛**（异常一律折成"不可达"），
   探不到就**渲染可读错误**，而不是挂一个注定空白的 iframe。
   ⚠ **诚实边界**（别假装覆盖）：它**不能证明内层页渲染出了内容** ⇒"内层页自己永远不空白"
   那一条由**内层页**负责（缺数据时如实渲染"未接监控面"这类文本，而不是空白）。

> 一句话：**资产的 `panelState` 让"没数据"无法伪装成成功；挂载/渲染这一层靠上面这两条义务。**

## 一句**判据**（给插件的作者，不是给面板）：`inject` 怎么写

**各项目自决**，但判据是这一句：
> **若你的插件还提供 web 服务之外的入口（AI 工具 / 命令 / 别的能力），
> 就别把 `webServer` 写成顶层硬 `inject`** —— 顶层 `inject` 缺一个服务会让**整个插件不激活**，
> 那会把"**面板没有 web 服务**"升级成"**AI 工具也没了**"。用**作用域注入**
> （只把**路由注册**包在里面），让面板缺服务不影响插件其余能力。

（真实差异：三家当前的 `inject` 形态**各不相同**，且**都合理**——单服务的插件硬 `inject`
就对；多服务的插件才需要作用域注入。**这是插件架构的事，不是面板的事**：
不要借"迁移面板"顺手改掉某项目的插件激活语义。）

## 三条设计点（为何这样写）

1. ⭐ **绝不回落**：端口文件读不到 / 内容非数字 / 越界 ⇒ **抛错**，路由回 `503` + 可读错误。
   回落会把"权威没起来"显示成"**连上了但空面板**"——本工程反复在防的假绿。
   **同一条纪律也适用于端口文件名**：所以 `portFile` 是**必填参数**，库**不提供默认文件名**
   （猜错名字是同一个病上一层）。
2. **每次调用现读**：端口漂移后下一拍就落在新端口上，不需要重启 dsh；本层**不缓存**。
3. **三档失败可区分**：`address`（地址拿不到）/ `offline`（**基础路由**失败 = 权威离线）/
   `route`（**附加路由**失败）。**档位共享、文案归项目**。把附加路由失败混进"权威离线"，
   会让真因被吃掉——`displayTier()` 让"塌缩成离线"成为一个**显式动作**，而不是就地混同。
4. ⭐ **`panelState` 让"面板空白"不可表达**：归约成**判别联合**
   （`ok` / `address` / `offline` / `route` / `empty`），**每个分支都带 `detail` 或数据**
   ⇒ 渲染方**没有"什么都不画"的档**；漏分支时 `assertNever` 在运行侧**抛**
   （跑了类型检查的项目里还会**编译不过**）。
   其中 **`empty` 档是刻意加的**：它堵的是"**连上了、也 200、但一点数据都没有**"——
   那是 R8 那一类**最难抓**的假绿（**有渲染，但内容是空的**）。
   ⚠ 它管的是**数据层**；"外层 200、内层空白"那类**渲染/挂载层**的空白靠上文的项目侧义务。
